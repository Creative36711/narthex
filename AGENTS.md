# Language and Reasoning Rules

## 1. Core Rule
- **ALL** internal reasoning, thought processes, planning, scratchpads, and step-by-step analysis **MUST** be conducted strictly in the **RUSSIAN** language.
- Do NOT write thoughts, plans, or explanations in English.

## 2. Permitted English Exceptions (Do NOT translate)
To prevent project corruption, the following **MUST** remain in English:
- **Code Syntax:** Variable names, functions, classes, types, imports, and API payloads.
- **System Commands:** Terminal commands, file paths, configurations, and raw console outputs.
- **Git Operations:** Keep commit messages in standard English (e.g., Conventional Commits).
- **Project UI & Data:** Do NOT translate existing English user interfaces, database schemas, or project content unless explicitly instructed in the task.
- **Search Patterns:** Keep search queries (grep, find, regex) aligned with the target code language.

## 3. Execution Rule
- Always write your reasoning in Russian *before* executing any tool call or bash command.
