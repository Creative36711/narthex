# cf-play — как агенту тестировать кампанию

`cf-play.mjs` — один файл, без дополнительных пакетов и без сети. Используй
Node 20+. Доступ к исходному репозиторию не нужен, но бандл содержит читаемый
скомпилированный код движка: локальная раздача не обеспечивает секретность.

Положи его рядом с кампанией:

```
campaign/
  campaign.json
  world.json
  scenes/ …
  __chronicle_ai__/
    cf-play.mjs
    campaign-audit.mjs
    campaign-guide.md
```

## Базовая проверка

```bash
node __chronicle_ai__/cf-play.mjs check . --seeds 1-5 --steps 300 --out .cf-play/check
```

`check` запускает статический граф, маршруты из `routes/*.json` и матрицу
seed'ов. Пишет `.cf-play/check/report.md` и `report.json`, печатает вердикт.
Код возврата `0` — обнаруженных в отчёте ошибок и предупреждений нет; `1` —
есть ошибки или предупреждения; `2` — ошибка вызова. Предупреждения загрузчика
на stderr проверяй отдельно: не каждое из них попадает в отчёт `check`.

Перед пушем агент обязан получить `0` и приложить `report.md` к отчёту.
Если `1` — читай `report.json`, там списком: `problems`, `graph.errors`,
`routes[].status`, `sweep.deaths`.

## Что проверять по отдельности

```bash
# 1. Статика, без игры. Битая ссылка, мёртвый флаг, недостижимая сцена.
node __chronicle_ai__/cf-play.mjs graph .

# 2. Все ветви одного диалога — без похода до NPC.
node __chronicle_ai__/cf-play.mjs dialogue . npc_brann --depth 3

# 3. Точечный прогон из нужного места. Это не приёмка: evidence=injected.
node __chronicle_ai__/cf-play.mjs run . --seed 7 --script routes/a.json \
  --scene scene_outpost_room --flag order_delivered --tick 40

# 4. Честный обход с записью маршрута.
node __chronicle_ai__/cf-play.mjs explore . --seed 7 --steps 300 --record routes/found.json

# 5. Матрица исходов по seed'ам.
node __chronicle_ai__/cf-play.mjs sweep . --seeds 1-10 --steps 300
```

Следующие флаги из `--help` — отладочная правка состояния: `--set`, `--var`,
`--item`, `--currency`, `--skill`, `--tick`, `--scene`, `--hp`, `--god`,
`--entity id=state`, `--quest id=stage`, `--weather id`.

## Правила доказательств

- `evidence: honest` — состояние пришло только из игры.
- `evidence: injected` — были правки; они перечислены в транскрипте.
- `verify <прогон> --honest` отвергает второй вид.

Не выдавай прогон с правками за прохождение. Для отчёта «проверено» годится
только `honest`; `injected` годится, чтобы найти баг, но не чтобы закрыть задачу.

Маршрут, записанный `--record`, воспроизводится байт-в-байт по хэшу
транскрипта. Значит, найденный путь можно приложить и переиграть в CI.

## Формат маршрута

```json
{
  "name": "01-night-pass / smoke",
  "steps": [
    { "do": "travel", "to": "loc_serpentine" },
    { "do": "interact", "entity": "npc_brann" },
    { "do": "choose", "text": "Спросить про обморожение" },
    { "do": "expect", "scene": "scene_outpost_yard" },
    { "do": "expect", "has_item": "item_order" },
    { "do": "expect", "game_over": null }
  ]
}
```

Проверки: `scene`, `flag`, `no_flag`, `has_item`, `game_over` (`null` — забег
идёт), `tick_at_least`, `quest_at_stage`. `{"do":"snapshot","label":"…"}` —
метка в транскрипте. Если маршруту нужен свой seed, добавь `"seed": 7` рядом
с `"steps"` — `check` возьмёт его вместо общего.

Артефакты `check` пишет в `.cf-play/`, добавь это в `.gitignore` кампании.

## Что этот инструмент не проверяет

Вёрстку, переполнение текста, тайминг анимаций, звук, читаемость на маленьком
экране, вкус диалога. Для этого нужны браузерные проверки (в том числе можно
снимать скриншоты headless-браузером) и оценка человека или визуального
аудитора. В отчёте честно перечисли, что осталось непроверенным, вместо того
чтобы писать «кампания протестирована полностью».

`check = 0` означает отсутствие ошибок и предупреждений, обнаруженных в
отчёте этого запуска; это не гарантия покрытия всех сцен, концовок и правил
или победы хотя бы в одном прогоне. Проверь отчёт, маршруты, покрытие и исходы
отдельно. На эталоне охват — 6/10 сцен и пять смертей; текущий `check` выдаёт
код 1 из-за трёх предупреждений, а не из-за этих покрытия и исходов.

Проверяй также предупреждения на stderr и версию движка: в текущем бандле
`0.8.0` кампания с `min_engine: 0.9.0` может получить `check = 0`, хотя
загрузчик предупреждает о несовместимости. Совмести версию кита с целевым
движком до приёмки.

**Ограничение автономного кита:** текущая упаковка не содержит
`packs/registry.json`, манифестов паков и `docs/contracts/caps.json`.
Без них `check` использует совместимый с прежними кампаниями режим и пропускает
часть проверок `project.json` на установленный пак и настройки возможностей.
Например, неизвестный `kind` может не вызвать ошибки. Для проверки проекта
по контрактам нужен доверенный CI/сервер с установленным реестром и пакетами;
один локальный бандл не доказывает совместимость всего проекта.

## CI

```yaml
- run: node __chronicle_ai__/cf-play.mjs check . --seeds 1-5 --out .cf-play/check
```

Кампания с ошибками или предупреждениями в отчёте `check` не должна
мержиться. Артефакт `report.md` прикладывается к PR.

## Другие команды и границы комплекта

`explain <код>` объясняет диагностический код, а `example` запускает
нарративный эталон, входящий в полный кит. `schema`, `shoot` и `kit doctor`
остаются планами. `explain --catalogue` требует установленного реестра паков,
а `cycles` — эталонных проектов в структуре репозитория движка; в автономном
ките эти команды без дополнительных файлов не работают. Актуальный список —
`node __chronicle_ai__/cf-play.mjs --help`.

Если кит и движок разошлись по версии, результаты прогона нельзя считать
доказательством: проверь `KIT.json` и запроси актуальный кит. Локальные хэши
полезны для сверки, но не защищают от изменённого агентом кита: окончательный
вердикт должен воспроизводиться доверенным CI или сервером.
