# Как работать с кампанией Chronicle Forge через ИИ-агента

Этот файл — сопроводительный текст к «чемодану для ИИ-агента» (скачивается
из редактора кампании: **Файл → Чемодан для ИИ-агента**). В чемодане:

- `campaign-guide.md` — полный гайд по движку и формату кампании (системный промпт);
- `campaign.schema.json` — формальная JSON Schema всех полей;
- `campaign.json` — ваша кампания одним документом (монолит);
- `НАЧНИ_С ЭТОГО.txt` — этот текст.

## Что сделать: пошаговая инструкция

1. Откройте чат вашего ИИ-сервиса (лучше — в режиме «агент» / «проект»,
   куда можно загружать файлы).
2. Загрузите в чат **все три файла** чемодана (гайд, схему, campaign.json).
3. Скажите агенту, например:

   > Прочитай campaign-guide.md как техническую спецификацию движка.
   > В campaign.json — текущая кампания. Задача: <что нужно изменить>.
   > Возвращай только фрагменты, которые нужно заменить, в том же формате,
   > с полями секции `scenes/…`, либо полный документ, если меняешь многое.
   > Проверь себя по campaign.schema.json — ни одного нарушения.

4. Агент вернёт результат: полный JSON монолита или отдельные фрагменты.
   - **Полный документ** — в редакторе: **Файл → Импорт из JSON** (вставить текст)
     либо **Файл → Импорт .chronicle** (если агент вернул файлами — переупакуйте zip).
   - **Фрагменты** — вставляйте в нужный раздел: у вкладок «JSON» каждой сущности
     есть своё редактируемое представление файла.
5. После импорта нажмите **Сохранить**, затем **Инструменты → Проверить кампанию** —
   ошибки можно снова показать агенту (кнопка «Скопировать отчёт для ИИ»).

## Правила для агента (скопируйте агенту в начало чата)

```
Ты автор кампаний для движка Chronicle Forge.
Строжайшие требования:
1. Формат — MonolithDoc из campaign-guide.md; формальная граница — campaign.schema.json.
2. Валидация по схеме обязана быть чистой: ссылайся только на существующие id,
   не добавляй полей вне схемы, не удаляй обязательные.
3. Тексты на русском; id — латиницей с префиксом секции.
4. Никаких полевых переименований/переиспользований id: «устаревшее» — удали и создай новое.
5. Запрещено выдумывать значения вне перечня типов из guide (состояния сцен, типы условий, эффектов).
6. Изображения/звук файлами не требуются: используй `art`-примитивы, синтетические
   SoundDoc/MusicDoc (см. «Sounds & Music» в guide).
7. Если не хватает механики — скажи об этом прямо, не выдумывай полей.
```

## Возможные способа работы

- **Уточнение частей** — «измени диалог кузнеца» (агенту достаточно `dialogues/<имя>.ink`
  фрагмента из campaign.json или монолита).
- **Дописывание контента** — «добавь квест на сбор лесных трав», «добавь локацию подвал таверны».
- **Новая кампания с нуля** — «создай кампанию с гильдией воров по этому брифу».
- **Проверка** — загрузите monitor JSON и попросите «найди швы» (непрорисованные места).
- **Миграция** — «переведи старую кампанию (приложена) к формату из guide».

## Чего не умеет агент (а движок делает за него)

- Проверка ссылок, id-связок и синтаксиса — после импорта редактор сам помечает битое
  и показывает отчёт «проверь кампанию».
- Генерация звуков/музыки/орнаментов — синтез из JSON-описаний (SoundDoc/MusicDoc/ArtDoc);
  мастер может заменить синтез на настоящие файлы позже.
- Устаревшие поля и старые форматы — мигратор каждый раз приводит кампанию к актуальному виду,
  при этом пишется отчёт миграции (смотрите его не импортируя уже сохранённое).
