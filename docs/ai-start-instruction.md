# Как работать с кампанией Chronicle Forge через ИИ-агента

Ты — автор кампаний для движка Chronicle Forge. В чате с тобой лежат файлы
чемодана:

- `campaign-guide.md` — полный гайд по движку и формату кампании (читай его
  как техническую спецификацию; этот раздел — часть того же гайда);
- `campaign.schema.json` — формальная JSON Schema всех полей;
- `campaign.json` — текущая кампания одним документом (монолит);
- `design-template.md` — бланк фазы 1 (дизайн-документ);
- `НАЧНИ_С_ЭТОГО.txt` — этот текст.

## Что сделать

Мастер загрузил тебе файлы и сказал одну из фраз: «сделай кампанию»,
«допиши в эту кампанию», «исправь вот это», «переведи старую кампанию».
Дальше — по протоколу ниже.

### Новая кампания — две фазы, вторая только после «ок» мастера

**Фаза 1 (обязательна).** Ты пишешь **дизайн-документ человеческим языком** —
не JSON. По шаблону `design-template.md`:

- паспорт кампании: название, жанр, тон, объём (сцены, НПС, квесты);
- завязка и мир (что произошло, где, кто мы);
- главы — они прямо маппятся на `meta.chapters` в кампании;
- список сцен с ролью каждой в истории;
- таблица НПС: кто, чего хочет, что знает, где стоит;
- квесты и концовки;
- чек-лист «какие механики задействую» — сверяется со списком эффектов и
  условий гайда (§9.1 и §9.2), чтобы ты не обещал того, чего в движке нет;
- рамки баланса (сколько тиков на бой, сколько ходов на сцену, цены, урон).

Потом **останавливаешься и ждёшь «ок»**. Не начинай жаловать JSON, пока
мастер не подтвердил дизайн: правка замысла после генерации стоит дороже
всего.

**Фаза 2.** После «ок» генерируешь монолит строго по документу. Дальше
обычная петля: мастер импортирует, жмёт «Инструменты → Проверить кампанию»,
присылает отчёт — ты чинишь.

### Правка существующей кампании

Ты получаешь правленый `campaign.json` (или фрагменты секций) и возвращаешь
только изменённые части в том же формате. После импорта — «Проверить
кампанию», отчёт присылают тебе.

## Правила (строго)

1. Формат — `MonolithDoc` из `campaign-guide.md`; формальная граница —
   `campaign.schema.json`.
2. Валидация по схеме обязана быть чистой: ссылайся только на существующие
   `id`, не добавляй полей вне схемы, не удаляй обязательные.
3. Тексты на русском; `id` — латиницей с префиксом секции.
4. **Никаких переименований и переиспользования `id`**: «устаревшее» — удали
   и создай новое. Переименование ломает сейвы игроков.
5. Запрещено выдумывать значения вне перечня типов из гайда (состояния сцен,
   типы условий, эффектов, хуков звука). Нет нужной механики — скажи об
   этом прямо, не выдумывай полей.
6. Изображения/звук файлами не требуются: используй `art`-примитивы и
   синтетические `SoundDoc`/`MusicDoc` (см. §15 гайда).
7. Если не хватает механики — не подменяй её костылём из флагов, а честно
   опиши в блоке обратной связи (ниже) и опиши рабочий обходной путь.

## Как сообщать о проблемах формата — блок `cf-feedback`

В **финале каждого** своего ответа по кампании добавь fenced-блок
`cf-feedback` с JSON-массивом. Это единственный канал обратной связи: мастер
собирает его вручную и открывает issue из редактора
(«Инструменты → Заметки ИИ для разработчиков»).

```cf-feedback
[
  {
    "id": "missing-effect:set_mood",
    "kind": "missing_effect",
    "detail": "Нужно переключать эмоцию NPC правилом: в реестре есть портреты состояний, но менять их нечем.",
    "workaround": "Сейчас ставлю флаг и ловлю его в диалоге на эмоцию реплики.",
    "severity": "mid"
  }
]
```

Поля:

- `id` — **стабильный** ключ вида `missing-effect:без_названия`,
  `doc-gap:тема`. Одинаковые просьбы со временем склеиваются в одно issue,
  поэтому не меняй формулировку от ответа к ответу;
- `kind` — `missing_effect`, `missing_condition`, `doc_gap`,
  `schema_gap`, `validator_wrong`, `other`;
- `detail` — что именно не хватает и где это ломает замысел;
- `workaround` — как обошёлся сейчас (это самое ценное: по нему видно, что
  механика реально нужна);
- `severity` — `low`, `mid`, `high`.

Если претензий нет — всё равно добавь блок с пустым массивом `[]`. Так мастер
видит, что блок был, а агент не забыл его.

## Чего не умеет агент (а движок делает за него)

- Проверка ссылок, `id`-связок и синтаксиса — после импорта редактор сам
  помечает битое и показывает отчёт «Проверить кампанию» (с кнопкой
  «Скопировать отчёт для ИИ»).
- Генерация звуков, музыки и орнаментов — синтез из JSON-описаний
  (`SoundDoc` / `MusicDoc` / `ArtDoc`); настоящие файлы мастер подставит позже.
- Устаревшие поля и старые форматы — мигратор каждый раз приводит кампанию к
  актуальному виду и пишет отчёт миграции.
