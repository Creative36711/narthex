# Глоссарий Narthex

Канонические термины интерфейса и книги. Склонение допускается, но термин не следует заменять синонимом в пределах одного экрана.

| Термин | Значение и употребление |
| --- | --- |
| характеристика | Базовое качество героя: Сила, Телосложение и другие параметры |
| навык | Умение с числовым значением |
| проверка навыка | Бросок d100 против навыка с модификатором |
| бросок | Результат случайной проверки; для проверок навыка используется d100 |
| очко / очки | Единица бюджета характеристик или навыков; писать с правильным числительным |
| происхождение | Шаблон характеристик при создании персонажа |
| призвание | Шаблон навыков и особенностей при создании персонажа |
| потребность | Шкала состояния героя, например голод |
| статус | Временное состояние, влияющее на героя или врага |
| способность | Действие или особенность, заданная кампанией |
| слот экипировки | Место, заданное кампанией, куда можно надеть предмет |
| предмет | Объект инвентаря, включая экипировку и расходники |
| рецепт | Условия создания предмета |
| сцена | Игровой экран с фоном, персонажами и действиями |
| локация | Место мира, включающее одну или несколько сцен |
| регион | Группа локаций на карте |
| слой погоды | Визуальный слой текущей погоды |
| время суток | Утро, день, вечер или ночь согласно настройкам кампании |
| тик | Единица игрового времени |
| НПС | Персонаж, которым управляет мастер или система |
| спутник | Персонаж, который путешествует вместе с героем |
| враг | Противник героя |
| банда | Группа противников (наименование задаёт кампания) |
| диалог | Разговор героя с персонажем |
| реплика | Одна фраза диалога |
| вариант ответа | Выбор игрока в диалоге |
| проверка в диалоге | Проверка навыка, связанная с вариантом ответа |
| квест | Задача со стадиями и записями журнала |
| стадия квеста | Текущее состояние развития квеста |
| запись журнала | Текстовое обновление истории квеста |
| правило | Заданное автором кампании условие, запускающее эффекты |
| условие | Требование для запуска правила или действия |
| эффект | Изменение состояния, заданное кампанией |
| срабатывание | Момент применения правила или эффекта |
| кодекс | Справочник сведений кампании |
| запись кодекса | Одна статья кодекса |
| концовка | Финальное состояние истории |
| забег | Одно прохождение кампании |
| хроника | Название основного профиля порогов броска и тематический термин проекта |
| катсцена | Последовательность слайдов с текстом и озвучкой |
| ролик | Разговорное обозначение катсцены; в редакторе предпочитать «катсцена» |
| слайд | Один экран катсцены |
| версия кампании | Номер выпуска кампании; задаёт мастер в разделе «Кампания → Версии» |
| версия движка | Номер сборки Narthex; задаётся проектом, не мастером |
| формат пакета | Версия структуры файлов кампании (Campaign Package) |
| контракт совместимости | Файл `compat.json`: какие изменения в версии ломают сохранения |
| граница сохранений | Версия кампании, начиная с которой сохранения ещё поддерживаются (`save_base_version`) |
| перенос сохранения | Автоматическое приведение старого сохранения к новому формату |
| починка сохранения | Удаление из сохранения ссылок на объекты, которых больше нет в кампании |
| отчёт о сохранении | Список того, что движок сделал с сохранением, на русском языке |
| файл сейва | Экспортированное сохранение `.nxsave` |
| ломающее изменение | Правка кампании, после которой старые сохранения не открываются |
| публикация версии | Запись контракта совместимости и нового номера версии из редактора |
| дизайн-документ | Гейм-дизайнерский документ кампании (`design_doc`): замысел простыми словами — паспорт, главы, сцены, персонажи, квесты, журнал решений; ведёт ИИ-агент, мастер читает и правит в разделе «Проект → Дизайн-документ» |
| чемодан для ИИ-агента | Архив из четырёх файлов (кампания, гайд с инструкцией первым разделом, схема, бланк дизайн-документа); скидывается в чат агента целиком, без распаковки |
| пак | Единица расширения: направление целиком — схема, панели студии, валидаторы, пробы и объявленные швы; подключается манифестом, а не правкой ядра |
| возможность (cap) | Одна проверяемая единица поведения («диалоги», «сетка»); проект включает её в `caps`, а реестр `caps.json` — источник правды |
| режим возможности | `core` — работает система, `code` — работает код в шве, `off` — данные остаются, поведение выключено; задаётся по возможности в `cap_options` |
| версия поведения | Номер правил механики, который фиксирует проект (`cap_options[cap].version`); позволяет движку менять поведение, не ломая старые проекты |
| шов | Объявленная точка расширения кодом (`sim` или `view`); пак перечисляет свои швы в `provides.seams`, проект не может подключиться к необъявленному |
| sim | Слой швов, который может менять состояние: чистый, детерминированный, проверяется headless и `check` |
| view | Слой швов, который рисует и звучит, но не меняет состояние; проверяется кадрами, а не прогоном |
| риг | Описание сборки и анимации: детали на сокетах, без скиннинга и весов; один формат для 2D и 3D |
| сокет | Якорь с осью, к которому крепится деталь или конечность |
| ассемблер (assembly) | Дерево деталей и сокетов: персонаж, дерево, дом |
| клип | Кейфреймы трансформаций узлов плюс события (шаг, удар, открыть) |
| локаль | Файл перевода проекта (`locales/<lang>.json`) со строками и хэшами исходников |
| стабильный ID строки | Ключ перевода по структуре (`scene/npc/greeting/2`), а не по тексту: переживает правки реплик |
| поведенческий корпус | Набор эталонных прогонов `(движок, версия проекта, seed, скрипт) → хэш состояния и лога`; ловит смысловые поломки после обновления |
| отпечаток прогона | Хэш конечного состояния и журнала для конкретного seed и скрипта; сравним между версиями движка |
| кит | Инструменты для агента (`cf-play`, схема, примеры), а не только архив документации; проверяется `kit doctor` |
| мастерская | Каталог проектов: манифест, хэш, лицензия и отчёт проверки; файлы лежат у автора, счётчики и отзывы — на сервере |
| проверяемость | Свойство проекта, которое можно подтвердить командой с воспроизводимым результатом; основа рейтинга мастерской |
| фаза | Этап плана; гипотеза, а не контракт: номер — идентификатор, состав и порядок меняются |
| инфраструктура | Серверная часть платформы: каталог, метрики, комнаты; всё остальное работает локально |
