# ScriptCat: что менять под новую программу

> Историческая записка про версию 0.14.0. Живой транспорт с 27.10.2026 —
> `_tools/ScriptCat/narthex.user.js`; `dispatch.user.js` удалён.

Userscript — тонкий транспорт: он берёт задачу из Notion, вставляет текст в Arena,
дожидается маркера, пишет лог в Drive и обновляет статус. Все правила должны
жить в карточке и регламенте, а не в коде: иначе каждая правка процесса — это
правка 3 000 строк и риск тихо сломать эстафету.

## 1. Что уже сделано (версия 0.14.0)

| Место | Изменение | Зачем |
|---|---|---|
| `@version` | `0.13.27` → `0.14.0` | ScriptCat показывает, что обновление встало |
| `roleContextText(role)` | добавлен блок «ПРОВЕРКА ПЕРЕД СДАЧЕЙ»: путь к `PLAYKIT.md`, точная команда `check` с `--seeds 1-5 --steps 300`, расшифровка кодов `0/1/2`, запрет на `evidence: injected` | агент не должен догадываться, чем проверять |
| `roleContextText` для Coordinator | «требуй код 0 и хэш отчёта; без них приёмки нет» | приёмка перестаёт быть вкусовой |
| `technicalHandoffFooter` | перед маркером добавлено требование полей `check` и `report` | доказательство едет вместе с ответом |
| маркер | `{"dispatch_id","run_id","status","check","report"}` | парсер принимает лишние поля, старые маркеры не ломаются |
| тест `visible-error-master-smoke.mjs` | версия в проверке обновлена на `0.14.0` | тест не пропускает забытый бамп версии |
| `README-авторизация.md` | описан раздел 0.14.0 | инструкция не врёт про текущую версию |

Проверка перед публикацией:

```bash
cd _tools/ScriptCat
node --check narthex.user.js
for t in tests/*.mjs; do node "$t" || exit 1; done
```

Три теста проходят. Gateway не менялся: `drive-gateway.gs` остаётся версии 1.2,
переразвёртывание веб-приложения не нужно.

## 2. Что нужно сделать руками в Notion

1. **Роли.** Добавить строку `Architect` (`Dispatch Function` = `Human`, если он
   не работает через Arena как агент; иначе `Executor`), убедиться, что
   `Coordinator` ровно один.
2. **База запросов.** Добавить три поля, необязательных для старых карточек:
   - `Kit Version` (текст) — из `__chronicle_ai__/KIT.json`;
   - `Check` (число) — код возврата `cf-play check`;
   - `Report SHA` (текст) — первые 8 символов `sha256` отчёта.
3. **Страница Координатора.** Перезалить содержимым `docs/coordinator.md`
   (или заменить ссылку в уставе на новую страницу). Новый агент не должен
   читать старые обсуждения.
4. **Страница «Регламент».** Ссылаться на действующий план
   [`phases.md`](./phases.md) и цикл [`agents/`](./agents/README.md);
   `program-v2.md` — исторический документ, не регламент.

Поля в Notion — витрина для человека. Если карточка их не заполнила, это не
повод останавливать эстафету, но Координатор обязан вернуть такую сдачу.

## 3. Порядок обновления

1. `narthex`: `npm run build:playkit-bundle && npm run pack:ai-kit`.
2. В репозитории кампаний: `npm run sync:ai-kit -- ../campaign-2`
   (из `narthex`), затем коммит `__chronicle_ai__/` в `main`.
3. В ветке TGD выполнить `git merge main` (или перебазировать), чтобы агент
   увидел новый кит.
4. В ScriptCat: заменить `narthex.user.js` на актуальную версию, перезагрузить
   вкладку Arena.
5. Проверка: открыть страницу агента с `?cf-auth-setup=1`, сделать `ping`
   (ключ и URL `/exec` не менялись).
6. Прогнать один ручной ход на тестовой задаче: в промпте должен появиться блок
   «ПРОВЕРКА ПЕРЕД СДАЧЕЙ», в ответе — маркер с `check` и `report`.

## 4. Совместимость и откат

- Старые карточки и старые маркеры работают: парсер не требует новых полей.
  Меняется только поведение Координатора (по регламенту).
- Откат — вернуть предыдущий файл userscript из истории Git. Данные в Drive и
  Notion не меняются, потому что формат логов прежний.
- Если gateway недоступен, пользователь видит прежнюю ошибку; новый код её не
  маскирует.

## 5. Чего в userscript быть не должно

- автоматической приёмки по одному `check = 0` (решение принимает Координатор);
- автоматического merge или закрытия PR;
- чтения дизайн-документа целиком в промпт;
- собственных правил нарезки задач;
- хранения ключей и токенов в тексте задания.

Если правило можно проверить в `cf-play`, оно проверяется там, а не в
userscript. Если правило про людей и приоритеты — оно в Notion и регламенте.
