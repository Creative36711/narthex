# Документы Narthex

Индекс: что читать в каком порядке. Если не знаешь, с чего начать — читай
сверху вниз, первые три документа отвечают на «зачем», «куда» и «как».

## Замысел и план

| Документ | Отвечает на вопрос |
|---|---|
| [`vision.md`](./vision.md) | **зачем** существует платформа: свойства, метрики, границы, цена свободы |
| [`phases.md`](./phases.md) | **в каком порядке**: десять фаз, что замораживает каждая, когда считается готовой |
| [`platform.md`](./platform.md) | **как устроено**: два рантайма, паки, студия, мастерская, совместимость |

## Контракты

[`contracts/`](./contracts/README.md) — исполняемые договоры, а не справка:

- [`contracts/format-v2.md`](./contracts/format-v2.md) — `project.json`: тип,
  возможности, режимы, языки, код в швах, миграция;
- [`contracts/caps.md`](./contracts/caps.md) — реестр возможностей, режимы и
  версии поведения;
- [`contracts/pack.schema.json`](./contracts/pack.schema.json) — манифест пака
  и объявленные швы;
- [`contracts/adr/`](./contracts/adr/) — решения 0001–0012 и их причины.

Проверка: `npm run check:contracts`.

## Правило

Один факт — одно место. Если документ противоречит коду, прав код, а документ
считается дефектом и правится в том же PR. Если противоречат два документа —
прав тот, который ближе к `docs/contracts/`.
