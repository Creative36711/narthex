# Проверка границы core / packs

`npm run check:pack-boundary` — исполняемая проверка §3 для `src/core/**`. Она разбирает TypeScript/JavaScript AST, а не ищет слова в исходном тексте:

- сравнение или управляющее условие, выбирающее зарегистрированный ID пака, — ошибка с путём и номером строки;
- статический, динамический или CommonJS-импорт из `packs/**` — ошибка с путём и номером строки;
- текст диагностического сообщения, комментарий или сравнение записей реестра в `scripts/**` сами по себе не являются ветвлением.

Список ID берётся из `packs/registry.json`, поэтому при регистрации нового пака список исключений не нужно поддерживать. Сканер не содержит исключений по именам файлов или каталогов. `check:contracts` запускает эту проверку после существующих контрактов и `check:packs`.

Каждый запуск сначала проверяет четыре временные фикстуры, которые создаются и удаляются внутри `scripts/`:

```text
fixture (a) branch on pack ID in src/core: PASS — rc=1, src/core/fixture-branch.ts:1
fixture (b) entry.pack filter in scripts probe: PASS — rc=0
fixture (c) registry diagnostic string literal: PASS — rc=0
fixture (d) import from packs/** in src/core: PASS — rc=1, src/core/fixture-import.ts:1
```

Ненулевой код в (a) и (d) — ожидаемый результат негативных фикстур; команда `check:pack-boundary` считается успешной, когда оба нарушения найдены с точными путём и строкой, а безвредные примеры (b) и (c) приняты. Лексические поиски, оставшиеся в `probe:pack-move`, предназначены для диагностики; авторитетная проверка границы — AST-гейт `check:pack-boundary`.
