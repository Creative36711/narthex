# Совместимость: движок, кампании, сохранения

Документ описывает контракт версий Chronicle Forge: что и кем версионируется,
как переносятся сохранения, как кампания объявляет совместимость и что видит
игрок при обновлении. Аудитория — разработчики движка и авторы кампаний.

Решения зафиксированы и реализованы (фаза A и B); мастерская — фаза C,
её устройство описано в [`workshop.md`](./workshop.md).

---

## 1. Четыре номера версии

Главная ошибка, которую важно не повторить: описывать «совместимость» одним
числом. Несовместимости бывают разные, и чинятся они по-разному.

| № | Что | Где объявлено | Кто отвечает | Как проверяется |
|---|-----|---------------|--------------|-----------------|
| 1 | **Формат пакета** — структура `campaign.json`/`world.json`/`manifest.json` | `PACKAGE_FORMAT` в движке; `meta.package_format` в пакете | движок | при загрузке пакета |
| 2 | **Версия движка** | `ENGINE_VERSION` (из `package.json` через define vite) | движок | `meta.min_engine` ≤ `ENGINE_VERSION` |
| 3 | **Формат сохранения** — форма `GameState` | `SAVE_VERSION` (`shared/types.ts`) | движок | цепочка миграций `SAVE_MIGRATIONS` |
| 4 | **Версия кампании** и база сохранений | `meta.version`, `meta.save_base_version` | мастер (числа считает редактор) | `save.campaign_version` ≥ `save_base_version` |

Номера 1–3 мастер не видит и не настраивает: обновление движка — забота
движка. Мастер отвечает только за номер 4, причём рутину делает редактор
(сравнение пакетов), а человек подтверждает результат.

### 1.1 Версия движка

`ENGINE_VERSION` берётся из `package.json` (define `__CF_ENGINE_VERSION__` в
`vite.config.ts`); в headless-прогонах — из `npm_package_version`, иначе
`0.0.0-dev`. Версии `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`
держат равными ей: десктоп-оболочка и движок релизятся вместе.

Поле `meta.engine_version` в старых пакетах означало «движок, под который
собрана кампания» и нигде не проверялось. Теперь это **минимальная** версия
движка; новое имя — `meta.min_engine`. Движок читает оба
(`min_engine ?? engine_version`), старые пакеты продолжают открываться.
Если движок старее требования, игрок видит предупреждение в главном меню
(кампания при этом запускается: лучше играть с предупреждением, чем не играть).

### 1.2 Версия кампании

`meta.version` — semver (`1.4.2`). Растёт при публикации обновления.
Редактор предлагает номер по характеру изменений: ломающие — `major`,
добавления — `minor`, правки — `patch` (`suggestNextVersion`).

### 1.3 База сохранений

`meta.save_base_version` — «сохранения от какой версии кампании ещё
поддерживаются». Пусто — поддерживаются все сохранения этой кампании (их
починит движок). Заполняется автоматически при публикации, если найдены
ломающие изменения.

## 2. Сохранение: обёртка и ключи

Сохранение лежит в `localStorage` в обёртке `SaveEnvelope`
(`shared/types.ts`), а не «голым» `GameState`:

```jsonc
{
  "envelope_version": 1,
  "save_version": 4,             // формат GameState
  "campaign_id": "ash-of-caerden",
  "campaign_version": "1.4.2",   // от какой кампании сейв
  "engine_version": "0.7.0",     // каким движком записан
  "created_at": "…", "updated_at": "…",
  "tick": 96, "location": "loc_market",
  "state": { … }
}
```

| Ключ | Что |
|------|-----|
| `chronicle-forge:save:<campaignId>` | активное сохранение (обёртка) |
| `chronicle-forge:save-backup:<campaignId>` | исходник сейва до первой правки (миграция/починка) |

Старый формат («голый» `GameState` под тем же ключом) читается и
переносится автоматически (`parseStored`). Обёртка — источник правды по
`save_version`: сейв из более нового движка распознаётся как «новее», даже
если само состояние помечено старой версией.

**Правило: чужое сохранение не удаляется молча.** Сейв стирается только
по правилам игры (permadeath — `gameOver()`, рестарт забега, явное удаление
кампании). Несовместимый сейв остаётся на диске: он понадобится, если игрок
вернётся к прежней версии кампании.

## 3. Перенос сохранений (фаза A, движок)

Два независимых механизма в `src/core/savemigrate.ts`.

### 3.1 Миграции формата

```ts
export const SAVE_MIGRATIONS: SaveMigration[] = [
  { from: 1, to: 2, title: 'базовые поля состояния', apply(state, ctx) { … } },
  { from: 2, to: 3, title: 'экипировка и валюты',    apply(state, ctx) { … } },
  { from: 3, to: 4, title: 'слоты экипировки',       apply(state, ctx) { … } },
]
```

- шаги идут строго вверх, цепочка непрерывна (проверяется смоуком);
- старые шаги **не удаляются** — сейв любой поддерживаемой версии доезжает
  до текущей;
- шаг обязан быть идемпотентным и не требовать кампании;
- сейв новее движка (`save_version > SAVE_VERSION`) не открывается и **не
  перезаписывается**: его оставил более новый движок, портить его нельзя.

`OLDEST_SAVE_VERSION = 1` — ниже переносить неоткуда.

### 3.2 Починка ссылок (`repairState`)

Кампания обновилась — сейв ссылается на то, чего в пакете больше нет. Сейв не
выбрасывается, а приводится в соответствие; каждая правка попадает в отчёт:

| Что в сейве | Если объекта нет в кампании |
|-------------|------------------------------|
| инвентарь, экипировка | предмет убирается, вещь снимается |
| шаблон героя | берётся `default_player` кампании |
| навыки (`skills`, `skill_marks`, выбор создания) | навык убирается (реестр кампании + встроенный словарь) |
| потребности | новые — на максимум; значения — в пределы `0…max`; исчезнувшие убираются |
| статусы | снимаются |
| отряд | напарник покидает отряд |
| квесты | квест без определения — из журнала; стадия не найдена — первая стадия |
| `fired_rules` | отметка убирается (иначе правило с `once` сработает повторно) |
| локация/сцена/регион | герой переносится в стартовую локацию/сцену |
| `spawned`, описания, мёртвые/убранные | записи убираются |
| погода, кодекс, фракции, перекрытые дороги | записи убираются |

Отчёт — по-русски, списком, с именами объектов (`SaveReport.notes`, виды
`migrated` / `repaired` / `warning`). Игрок видит его в модалке перед
продолжением забега (`player/SaveReportModal.tsx`). Если название узнать
неоткуда (объект удалён из кампании), показывается id в кавычках.

### 3.3 Порядок открытия сейва

`openSave(campaignId, campaign)`:

1. прочитать и разобрать (обёртка или старый «голый» формат);
2. вердикт по версиям кампании (`checkSaveVersion`);
3. миграции формата;
4. починка ссылок;
5. если что-то изменилось — записать резервную копию исходника (один раз) и
   обновлённый сейв.

`inspectSave` — то же без записи: по нему меню решает, предлагать ли
«Продолжить», не трогая файл.

### 3.4 Вердикты

| Вердикт | Когда | Что делает игрок |
|---------|-------|------------------|
| `ok` | версии подходят | «Продолжить забег» (+ отчёт, если была починка) |
| `unsupported` | `campaign_version < save_base_version` | причина, «Начать новый забег», «Сохранить файл сейва»; сейв не удаляется |
| `too_old` | формат древнее `OLDEST_SAVE_VERSION`, новее движка или битый файл | то же; файл не перезаписывается |

Если игрок после такого вердикта начинает новый забег, старый файл уезжает в
резервный ключ (`preserveSave`) — иначе новый забег затёр бы его тем же
ключом, и обещание «сохранение останется на диске» оказалось бы ложью.

Сейв **без** версии кампании (сделан до введения обёртки) считается
совместимым: его чинит `repairState`, а версия запишется при первом автосейве.

### 3.5 Шлюпка спасения

`exportSaveText` / `importSaveText` — экспорт и импорт файла `.cfsave`.
Это и способ спасти сейв, который не перенёсся, и способ приложить сейв к
багрепорту.

## 4. Совместимость кампаний (фаза B, редактор)

### 4.1 Классы изменений

| Класс | Примеры | Что делает движок | Вердикт сравнения |
|-------|---------|-------------------|-------------------|
| **S** — косметика | `label`, `description`, изображения, музыка, оформление | ничего | совместимо |
| **A** — добавление | новый НПС, предмет, навык, статус, слот, локация | заполняет дефолты, пишет в отчёт | совместимо |
| **B** — правка значений | `decay_per_tick`, урон, бюджеты создания героя, `dice_rules` | пересчитывает производные, предупреждает | **совместимо по умолчанию** (решение заказчика) |
| **C** — удаление/переименование id | удалён НПС в отряде, стадия квеста, потребность, правило, локация героя | починка + громкий отчёт | **ломает** → `save_base_version = новая версия` |
| **D** — смена смысла | тот же id, другая семантика; перестроен квест; другой старт | не чинится | **ломает**; решается мастером |

Словарь видов объектов и их классы — `CHANGE_KINDS` в `shared/compat.ts`.
Косметические поля перечислены в `COSMETIC_FIELDS` и в свёртке не
участвуют: смена названия не делает обновление ломающим.

### 4.2 Инвентаризация и отпечаток

`inventoryOf()` собирает по пакету: id по видам объектов (сцены, сущности,
правила, квесты и их стадии, реестры `campaign.json`…), свёртку значимых
полей каждого объекта и названия для отчёта. Итог — `CampaignInventory` с
отпечатком `digest` (FNV-1a, не криптография — только сравнение пакетов).

`diffInventories(prev, next)` даёт `added` / `removed` / `changed` и список
`breaks` с последствиями по-русски («Предмет исчезнет из инвентаря и
экипировки героя»).

### 4.3 `compat.json` — контракт пакета

Пишет редактор при публикации (`editor/compatPublish.ts`), читает игрок:

```jsonc
{
  "format": "chronicle-compat/1",
  "version": "1.5.0",
  "save_base_version": "1.5.0",
  "min_engine": "0.7.0",
  "package_format": 1,
  "updated_at": "2026-09-27T12:00:00.000Z",
  "inventory_digest": "5e2e1581969f79e9",
  "breaks": [
    { "kind": "npc", "id": "npc_guard_aldric", "label": "Страж Алдрик",
      "impact": "Персонаж исчезнет из сцен и отряда, связанные диалоги и квесты могут не сработать" }
  ],
  "changes": { "added": 0, "removed": 1, "changed": 1 },
  "notes": "Переписана глава 3"
}
```

Поля, нужные рантайму (`version`, `min_engine`, `package_format`,
`save_base_version`), дублируются в `campaign.json`: движок решает судьбу
сохранения, не открывая `compat.json`. Файл попадает в `.chronicle` вместе с
остальными (`store.allPaths()`).

### 4.4 Публикация версии в редакторе

Раздел **«Кампания → Версии»**:

1. «Проверить совместимость и опубликовать версию» — редактор читает
   предыдущий `compat.json`, сравнивает инвентаризации, показывает отчёт
   (что добавлено/изменено/удалено, ломающие изменения и их последствия);
2. мастер подтверждает номер версии (предложенный можно поправить) и пишет
   «что изменилось» для игрока;
3. редактор записывает `compat.json` и обновляет `campaign.json`.

Отдельные поля доступны и вручную: версия, минимальный движок,
`save_base_version`, кнопки «поднять версию» (patch/minor/major).

Общая проверка кампании («Проверить» в редакторе) ловит ошибки в этих полях:
версия не в формате semver, непонятный минимальный движок, граница
сохранений новее версии кампании (с ней сохранения не открылись бы ни у
кого).

### 4.5 CLI

```bash
npx tsx scripts/compat-report.mts <старая> <новая> [--json compat.json]
```

`<старая>`/`<новая>` — каталог Campaign Package или файл `.chronicle`.
Отчёт по-русски, предложение по версии и `save_base_version`, код возврата 1
при ломающих изменениях (удобно в CI автора кампании).

### 4.6 Запрет переименования id

Решение заказчика — жёсткий вариант. Id не редактируется нигде: он
генерируется из названия при создании объекта (`editor/ids.ts`), а в
«Расширенном JSON» попытка поменять `id` отклоняется с объяснением
(`FileAdvancedJson` в `editor/Fields.tsx`). Нужен «переименованный» объект —
создайте новый и удалите старый: это честное ломающее изменение, и контракт
его покажет.

## 5. Что видит игрок

**Обновление движка** — прозрачно: сейв переносится, при правках игрок видит
отчёт «Сохранение перенесено и почищено» со списком.

**Обновление кампании, сейв совместим:**

> Сохранение сделано в версии кампании 1.4.2, сейчас установлена 1.5.0.
> Вот что изменилось:
> · Починка: Из инвентаря убрано: «Ржавый ключ» — этих предметов больше нет в кампании.

**Сейв слишком старый:**

> Сохранение не поддерживается
> Сохранение сделано в версии кампании 1.0.0, а поддерживаются сохранения
> начиная с 1.5.0.
> Старое сохранение не удалено: оно останется на диске и откроется, если
> вернуться к прежней версии кампании.
> [Начать новый забег] [Сохранить файл сейва] [Закрыть]

Главное меню показывает версию кампании, версию движка и строку о
сохранении (версия кампании в сейве, тики, дата), а при несовпадении
`min_engine` — предупреждение.

## 6. Обязанности автора кампании

1. Не менять и не переиспользовать id (движок и редактор это enforce'ят).
2. Публиковать обновления через «Кампания → Версии»: контракт и номер версии
   появятся сами.
3. Не понижать `save_base_version` без причины и не завышать его «на всякий
   случай» — это лишает игроков сохранений.
4. Описывать в «что изменилось» то, что заметит игрок, а не технические детали.
5. Проверять крупные правки через `scripts/compat-report.mts` до публикации.

## 8. План фаз

- **A — совместимость сохранений** (сделано): обёртка сейва, цепочка
  миграций, починка ссылок, отчёт игроку, резервная копия, экспорт/импорт.
- **B — контракт кампании** (сделано): `compat.json`, инвентаризация и
  сравнение пакетов, вкладка «Версии», CLI, запрет переименования id.
- **C — мастерская** (запланировано): установка/обновление кампаний,
  хранение в appdata, откат версии. См. [`workshop.md`](./workshop.md).
- **D — экосистема**: каталоги мастеров, подписка на обновления, статистика
  версий.
