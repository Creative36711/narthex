# cf-play — движок как инструмент, а не как исходники

Документ отвечает на один вопрос: **как дать внешнему ИИ-агенту возможность играть
в кампанию, не отдавая ему движок**. Хостинг, домены и браузерные демо здесь не
участвуют: агент работает в своём терминале, а движок приезжает к нему одним
файлом.

## 1. Три разных требования, которые обычно путают

| Требование | Что значит на практике | Чем решается |
| --- | --- | --- |
| **Возможность** | агент может пройти кампанию и увидеть последствия | CLI/бандл (этот документ) |
| **Секретность** | агент не может прочитать код движка | только серверное исполнение |
| **Целостность** | результату агента можно верить | пиннинг версии + хеши + CI |

`cf-play` закрывает первое и третье. Второе он **не** закрывает и не пытается:
минифицированный JavaScript читается. Это осознанный размен — см. §7.

## 2. Граница возможностей

Агент получает ровно две вещи.

**Наблюдение — то, что игрок видит на экране:**

- сцена, локация, метка времени (тик);
- видимые слоты сцены: кто/что там, какое действие доступно (`talk` / `use` / `inspect`);
- выходы — только реальные дороги с ценой в тиках;
- открытый диалог: реплики, говорящий, варианты ответа;
- **бой**: арена, раунд, чей ход, юниты с HP и координатами, достижимые клетки;
- HUD: HP/MP, потребности, квесты со стадиями, инвентарь;
- новые строки журнала и ошибки открытия диалога.

**Действия — те же глаголы, что у игрока:**

| Действие | Что вызывает |
| --- | --- |
| `interact` | клик по слоту (разговор, предмет, осмотр) |
| `interact_option` | выбор пункта в меню предмета |
| `choose` | выбор реплики в диалоге |
| `travel` | переход по дороге |
| `wait` | ожидание N тиков |
| `combat_attack` / `combat_move` / `combat_end_turn` / `combat_flee` | ход в бою |
| `combat_close` | кнопка «Продолжить» на экране исхода боя |
| `use` / `equip` | предмет из инвентаря |
| `fight` | тестовый помощник: доводит бой политикой «атакуй первого живого врага» |

`fight` — не новое право, а композиция `combat_attack` / `combat_end_turn` /
`combat_close`; в транскрипте он виден как одно действие.

**Чего агент не получает:** исходников движка, редактора, доступа к реестрам
кампании сверх того, что видно на экране, возможности менять правила, монтировать
движок, читать `src/`. Флаг `--debug` добавляет к результату `state.final.json` —
это **состояние прогона**, а не код: без него агент пишет кампании вслепую, потому
что не видит флагов, квестов и переменных.

## 3. Команды

```bash
# один сценарий
node cf-play.mjs run  <кампания> --seed 42 --script route.json --out runs/a

# случайные прогоны: ищут падения и застревания
node cf-play.mjs fuzz <кампания> --seeds 1-20 --steps 400 --out runs/fuzz

# жадный обход: сначала неисследованные локации
node cf-play.mjs explore <кампания> --seed 7 --steps 300

# проверка целостности готового прогона
node cf-play.mjs verify <runs/a> --expect-engine 0.8.0
```

Код возврата: `0` — без провалов, `1` — проваленный assert/ошибка/софтлок,
`2` — ошибка вызова. Флаг `--json` печатает машиночитаемый итог в stdout.

## 4. Формат маршрута

```json
{
  "name": "01-night-pass / smoke",
  "steps": [
    { "do": "interact", "entity": "npc_vyaz" },
    { "do": "travel", "to": "loc_serpentine" },
    { "do": "fight" },
    { "do": "interact", "entity": "npc_brann" },
    { "do": "choose", "text": "Спросить про обморожение" },
    { "do": "expect", "scene": "scene_outpost_yard" },
    { "do": "expect", "has_item": "item_order" },
    { "do": "expect", "game_over": null }
  ]
}
```

Доступные проверки (`expect`): `scene`, `flag`, `no_flag`, `has_item`,
`game_over` (`null` — забег идёт), `tick_at_least`, `quest_at_stage`.
Шаг `{"do":"snapshot","label":"…"}` просто ставит метку в транскрипте.

## 5. Что создаётся

```
runs/a/
├── transcript.md   # человекочитаемый лог: сцены, реплики, бои, журнал
├── run.json        # машинный лог: действие + наблюдение на каждом шаге
├── result.json     # вердикт: статус, проверки, покрытие, хеши
└── state.final.json  # только с --debug
```

`result.json` содержит:

- `engine` — версия движка (пиннинг);
- `campaign.logicDigest` — sha256 по всем `json`/`ink` кампании, **без медиа**:
  меняется логика — меняется отпечаток, а 26 МБ картинок в хеш не тянутся;
- `seed` — воспроизводимость;
- `coverage` — какие сцены, локации, диалоги, концовки посещены, а какие **нет**;
- `hashes.transcript` / `hashes.run` — хеши файлов прогона.

## 6. Детерминизм и целостность

Один и тот же `seed` + один и тот же маршрут + одна и та же версия движка дают
**побайтово одинаковый** транскрипт. Это проверено: прогон через `tsx` и прогон
через собранный бандл дают одинаковый `hashes.transcript`.

`verify` пересчитывает хеши и сверяет версию движка:

```bash
$ node cf-play.mjs verify runs/a --expect-engine 0.8.0
✓ прогон цел: 115be504-… seed 7, движок 0.8.0, шагов 15

$ node cf-play.mjs verify runs/a --expect-engine 9.9.9
✗ движок 0.8.0 ≠ ожидаемого 9.9.9
```

Отсюда правило, которое снимает главный риск «агент поправил движок и сдал
зелёный прогон»:

> **Локальный прогон — совещательный. Авторитетный прогон — в CI.**

Агент гоняет `cf-play` у себя для быстрой обратной связи: это может быть любая
сборка, даже подправленная. Вердикт выносит CI, который берёт **запиненную**
версию бандла и переигрывает маршрут на чистом чекауте. Локальный результат без
совпадающего хеша в CI не считается доказательством.

Практическая схема в `campaign-2`:

```yaml
# .github/workflows/playtest.yml (эскиз)
- uses: actions/checkout@v4
- run: node __chronicle_ai__/campaign-audit.mjs campaigns/${{ matrix.campaign }}
- run: |
    node __chronicle_ai__/cf-play.mjs run campaigns/${{ matrix.campaign }} \
      --seed 42 --script __chronicle_ai__/routes/smoke.json --out runs/smoke \
      --json
- uses: actions/upload-artifact@v4
  with: { name: playtest, path: runs/ }
```

## 7. Почему не exe, не WASM и не сервер — пока

| Вариант | Что даёт | Цена |
| --- | --- | --- |
| **CLI-бандл** (выбран) | работает у любого агента с Node; один файл; ноль инфраструктуры | код читаем |
| Tauri exe | красивый плеер для человека | GUI, подпись, per-OS, агент его не запустит |
| WASM-модуль | жёсткая граница экспортов, тампер-резистентность к `Math.random` | переписать ядро под сборку; inkjs и браузерные зависимости |
| Серверный API | код не уезжает вообще | хостинг, лимиты, а у части агентов нет сетевого доступа к вашему домену |

Проверено на живом агенте (Arena): доступны `github.com`, `api.github.com`,
`registry.npmjs.org`, `pypi.org`; **недоступны** `raw.githubusercontent.com`,
`release-assets.githubusercontent.com`, `jsdelivr`, `unpkg`, `*.github.io`,
`*.vercel.app`. Поэтому серверный API и «просто дать ссылку» не покрывают всех
агентов, а `npx`/`git clone` — покрывают.

Если позже понадобится именно **секретность кода**, а не возможность играть,
добавляется четвёртый вариант: тот же `cf-play` живёт на сервере, агент ходит в
`POST /runs` и получает наблюдения. Тогда локальный бандл остаётся для оффлайна,
а авторитетный прогон — серверный.

## 8. Что это даёт кампаниям

`campaign-audit.mjs` отвечает на вопрос «правильно ли собрано»: схема, ссылки,
медиа. `cf-play` отвечает на другой: **«что происходит, когда в это играют»**.

Первый прогон на `01-night-pass` уже дал три находки, которых статический аудит не
видит:

1. случайные обходы (6 seed'ов, до 150 шагов) заканчиваются `victory` за 8–19
   шагов — правило дедлайна `rule_deadline` завершает забег `game_over_victory`
   на 7-м тике при нейтральной концовке «Немой перевал»; тип исхода и тон
   концовки расходятся, нужен вердикт TD;
2. без `combat_close` бой с результатом `fled` оставляет `engine.combat`
   непустым — в браузере это закрывает кнопка «Продолжить», и агент без неё
   застревает (в инструменте исправлено);
3. на seed 42 дорога к заставе приводит к гибели за 2 атаки — это данные для
   баланса, а не баг.

`coverage` при этом показывает обратное: 19–21 сцена из 24 не посещается ни одним
из прогонов. Именно поэтому «прошёл игру» — не то же самое, что «проверил
кампанию», и почему нужны маршруты, а не только случайный обход.

## 9. Как это попадает к агенту

Порядок по возрастанию усилий:

1. **Сейчас:** `npm run build:playkit-bundle` → `public/ai/cf-play.mjs` (787 КБ,
   один файл). Кладётся в `campaign-2/__chronicle_ai__/` рядом с
   `campaign-audit.mjs` — агент получает его вместе с чемоданом.
2. **Дальше:** CI собирает бандл и публикует артефактом релиза/в публичный
   `engine-dist`; агент скачивает его `git clone`.
3. **Позже:** пакет в npm (`npx @chronicle-forge/playkit …`) — установка без
   репозитория; имена пакетов свободны.
4. **Опционально:** MCP-обёртка (`cf_start_run`, `cf_step`, `cf_get_state`) для
   агентов, которые умеют подключать MCP-серверы.

## 10. Что остаётся человеку

`cf-play` не проверяет вёрстку, тайминг, звук, читаемость шрифтов и «ощущение»
сцены. Для этого нужен браузер и человек — и именно здесь остаются место для
Tauri-приложения, веб-демо и живого плейтеста. Инструмент снимает с человека
рутину «пройти 50 раз и записать, что сломалось», а не заменяет приёмку.
