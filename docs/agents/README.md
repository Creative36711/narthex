## Как устроен цикл

```
Notion: миссия «Активна»
        │
        ▼
Coordinator ──CF_COORDINATOR_RESULT next=<роль>──▶ исполнитель
        ▲                                            │
        │                                     работа в своей зоне
        │                                     коммит → пуш → PR → мерж
        │                                            │
        └──── Submitted ◀── Continue ◀───────────────┘
        │
        └── все задачи Accepted → next: "done" → приёмка (Warden) → «Завершена», стоп
```

Мерж делает сам исполнитель в том же ходе: `gh pr create --fill` и
`gh pr merge --squash --delete-branch`. Кнопки Create PR / Merge PR — не
маршрут, а аварийный выход: они пишут команду в чат, агент отвечает новым
сообщением, и учёт хода сбивается. ScriptCat нажимает только **Continue** —
эта кнопка не требует участия агента. Если пришлось нажимать Create/Merge —
это дефект инструкции исполнителю, а не штатный шаг.

Цикл **бесконечный по замыслу**: останавливает его вердикт приёмки
(`accept` от роли с функцией `Reviewer`) или пауза транспорта. Координатор
закрыть миссию не может: его `next: done` — это передача на приёмку. Пауза — не «подождать и продолжить»: тики
встают, статус краснеет, уходит громкий пуш, и дальше ждёт человек.

## Что ScriptCat дописывает сам

К тексту Координатора транспорт добавляет технический блок — в каждое
сообщение. Это не задание, а факты о среде: какой репозиторий, что ветка
сессии может быть старым снимком без общей истории с `main`, как начать
безопасно. Набор различается по полю `Функция`:

| Функция | Блок |
|---|---|
| `Executor` | ритуал старта: `git reset --hard origin/main` → своя ветка от `origin/main` |
| `Auditor` | «ты не пишешь» + чтение `origin/main` и слитого PR |
| `Coordinator` | git не нужен: только Notion и Drive |

Факт о снимке проверен и записан с числами в `sandbox.md`. Подробности
транспорта — [`_tools/ScriptCat/README-narthex.md`](../../_tools/ScriptCat/README-narthex.md).

## Когда цикл останавливается

| Повод | Что делает транспорт |
|---|---|
| ответ без маркера | ждёт 20 с, напоминает шаблон (до двух раз), затем пауза |
| видимая ошибка Arena | пауза сразу, без повторной отправки |
| исключение Notion/Drive/шлюза, таймаут PR, нет кнопки Send | пауза с причиной |
| задача висит в `Running` дольше 45 минут | возврат в `Ready`, цикл идёт дальше |
| агент не ответил ни одним сообщением 30 минут | пауза: очередь и ожидание сняты, задание до него не дошло |

Снимает паузу только Мастер — кнопкой «Продолжить» с подтверждением и текстом
причины. Нажатая кнопка не молчит: «Шаг» пишет, что сделал или почему не смог,
а задание, сохранённое перед переходом, досылается на странице адресата и в
ручном режиме. Плашка «задание выполнено» закрывается до вставки текста — чат
освобождают, а не пишут поверх него. В ntfy два потока: тихие вехи (ход выдан, ответ записан, пауза снята) и
громкие тревоги (пауза, ошибка, конец миссии). Это единственный случай, когда
циклу нужен человек: агент, забывший маркер, — ошибка формата, а не блокировка,
и решается напоминанием, а не обращением к Мастеру.

## Состояния задачи

| Состояние | Кто ставит | Что означает |
|---|---|---|
| `Draft` | Координатор, Архитектор или Мастер | предложение: ещё не выдано; выдаёт его Координатор (Draft → Ready) |
| `Ready` | Координатор | можно выдавать; есть Намерение, Инварианты, Acceptance (оракул), Scope и Кому |
| `Running` | ScriptCat | ход выдан, `Started At` записан |
| `Submitted` | ScriptCat | ответ записан в лог, PR слит |
| `Accepted` | Координатор | проверено, гейт зелёный |
| `Rework` | Координатор | причина указана в `Ответ` |
| `Blocked` | Координатор | нужен выбор из вариантов (см. `tz.md` §0) |

Черновик — не тупик. Координатор вправе выдать его сам: переписать под оракул
миссии и перевести в `Ready` (или отправить в архив, если он дублирует уже
выданное). Пересоздавать такую же карточку ради смены статуса не нужно: право
на `Ready` у Координатора есть, а `Draft` — это предложение, а не запрет.
Мастер и Архитектор пишут только `Draft`: приказом их текст делает Координатор.

Черновик с неактивной ролью выдать нельзя, и причина в списке названа точно:
`Статус «Ждёт»` (агент создан, но не включён), `нет Agent URL` (роль есть, а
агента в Arena нет) или `нет в «Ролях»` (опечатка в `Кому` или новая роль).
Координатор назначает в `Кому` активную роль или оставляет карточку в `Draft` и
говорит, какую роль нужно включить.

**Статус роли и `Agent URL` ставит Мастер.** Агента в Arena создаёт человек, и
только он решает, держать ли ещё одну вкладку в цикле; Координатор, исполнители
и аудиторы в базе «Роли» только читают. Включить роль «по ходу» — не право
агента, иначе появятся исполнители, которых физически нет.

Переходы делает ScriptCat только между `Ready → Running → Submitted`.
Всё остальное — решение Координатора, записанное в Notion. Единственное
исключение: `Running → Rework`, когда PR оказался **закрыт без мержа** — это
констатация факта «работа не влита», причина пишется в `Ответ`, а решение
(перевыдать, разбить, закрыть) остаётся за Координатором.

Состояния PR, которые различает ScriptCat: `Merged` (бейдж подтверждает мерж),
`Closed` (бейдж есть, но мерж не подтверждён — так же выглядит и ручной мерж
через GitHub, поэтому решает маркер `merged: true`) и `Timeout` (пауза).

## Что каждый пишет

* **Координатор** — только Notion и Drive: карточки, вердикты, логи.
* **Исполнитель** — код в своей зоне, ветка, PR, отчёт в Drive.
* **Аудитор** — отчёт и вердикт; в код не пишет.
* **ScriptCat** — состояния `Running`/`Submitted`, `Branch`, `Check`, `Run ID`.

Никто не пишет в две зоны одновременно. Если нужна правка в чужой зоне — это
новая карточка, а не «быстро поправлю».

## Запуск на новый проект

1. Создать страницу проекта по образцу «Narthex — разработка платформы».
2. Создать четыре базы: Роли, Миссии, Запросы, Вопросы (схемы — в `tz.md` §3
   и в самой странице; «Вопросы» — в `roles.md` § «Вопросы Мастеру»).
3. Заполнить роли: `Agent URL` (ссылка вида
   `https://arena.ai/agent/<id>`; id — последний сегмент пути, отдельного поля
   нет), `Функция`, `Статус`, `Зона записи`, `Гейт`, `Устав`.
4. Завести миссию со `Состояние = Активна`, приложить ТЗ и `Координатор`.
5. Дать Координатору черновик карточек или пустую доску: `Кому`, `Sequence` и
   число `Ready` — его работа, а не ТЗ. На старте достаточно одной карточки
   «развернуть очередь».
6. Прописать id источников данных в `_tools/ScriptCat/narthex.user.js` (`C`).
7. Установить скрипт, открыть страницу Координатора
   (`https://arena.ai/agent/<id>`) и нажать **▶ Включить** в панели Narthex
   в правом нижнем углу. Автостарт — `?cf-auto` в адресе страницы.

* **Миссия** NAR-1 «Ядро под паки» — `Состояние = Активна`, `Итог` пуст

* **Карточки** — 10 черновиков в базе «Запросы» (источник `11b41fcc…`) с

  ScriptCat зелёные.

### Два действия, которые может сделать только Мастер

1. Создать в Arena пять агентов и вписать их адреса в поле `Agent URL`
   соответствующих ролей. Пока `Agent URL` пуст, ScriptCat роль не видит:
   фильтр — `Статус = Активна` **и** непустой `Agent URL`.
2. Нажать **Шаг** на любой странице `arena.ai` — скрипт сам откроет
   Координатора и выполнит шаг там; один клик на ход;
   когда цикл станет понятен, та же панель включает автоцикл (**▶ Включить**
   или `?cf-auto` в адресе). Состояние живёт в Notion, переключение ничего не
   теряет.

Дальше цикл идёт без человека: Координатор разворачивает очередь (NAR-1.0) →
выдаёт 1.1 → Architect строит карту ядра → исполнитель сам коммитит, пушит и
мержит PR → Continue → 1.2 → … → 1.10. Останавливает цикл только флаг
Координатора. Если в задании чего-то нет — агент решает сам и пишет три строки
в журнал решений, а не ждёт Мастера.

### Проверка перед стартом

```bash
npm ci
npm run check:brand && npm run check:contracts
for t in _tools/ScriptCat/tests/*.mjs; do node "$t" || exit 1; done
```

`npm ci` обязателен: без `node_modules` проверки не запускаются. Отчёты
`cf-play` лежат в `.cf-play/` и в git не попадают — иначе `check:brand` падает
на старом имени пакета в отчёте.

## Чего в системе нет намеренно

* **Нет веб-панели управления** — состояние живёт в Notion, а управление в
  ScriptCat. Отдельный дашборд означал бы второй источник правды.
* **Нет очереди с блокировками** — при числе агентов ≤ 5 достаточно Notion и
  последовательного цикла. Supabase понадобится позже (см. `connectors.md`).
* **Нет «умного» ретрая** — ошибка останавливает цикл. Молчаливый повтор
  скрывает причину и делает отладку дороже, чем простой.
