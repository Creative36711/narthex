# Narthex: команда ИИ-агентов

Пакет документов, который делает разработку платформы циклом, а не перепиской.

## Файлы

| Файл | Отвечает на вопрос |
|---|---|
| `roles.md` | кто есть, у кого какая зона, что должно быть зелёным |
| `tz.md` | что делать в первой миссии и как выдавать задачи |
| `connectors.md` | какие инструменты берём и почему остальные нет |
| `sandbox.md` | что можно и чего нельзя в песочнице агента |
| `../coordinator.md` | регламент Координатора (роль, права, запреты) |
| `_tools/ScriptCat/README-narthex.md` | как установить и настроить транспорт |

## Как устроен цикл

```
Notion: миссия «Активна»
        │
        ▼
Coordinator ──CF_COORDINATOR_RESULT next=<роль>──▶ исполнитель
        ▲                                            │
        │                                     работа в своей зоне
        │                                     коммит → пуш → PR → мерж
        │                                            │
        └──── Submitted ◀── Continue ◀───────────────┘
        │
        └── все задачи Accepted → next: "done" → миссия «Завершена», скрипт стоп
```

Мерж делает сам исполнитель в том же ходе: `gh pr create --fill` и
`gh pr merge --squash --delete-branch`. Кнопки Create PR / Merge PR — не
маршрут, а аварийный выход: они пишут команду в чат, агент отвечает новым
сообщением, и учёт хода сбивается. ScriptCat нажимает только **Continue** —
эта кнопка не требует участия агента. Если пришлось нажимать Create/Merge —
это дефект инструкции исполнителю, а не штатный шаг.

Цикл **бесконечный по замыслу**: останавливает его только явный флаг
Координатора. Пауза возникает лишь из-за ошибки транспорта — и это видно в
панели ScriptCat.

## Состояния задачи

| Состояние | Кто ставит | Что означает |
|---|---|---|
| `Draft` | Координатор | черновик, ещё не готова к выдаче |
| `Ready` | Координатор | можно выдавать; есть Scope, Acceptance, Sequence |
| `Running` | ScriptCat | ход выдан, `Started At` записан |
| `Submitted` | ScriptCat | ответ записан в лог, PR слит |
| `Accepted` | Координатор | проверено, гейт зелёный |
| `Rework` | Координатор | причина указана в `Ответ` |
| `Blocked` | Координатор | нужен выбор из вариантов (см. `tz.md` §0) |

Переходы делает ScriptCat только между `Ready → Running → Submitted`.
Всё остальное — решение Координатора, записанное в Notion.

## Что каждый пишет

* **Координатор** — только Notion и Drive: карточки, вердикты, логи.
* **Исполнитель** — код в своей зоне, ветка, PR, отчёт в Drive.
* **Аудитор** — отчёт и вердикт; в код не пишет.
* **ScriptCat** — состояния `Running`/`Submitted`, `Branch`, `Check`, `Run ID`.

Никто не пишет в две зоны одновременно. Если нужна правка в чужой зоне — это
новая карточка, а не «быстро поправлю».

## Запуск на новый проект

1. Создать страницу проекта по образцу «Narthex — разработка платформы».
2. Создать три базы: Роли, Миссии, Запросы (схемы — в `tz.md` §3 и в самой
   странице).
3. Заполнить роли: `Agent URL` (ссылка вида
   `https://arena.ai/agent/<id>`; id — последний сегмент пути, отдельного поля
   нет), `Функция`, `Статус`, `Зона записи`, `Гейт`, `Устав`.
4. Завести миссию со `Состояние = Активна`, приложить ТЗ и `Координатор`.
5. Создать карточки задач в `Ready` (или позволить Координатору сделать это
   самому).
6. Прописать id источников данных в `_tools/ScriptCat/narthex.user.js` (`C`).
7. Установить скрипт, открыть страницу Координатора
   (`https://arena.ai/agent/<id>`) и нажать **▶ Включить** в панели Narthex
   в правом нижнем углу. Автостарт — `?cf-auto` в адресе страницы.

## Чего в системе нет намеренно

* **Нет веб-панели управления** — состояние живёт в Notion, а управление в
  ScriptCat. Отдельный дашборд означал бы второй источник правды.
* **Нет очереди с блокировками** — при числе агентов ≤ 5 достаточно Notion и
  последовательного цикла. Supabase понадобится позже (см. `connectors.md`).
* **Нет «умного» ретрая** — ошибка останавливает цикл. Молчаливый повтор
  скрывает причину и делает отладку дороже, чем простой.
