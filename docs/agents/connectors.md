# Коннекторы: что берём и почему

Список из десяти инструментов проверялся по одному вопросу: **владеет ли он
фактом, которого нет больше нигде**. Если нет — это лишняя поверхность, за
которой нужно следить.

## Решение

| Инструмент | Берём | Роль в системе |
|---|---|---|
| **Notion** | да | состояние: миссии, запросы, роли. Единственный источник правды по «что сейчас происходит» |
| **Google Drive** | да | тексты заданий и логи передач; артефакты, которые не должны попадать в git |
| **GitHub** | да | код, ветки, PR, мерж. Не коннектор, а среда исполнения |
| **Google Sheets** | позже | сводка по миссиям для человека. Read-only, пишет только синк-джоб |
| **Supabase** | нет (пока) | понадобится, когда появится очередь с блокировками и больше пяти агентов |
| **Linear** | нет | дублирует Notion; инженерные баги живут в тех же «Запросах» с меткой |
| **Gmail** | нет | уведомления идут в ntfy из ScriptCat; почта ничего не канонизирует |
| **Google Calendar** | нет | дедлайнов у агентов нет, а календарь человека — не их область |
| **Google Docs** | нет | экспорт теряет разметку (замер: −1,4 % и вся md-структура), а комментарии не нужны машинам |
| **Google Slides** | нет | презентации не являются рабочим артефактом разработки |
| **Dropbox** | нет | полный дубль Drive, но без шлюза и без истории версий в нашей схеме |

Итого три активных инструмента: **Notion + Drive + GitHub**. Остальные —
либо позже (Sheets, Supabase), либо осознанно нет.

## Почему именно так

**Notion — состояние, а не хранение.** Карточка отвечает на вопросы «кто»,
«что», «в каком статусе». Текст задания туда не кладём: он лежит в Drive, а в
карточке только `Payload Drive File ID`. Причина не в лимитах (замер показал,
что 2 000 знаков в блоке проходят), а в том, что состояние должно читаться
одним запросом и не разрастаться.

**Карточка — направление, а не инструкция.** Четыре поля отвечают за смысл:
`Намерение` — что станет возможным, `Инварианты` — что обязано остаться
правдой, `Acceptance` — команда-оракул, `Свободно` — что явно на усмотрение
исполнителя. Плюс `Scope` с путями. `Кому` и `Sequence` — не смысл, а очередь:
их ставит Координатор, и он же вправе перекроить нарезку. Поэтому карточка не
пересказывает ТЗ, а называет финиш; дорога остаётся за агентом
([`freedom.md`](./freedom.md)).

**Drive — обмен, а не канон.** Логи и тексты заданий нужны человеку и
Координатору, но не должны попадать в git (иначе репозиторий превращается в
переписку). Всё живёт в одной папке — `Arena/{logs,payloads}`; в корне Диска
система не создаёт ничего, чужой `folderId` шлюз отклоняет, запись в файл вне
`Arena/logs` запрещена. Раскладка и правила — `drive.md`.

**GitHub — исполнение.** Всё, что имеет версии, диффы и ревью, живёт только
там. Ни Notion, ни Drive не являются источником истины по коду.

## Что это значит для ScriptCat

Скрипт знает ровно три адреса: `api.notion.com`, `script.google.com` и саму
страницу Arena. Ни Linear, ни почта, ни календарь ему не нужны — поэтому в
разрешениях (`@connect`) их нет.

## Порог перехода

Добавляем инструмент только при выполнении условия:

| Инструмент | Когда включать |
|---|---|
| Sheets | когда человек захочет недельную сводку, а не чтение карточек |
| Supabase | когда задач в очереди больше 50 или агентов больше 5: нужны транзакции и аренда задач |
| Linear | никогда, пока баги движка не станут отдельным потоком с внешними исполнителями |
| Docs | если появится документ, который правят руками несколько людей |

Правило общее: новый инструмент обязан **заменить** существующий или закрыть
факт, которого нет нигде. «Добавить на всякий случай» — запрещено.
