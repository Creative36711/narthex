# Google Drive: где что лежит

Диск — не свалка и не второе хранилище. Это обменник: тексты заданий и логи
передач. Поэтому у него один корень и три правила.

## Раскладка

```
Arena/                  ← единственная папка, которую создаёт система
  Gateway               Apps Script шлюза (создаёт человек, агент не трогает)
  logs/                 лог на каждую пару Dispatch-Run
  payloads/             тексты заданий длиннее 2 000 знаков
```

В корне «Моего диска» не появляется **ничего**: ни файлов, ни папок. Если
агент создал файл в корне — это дефект, а не «мелочь»: диск перестаёт
читаться человеком с одного взгляда.

## Правила

1. **Писать только через шлюз.** `createLog` и `savePayload` сами кладут файл
   в `Arena/logs` и `Arena/payloads`. Прямой `folderId` шлюз отклоняет — это не
   ограничение удобства, а гарантия: старый агент с прямым доступом к Drive
   не может промахнуться мимо Arena.
2. **Имя файла — адрес, а не украшение.**
   - лог: `<dispatch-id>_<run-id>.md` — собирает шлюз, руками не придумывать;
   - payload: `<миссия>__<номер задачи>.md`, например `NAR-1__1.2.md`.
   Слэши и `:` в имени запрещены: шлюз заменяет их на `-`.
3. **Чужое не удалять и не переименовывать.** Чистка — решение Координатора
   после `Accepted`, а не самодеятельность исполнителя.
4. **Новый тип файлов — новая подпапка внутри Arena**, а не файл в корне.
   Порядок: сначала правится шлюз, потом появляется папка. Иначе через месяц
   в корне окажутся «отчёты», «черновики» и «на всякий случай».
5. **Drive не канон.** Код — только в git, состояние — только в Notion. Файл,
   который нужен навсегда, живёт в репозитории; Drive — для того, что не должно
   попадать в историю git.

## Кто и что пишет

| Кто | Что | Куда |
|---|---|---|
| ScriptCat | лог передачи, ответ исполнителя, причина `Rework` | `Arena/logs` через шлюз |
| Координатор | текст задания длиннее 2 000 знаков | `Arena/payloads` через `savePayload` |
| Исполнитель | ничего не создаёт: читает payload по `Payload Drive File ID` и отвечает в чат | — |
| Человек | разбор, чистка, переименование папок | вручную |

Исполнитель **не** заводит файлов «для отчёта»: отчёт — это ответ в чате и
карточка в Notion. Второй экземпляр отчёта в Drive создаёт две правды.

## Прямой доступ к Drive (коннектор)

У агента может быть включён коннектор Google Drive. Он видит весь диск, и
именно поэтому правило звучит жёстко: **создавать файлы разрешено только внутри
`Arena`**. Перед созданием проверь родителя:

```
files.list(q="name = 'Arena' and mimeType = 'application/vnd.google-apps.folder' and trashed = false")
```

Не нашёл `Arena` — не создавай её сам в другом месте и не пиши в корень:
сообщи Координатору, что раскладка нарушена.

## Старый шлюз и старая папка

Версия 1.4 создавала `Narthex — логи` в корне Диска. Версия 1.5 при первом
обращении переносит её в `Arena/logs` и переименовывает; старые файлы
сохраняются. ScriptCat при настройке проверяет версию шлюза и предупреждает,
если она ниже 1.5 — со старым шлюзом логи снова уедут в корень.

## Проверка

```bash
node _tools/ScriptCat/tests/drive-gateway-arena-smoke.mjs
```

Проба исполняет настоящий `drive-gateway.gs` на макете Apps Script и проверяет:
корень остаётся с одной папкой `Arena`, `createLog` и `savePayload` пишут
внутрь, чужой `folderId` отклоняется, старая папка переносится, `append` вне
`Arena/logs` запрещён.
