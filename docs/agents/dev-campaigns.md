# Кампании Narthex: dev-полигоны и штатный проект

Этот документ описывает каталоги в `public/campaigns/`. Два каталога
`ash-of-caerden` и `ash-of-caerden-adventure` — внутренние полигоны разработки.
`fmv-crossing` — штатный игровой проект «Перекрёсток огней», который игрок
запускает из обычного меню.

## Что видит игрок

`public/campaigns/index.json` — реестр видимых игроку проектов. Сейчас в нём
ровно одна запись: `fmv-crossing` с названием «Перекрёсток огней». В меню
можно выбрать проект и нажать «Новый забег»; для этого не нужны query-параметры
или команды в консоли.

Пустой реестр остаётся отдельным сценарием проверки, а не состоянием поставки:
`smoke:no-campaign` создаёт изолированную in-memory фикстуру `[]`, проверяет
экран и потоки пустого реестра и сверяет, что реальный `index.json` не изменился.
Браузерный `smoke:campaign-start` использует, наоборот, реальный реестр,
запускает проект через меню и сохраняет скриншоты с логом.

Каталоги, которых нет в реестре, обязаны иметь маркер `dev-fixture.json`
(старое имя `smoke-fixture.json` тоже принимается). Без маркера каталог
считается забытой кампанией, и `npm run audit:campaign-formats` падает.

## Полигоны разработки (26.10)

| Каталог | Что это | Кто создал | Используют |
|---|---|---|---|
| `ash-of-caerden` | Эталон narrative: 10 сцен, бой, диалоги, сейвы. Изображения удалены намеренно (4,4 МБ → 524 КБ) | NAR-1, полигон смоуков | оракул `cf-play check`, ~40 `*-smoke.mts`, playkit `example` |
| `ash-of-caerden-adventure` | Те же данные под видом проекта `kind: adventure`; проверяет шов «движок / пак» | NAR-2, карточка 2.3-Б | `adventure-mechanics-probe.mts`, `check:campaigns`, браузерный playthrough |

Все три каталога — **артефакты паков**: источник лежит в `packs/*/data/<имя>`,
а `public/campaigns/<имя>` публикуется командой `npm run publish:campaigns`.
Правка «только в public» запрещена: `npm run check:campaigns` сравнивает
хэши всех файлов и падает на любом расхождении.

27 изображений `ash-of-caerden` **не потеряны**: они лежат в истории git в
коммите `a3bea9a` (родитель `60a2da5`) в
`public/campaigns/ash-of-caerden/assets/img/{scenes,npc,arenas,maps}`.
Восстанавливать их в полигоны не нужно; `ash-of-caerden` остаётся внутренним
примером по D-075. Если её когда-либо отдельно готовят к витрине, изображения
берутся из истории (`git checkout a3bea9a -- …`), а не генерируются.
`smoke:no-campaign` проверяет, что у полигона нет `assets/img` и тяжёлых файлов;
проверка пустого реестра при этом изолирована и не скрывает штатный проект.

## Штатный проект

- **ID:** `fmv-crossing` (ID и строка в `packs/publications.json` сохранены).
- **Название:** «Перекрёсток огней» — без `[DEV]` в паке и публичной копии.
- **Состояние:** зарегистрирован через `campaign:release`; `dev-fixture.json`
  отсутствует в источнике и публичной копии.
- **Путь игрока:** выбрать название в обычном списке кампаний и нажать
  «Новый забег». `smoke:campaign-start` проверяет реальный `index.json`,
  переход в FMV-сцену, отсутствие query-параметров и ошибок консоли; PNG и
  лог попадают в visual artifact.

## Как переключать dev и витрину (26.10)

Игрок видит **только** записи `public/campaigns/index.json`; каталог вне
реестра не показывается ни в меню, ни в редакторе. Поэтому «скрыть в движке» —
это убрать запись из реестра и включить маркер dev, а не добавить флаг в
`campaign.json`. UI-переключателя нет и не нужно.

Один D-075 выключатель для обеих сторон:

```bash
# витрина → dev: [DEV] в заголовке, маркер, удаление из реестра, публикация копии
npm run campaign:dev -- <id>

# dev → витрина: чистое название, удаление маркера, запись в реестре, публикация
npm run campaign:release -- <id> --title "Название для игрока"
```

Для `fmv-crossing` команда релиза использует документированный `--no-audit`:
текущий `audit:campaign` не знает FMV-поля `fmv` в манифесте и сцене и
останавливается на `additional properties`. До переключения отдельно прошли
`cf-play check` и проверка ссылок на ассеты; это обход только несовместимого
legacy-аудита для этого FMV-формата, а не изменение общего аудита или гейта
dev-кампаний. Все остальные предохранители `campaign:release` продолжают
работать.

Инструмент `scripts/campaign-visibility.mts` работает через источник пака:
правит `packs/<pack>/data/<campaign>/campaign.json`, маркер
`dev-fixture.json` и `public/campaigns/index.json`, затем копирует файлы в
`public/campaigns/<campaign>`. `public/campaigns/**` руками не правится.

- **Новые внутренние кампании агента — dev по умолчанию.** В витрину — только
  по отдельной карточке и с чистым названием.
- **Перед обычным release** инструмент запускает `audit:campaign` на источнике
  и отказывается выпускать кампанию с отсутствующими изображениями.
- **Исходное название сохраняется** в маркере (`title`), поэтому `dev` →
  `release` возвращает его, а не обрезает `[DEV]` механически.
- **Оба проекта Ash остаются dev** (D-075): `ash-of-caerden` — оракул, пример
  в ките и лёгкая фикстура; `ash-of-caerden-adventure` — проект для проверки
  границы между движком и паком.
- `npm run smoke:campaign-visibility` проверяет переключение и отказ на
  временной фикстуре, не меняя реальный реестр.

Критерии витрины: `cf-play check` = 0, все ссылки на ассеты найдены,
`playthrough` проходит, `smoke:campaign-start` открывает игровую сцену,
строка проекта находится в разделе «Штатный проект», а не среди dev-полигонов.

Правила для содержимого:

- для **dev-полигона** `title` в `campaign.json` начинается с `[DEV] `, рядом
  лежит `dev-fixture.json`, а каталога нет в `index.json`;
- для **штатного проекта** заголовок предназначен игроку, запись есть в
  `index.json`, а dev-маркера нет;
- `dev-fixture.json` содержит `visibility: internal`, `reason`, `used_by`,
  `created_by` и `remove_rule`;
- `id` уникален и совпадает с именем каталога (проверяет аудит форматов);
- ID и карта `packs/publications.json` сохраняются при переключении видимости.

## Как агентам создавать свои тестовые кампании

Агенты **создают их сами** — общий механизм уже есть:

```ts
import { createCampaign, deleteCampaignFolder } from '../src/editor/newCampaign'
const id = await createCampaign('[DEV] probe: <суть>', 'NAR-3.x')
try { /* прогон */ } finally { await deleteCampaignFolder(id) }
```

Три обязательных правила:

1. **Название с префиксом `[DEV] `.** Тогда временная кампания отличается от
   пользовательской в любом журнале. `createCampaign` вернёт UUID — это
   нормально, имя каталога генерируется приложением.
2. **Если нужен каталог на диске вручную** (например, для headless-пробы без
   dev-сервера) — имя начинается с `__dev_`, например
   `public/campaigns/__dev_fmv_probe`. Каталог обязан иметь `dev-fixture.json`.
   Имена `__smoke26`, `__diff_smoke__`, `offline-test-campaign` из старых
   смоуков — наследие, новые пробы так не называть.
3. **Уборка в `finally`.** Временный каталог удаляется той же пробой, которая
   его создала; `check:dev-campaigns` не даст закоммитить `__dev_*` в git.

Долгоживущий dev-полигон создаётся только через карточку миссии: сначала
`packs/*/data/<имя>`, затем `publications.json`, затем `publish:campaigns`,
потом строка в таблице выше. Штатный проект проходит свой согласованный путь
релиза и описывается отдельно в разделе «Штатный проект».

## Страж

`npm run check:dev-campaigns` (входит в `check:contracts`) проверяет:

- все каталоги вне реестра имеют маркер и префикс `[DEV]` в `title`;
- `id` совпадает с именем каталога и уникален;
- в репозитории нет закоммиченных `__dev_*` / `__smoke*` каталогов;
- `index.json` не содержит внутренних кампаний.

Гейт остаётся общим: у `fmv-crossing` нет отдельного исключения или
захардкоженного ID. Маркеры Ash остаются в дев-состоянии, а у штатного проекта
dev-маркеров нет.

## Связанные решения

- `docs/agents/generation-quotas.md` — квота Arena на картинки и озвучку
  (10 + 10 за ход) и порядок планирования медиа.
- `docs/decisions/NAR-3.6.md` (D-075) — dev по умолчанию, один выключатель,
  квота и судьба `ash-of-caerden`.
- `docs/decisions/NAR-2.22.md` (D-072) — почему приёмка обязана открывать игру
  в настоящем браузере; именно браузер показал, что adventure-копия грузит
  narrative-сцену из-за дубля `id`.
- `docs/agents/tz-nar-3.md`, карточка 3.3 — играбельный проект в поставке и
  27 отсутствующих ассетов (намеренная фикстура).
- `scripts/visual/playthrough.mjs` — подменяет пустой реестр сетевым ответом,
  чтобы пройти игру в браузере, не трогая файлы поставки. Новый
  `smoke:campaign-start` для запуска, напротив, читает реальный реестр.
