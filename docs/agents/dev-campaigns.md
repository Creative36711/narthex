# Внутренние кампании: полигоны разработки, а не игры

Этот документ отвечает на вопрос «что это за каталоги в `public/campaigns/`,
если игроку играть нечего?». Короткий ответ: **это не кампании, это тестовые
полигоны**. Их видят смоуки и агенты, но не видит игрок.

## Почему их не видно игроку

`public/campaigns/index.json` намеренно пуст (`[]`). Это штатное состояние
поставки: игрок попадает на экран «Кампаний пока нет» и либо создаёт свою
кампанию в редакторе, либо импортирует `.narthex`. Пустой реестр проверяется
смоуком `smoke:no-campaign` — он не даст случайно «подарить» игроку полигон.

Каталоги, которых нет в реестре, обязаны иметь маркер `dev-fixture.json`
(старое имя `smoke-fixture.json` тоже принимается). Без маркера каталог
считается забытой кампанией, и `npm run audit:campaign-formats` падает.

## Реестр полигонов (26.10)

| Каталог | Что это | Кто создал | Используют |
|---|---|---|---|
| `ash-of-caerden` | Эталон narrative: 10 сцен, бой, диалоги, сейвы. Изображения удалены намеренно (4,4 МБ → 524 КБ) | NAR-1, полигон смоуков | оракул `cf-play check`, ~40 `*-smoke.mts`, playkit `example` |
| `ash-of-caerden-adventure` | Те же данные под видом проекта `kind: adventure`; проверяет шов «движок / пак» | NAR-2, карточка 2.3-Б | `adventure-mechanics-probe.mts`, `check:campaigns`, браузерный playthrough |
| `fmv-crossing` | Минимальный проект с ветвящимся видео (`fmv`) | NAR-2 | `check:campaigns`, регрессия на `nav.area` (D-072), playthrough |

Все три — **артефакты паков**: источник лежит в `packs/*/data/<имя>`, а
`public/campaigns/<имя>` публикуется командой `npm run publish:campaigns`.
Правка «только в public» запрещена: `npm run check:campaigns` сравнивает
хэши всех файлов и падает на любом расхождении.

Правила для содержимого:

- `title` в `campaign.json` начинается с `[DEV] ` — чтобы в любом списке,
  отчёте или меню было видно, что это не играбельная кампания;
- `dev-fixture.json` содержит `visibility: internal`, `reason`, `used_by`,
  `created_by` и `remove_rule`;
- `id` уникален и совпадает с именем каталога (проверяет аудит форматов);
- каталог не вносится в `index.json`.

## Как агентам создавать свои тестовые кампании

Агенты **создают их сами** — общий механизм уже есть:

```ts
import { createCampaign, deleteCampaignFolder } from '../src/editor/newCampaign'
const id = await createCampaign('[DEV] probe: <суть>', 'NAR-3.x')
try { /* прогон */ } finally { await deleteCampaignFolder(id) }
```

Три обязательных правила:

1. **Название с префиксом `[DEV] `.** Тогда временная кампания отличается от
   пользовательской в любом журнале. `createCampaign` вернёт UUID — это
   нормально, имя каталога генерируется приложением.
2. **Если нужен каталог на диске вручную** (например, для headless-пробы без
   dev-сервера) — имя начинается с `__dev_`, например
   `public/campaigns/__dev_fmv_probe`. Каталог обязан иметь `dev-fixture.json`.
   Имена `__smoke26`, `__diff_smoke__`, `offline-test-campaign` из старых
   смоуков — наследие, новые пробы так не называть.
3. **Уборка в `finally`.** Временный каталог удаляется той же пробой, которая
   его создала; `check:dev-campaigns` не даст закоммитить `__dev_*` в git.

Долгоживущий полигон создаётся только через карточку миссии: сначала
`packs/*/data/<имя>`, потом `publications.json`, потом `publish:campaigns`,
потом строка в таблице выше. Так он не станет «ничьим».

## Страж

`npm run check:dev-campaigns` (входит в `check:contracts`) проверяет:

- все каталоги вне реестра имеют маркер и префикс `[DEV]` в `title`;
- `id` совпадает с именем каталога и уникален;
- в репозитории нет закоммиченных `__dev_*` / `__smoke*` каталогов;
- `index.json` не содержит внутренних кампаний.

## Связанные решения

- `docs/decisions/NAR-2.22.md` (D-072) — почему приёмка обязана открывать игру
  в настоящем браузере; именно браузер показал, что adventure-копия грузит
  narrative-сцену из-за дубля `id`.
- `docs/agents/tz-nar-3.md`, карточка 3.3 — играбельный проект в поставке и
  27 отсутствующих ассетов (намеренная фикстура).
- `scripts/visual/playthrough.mjs` — подменяет пустой реестр сетевым ответом,
  чтобы пройти игру в браузере, не трогая файлы поставки.
