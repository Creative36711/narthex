# ТЗ Координатору: миссия NAR-1 «Ядро под паки»

Версия: **2** (2026-10-22). Транспорт: **narthex.user.js v1.3.0** (самомёрж
исполнителя, Continue-only, различение PR Merged / Closed, технический блок в
каждом сообщении). Все роли ниже — ИИ-агенты; Архитектор — тоже агент.

Документ, который Координатор получает на вход. Всё, что не описано здесь, он
решает сам и записывает решение как ADR или как строку в карточке.

## 0. Что изменилось относительно версии 1

Версия 1 была написана до того, как в репозитории навели порядок. Три его
утверждения разошлись с кодом, и по ним нельзя ставить задачи:

| Версия 1 говорила | Факт на 2026-10-22 |
|---|---|
| эталон — `01-night-pass`: 24 сцены · 10 локаций · 12 диалогов · 96 узлов | такой кампании в репозитории нет. Единственная — `public/campaigns/ash-of-caerden`: 10 · 8 · 6 · 21 |
| «вынести время, RNG, события, состояние, сейвы» | `src/core/time.ts`, `src/core/prng.ts`, `src/core/savemigrate.ts` (788 строк) уже вынесены и работают |
| `CampaignFeatures` заменяется реестром `caps` | в коде нет `CampaignFeatures`, есть `featureOn(meta, key)` в `src/shared/types.ts:605`; реестр `caps.json` есть, но кода `caps.ts` нет |

Настоящий объём фазы 1 виден по файлу: **`src/core/engine.ts` — 5146 строк,
один класс `GameEngine` и 253 метода**. Всё остальное — следствие. Задача миссии
не «дописать недостающие модули», а **разрезать этот класс**, не изменив
поведения.

## 1. Что должно получиться

1. `src/core/engine.ts` — фасад **не длиннее 600 строк**: поля класса и методы,
   которые только делегируют. Бизнес-логики в нём нет.
2. Логика разложена по `src/core/<система>.ts`; каждый модуль **не длиннее 450
   строк**.
3. Ни один модуль не импортирует `engine.ts`; в графе импортов `src/core/*` нет
   циклов — это проверяет скрипт, а не глаз.
4. Поведение не изменилось: эталон §2 и все `smoke:*` дают те же результаты,
   что до первой правки.
5. Каждая задача миссии имеет PR, смерженный **самим исполнителем** в том же
   ходе, и строку в отчёте.

Четыре критерия из пяти — про сохранность поведения. Это намеренно: фаза 1 не
добавляет возможностей, она делает расширяемость возможной. «Стало лучше, но
старая кампания не открывается» — провал миссии.

## 2. Эталон регрессии

Снят **до** первой правки, не меняется до конца миссии.

```
node public/ai/cf-play.mjs check public/campaigns/ash-of-caerden
```

| Что | Эталон на 2026-10-22 |
|---|---|
| Статика | 10 сцен · 8 локаций · 6 диалогов · 21 узел ink |
| Ошибки / предупреждения | 0 / 8 (все `flag_written_never_read`) |
| Маршруты | маршрутов нет — прогон по seed'ам |
| Матрица seed 1–5 | 5 смертей: 1 «истощение, жажда», 4 «пал в бою» |
| Покрытие | 6 из 10 сцен; не покрыты `scene_gates_guardroom`, `scene_mine_deep`, `scene_mine_entrance`, `scene_ravine_camp` |

Смерть в матрице — не баг фазы 1, а свойство кампании-примера. Если после
рефакторинга смертей стало 4 или 6 — это регрессия, а не «стало играбельнее».

Остальные проверки, которые обязаны остаться зелёными:

```
npx tsc -b
npm run check:contracts      # 20 проверок
npm run check:brand          # 463 файла, 0 находок
npm run check:version        # 0.9.0 в шести местах
все smoke:*                 # 50 из 50
```

## 3. Правила переноса

Общие для всех задач. Нарушение любого — возврат на доработку.

- **Перенос, а не переписывание.** Тело метода переезжает дословно. Меняется
  только способ обращения к состоянию (`this.state` → `ctx.state`).
- **Ничего «заодно».** Найденный по пути баг записывается в отчёт и становится
  отдельной карточкой. В этом PR он не правится.
- **Публичный API не меняется.** `GameEngine` импортируют 22 файла UI; ни один
  из них не правится в этой миссии.
- **Одно направление зависимостей.** `inventory` может знать про `needs`,
  `needs` про `inventory` — нет. Нужен обратный вызов — он идёт через `ctx`,
  а не через импорт.
- **Порог размера.** Модуль длиннее 450 строк не принимается: это значит, что
  граница проведена по живому.
- **Один PR — одна система.** Задачи 1.3–1.8 трогают `engine.ts`, поэтому
  строго последовательны. Параллелить их нельзя: конфликт в одном файле съест
  выигрыш и сломает учёт хода.

## 4. Задачи миссии

Порядок неслучаен: каждая следующая опирается на предыдущую. Дробить можно,
переставлять — только с обоснованием в карточке.

### NAR-1.1 · Карта ядра
**Роль:** Architect · **Зона:** `docs/design/core-map.md` (создать) ·
**Sequence:** 10 · **Dependency:** —

Таблица всех 253 методов `GameEngine`: имя, строк (от секции до секции),
группа (куда переедет), «зависит от нарратива» (да/нет), решение
(ядро / пак / фасад). Отдельно — поля класса: какие остаются в фасаде,
какие уезжают вместе с системой.

**Приёмка:** в таблице ровно 253 строки методов; сумма строк по группам плюс
строки шапки и экспортов равна 5146; для каждого метода указана группа.

**Проверка:** команда подсчёта приложена к карточке:
`grep -cE '^  (async )?[a-zA-Z_]+\(' src/core/engine.ts` = 253.

### NAR-1.2 · Контекст и страж графа
**Роль:** Kernel · **Зона:** `src/core/context.ts` (создать),
`src/core/engine.ts`, `scripts/core-graph.mts` (создать), `package.json`
**Sequence:** 20 · **Dependency:** NAR-1.1

`EngineCtx`: `campaign`, `state`, `rng`, `notify()`, `log()`, `audio()`.
`GameEngine` реализует интерфейс — пока без переноса логики. Скрипт
`npm run check:core-graph` строит граф импортов `src/core/*` и падает на цикле.

**Приёмка:** `check:core-graph` существует и зелёный; `tsc -b` чист; ни один
модуль не импортирует `engine.ts`; поведение не изменилось (эталон §2).

**Проверка:** `npm run check:core-graph && npx tsc -b && npm run smoke:core`.

### NAR-1.3 · Мир и сцены

### NAR-1.9 · Реестр `caps` вместо `featureOn`
**Роль:** Data/Schema · **Зона:** `src/core/caps.ts` (создать),
`src/shared/types.ts`, `docs/contracts/caps.json`, `scripts/contracts-check.mts`
**Sequence:** 90 · **Dependency:** NAR-1.3

`featureOn(meta, key)` перестаёт быть функцией с дефолтом «всё включено» и
становится обёрткой над реестром: id, статус, что включает, какая проба.
Проект со старым `features: { map: true }` читается как `caps: ["map"]`.

**Приёмка:** `caps.json` и `caps.ts` не расходятся — расхождение ловит
`check:contracts`; кампания-пример с `features` открывается; `featureOn`
объявлен в `caps.ts`, а не в `types.ts`.

**Проверка:** `npm run check:contracts && npm run smoke:no-campaign`.

### NAR-1.10 · Регрессия и отчёт
**Роль:** Runtime Auditor · **Зона:** отчёт в карточке + файл в `Arena/payloads`
**Sequence:** 100 · **Dependency:** NAR-1.9

Прогон эталона, сравнение с §2, проверка детерминизма: два запуска с одним
seed дают одинаковый хэш состояния.

**Приёмка:** каждая строка §2 совпала; расхождения объяснены построчно; в
отчёте есть команда и её вывод, а не пересказ.

**Проверка:** команды §2 + `sha256sum` двух прогонов.

## 5. Как выдавать задачи

Карточка в **Запросах** — единственный способ выдать работу. Поля, обязательные
до `Ready`:

| Поле | Требование |
|---|---|
| `Запрос` | «NAR-1.2 · Контекст и страж графа» — номер из этого ТЗ |
| `Кому` | роль из карточки; одна роль, не «кто-нибудь» |
| `Scope` | пути, которые можно менять; всё остальное — чужая зона |
| `Acceptance` | проверяемое утверждение, а не «сделать хорошо» |
| `Sequence` | 10, 20, 30… — кратно десяти, чтобы вставлять задачи между |
| `Миссия` | `NAR-1` или id миссии |
| `Dependency` | номер задачи, которая должна быть смержена первой |
| `Dispatch State` | `Ready` — только после заполнения всего выше |

Текст задания длиннее 2 000 знаков — в `Arena/payloads`, в карточке
`Payload Drive File ID`. Других файлов исполнитель не создаёт: отчёт — это
ответ в чате и карточка.

## 6. Цикл

1. Взять `Ready` с наименьшим `Sequence` и выполненными зависимостями.
2. `Running` + `Started At`.
3. Выдать: Scope + Acceptance + команда проверки. Финал хода обязателен:
   `git commit` → `git push` → `gh pr create --fill` →
   `gh pr merge --squash --delete-branch`.
4. Принять по критерию из карточки, а не по объёму диффа.
5. `Accepted` или `Rework` с точной причиной.
6. Все задачи `Accepted` → `next: done`.

## 7. Что считается провалом миссии

- Кампания-пример перестала открываться или покрытие изменилось.
- Задача `Accepted` без прогона проверки из карточки.
- PR пришлось дожимать кнопками ScriptCat.
- В `src/core/*` появился циклический импорт.
- Модуль длиннее 450 строк «потому что так удобнее».
- Координатор написал код в зоне исполнителя.
