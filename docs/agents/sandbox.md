# Песочница агента: что можно и чего нельзя

Документ для ролей и для Координатора. Составлен по фактам проверок, а не по
документации Arena.

## Первое, что нужно проверить: ветка-снимок

Arena выдаёт сессию **не от `main`**. Проверено 22 октября 2026 на двух сессиях
подряд: обе стартовали с коммита `5dfcbc3` («Связать истории с main
(снапшот 27cacd4)»), у которого **нет родителей**, то есть общей истории с
`main` нет вообще. Коммит лежит на remote как `arena/4c73faf9-chronicle-forge` —
похоже, каждая новая сессия ветвится от ветки предыдущей.

| Проверка | Команда | Результат на старте сессии |
|---|---|---|
| общая история | `git merge-base HEAD origin/main` | пусто |
| файлы main, которых нет в ветке | `comm -13 <(git ls-tree -r --name-only HEAD \| sort) <(git ls-tree -r --name-only origin/main \| sort)` | 46 |
| файлы ветки, которых нет в main | то же наоборот | 0 |
| объём расхождения | `git diff --shortstat HEAD origin/main` | 56 файлов, +27 364 строки |

Это значит: дерево сессии — **старый снимок main**, а не ветка от него. Среди
46 отсутствующих файлов — `_tools/ScriptCat/narthex.user.js`, `docs/agents/*` и
`.github/workflows/visual.yml`. Агент, который начнёт работать «как есть»,
получит три проблемы разом: не найдёт файлов, о которых говорит задание;
закоммитит в историю, которой нет в `main`; а его PR покажет удаление 27 тысяч
строк чужой работы.

### Ритуал старта (обязателен для всех, кто пишет)

```bash
git fetch origin main
git merge-base HEAD origin/main      # пусто → ты на снимке
git status --short                   # есть незапушенное — сначала сохрани
git reset --hard origin/main         # дерево как в main
git switch -c nar/<номер> origin/main
git diff --stat main                 # до работы — пусто
```

Сброс безопасен только когда своё уже запушено: `reset --hard` стирает
незакоммиченное. Порядок «сохрани → сбрось → работай» — не формальность.

### Кому это нужно

| Функция роли | Что делать |
|---|---|
| **Executor** | ритуал целиком: свежая ветка от `origin/main` до первой правки |
| **Auditor** | ничего не сбрасывать: читать `origin/main` напрямую (`git show origin/main:<путь>`), эталон — слитый PR |
| **Coordinator** | не нужно: git не его инструмент |

Этот блок ScriptCat **дописывает в каждое сообщение** автоматически
(`narthex.user.js`, `technicalInfo()`). Знание о среде не должно зависеть от
того, прочитал ли агент этот документ: оно приходит вместе с заданием.

## Можно

| Возможность | Детали |
|---|---|
| `git`, `gh` | клонирование, ветки, коммиты, пуш, PR, просмотр проверок |
| `npm`, `npx`, `node` | установка зависимостей, сборка, тесты; сеть до реестра npm работает |
| Python 3 | скрипты, обработка изображений (`cutout-chromakey.py`) |
| Запуск серверов | `start_process`, порт доступен как live-preview |
| **Браузер** | **работает** почти без настройки: одна команда + `scripts/visual/local-browser.mjs` → живой Chromium 131. Пошагово — `browser.md`; памятка — `sandbox-browser-note.md` |
| Сеть | только к разрешённым хостам: GitHub, npm, PyPI. Прочие домены недоступны |

## Нельзя или нельзя надёжно

| Ограничение | Что это значит на практике |
|---|---|
| **Обычный Playwright не ставится** | его браузер качается с закрытого домена, а `--with-deps` требует root. Обходится пакетом `@sparticuz/chromium`: рядом с бинарником лежат недостающие `libnss3/libnspr4/…`, достаточно `LD_LIBRARY_PATH`. Проверено: `Chromium 131.0.6778.0`, экраны снимаются |
| **Локальная ветка не переживает ход** | песочница пересоздаётся: незапушенное теряется. Коммит и пуш — в конце каждого шага, а не «потом» |
| **`node_modules` не сохраняется** | после пересоздания нужен `npm ci`; кэш зависимостей не переносится |
| **Файлы вне репозитория не сохраняются** | всё, что должно жить, живёт в git или во внешнем сервисе |
| **Нет доступа к чужим репозиториям на запись** | пуш только в свой репозиторий и свою ветку |
| **Секреты не передаются через чат** | токены и ключи — только в переменных окружения песочницы или в настройках ScriptCat |
| **Долгие процессы не гарантированы** | сервер может быть остановлен между ходами; состояние — в файлах, а не в памяти процесса |

## Правила, вытекающие из ограничений

1. **Push или потеря.** Работа без пуша живёт до конца хода. Это не совет, а
   свойство среды.
2. **Сначала сверься с main.** Checkout — снимок без общей истории. Правка,
   начатая без `git reset --hard origin/main`, уедет в мёртвую ветку.
3. **Инструменты — в репозитории.** Если скрипт нужен в следующем ходе, он
   коммитится, а не лежит в `/tmp`.
4. **Проверка — командой, а не словами.** `npm test`, `npx tsc`, `node
   scripts/...` — то, что можно повторить. «Я посмотрел, красиво» не является
   результатом; результатом является отчёт скрипта или PNG из CI.
5. **Глаза — это браузер, и он здесь есть.** Утверждать «браузера в песочнице
   нет» запрещено (`check:browser-gate` ловит такие фразы). Приёмка без
   браузерного прохождения (`npm run playthrough`) недействительна — D-072.
   Видишь проблему — снимаешь PNG и смотришь на него
   (`browser.md`, `node scripts/visual/shot.mjs <url> out/x.png`). Утверждать
   «выглядит нормально», не открыв картинку, нельзя. CI (`visual.yml`) —
   независимый свидетель и история прогонов, а не замена локальному браузеру.
6. **Никаких секретов в коде и в промптах.** Ключ шлюза и токен Notion живут в
   ScriptCat, у агента их нет и быть не должно.

## Что делать, если чего-то не хватает

Не «обходить» ограничение, а зафиксировать его в отчёте одной строкой:
«требуется X, недоступно, потому что Y». Координатор решает, менять ли план.
Молчаливая подмена (например, «вместо браузера посмотрел в код и решил, что
работает») — худший вариант: она выглядит как успех.
