# Песочница агента: что можно и чего нельзя

Документ для ролей и для Координатора. Составлен по фактам проверок, а не по
документации Arena.

## Можно

| Возможность | Детали |
|---|---|
| `git`, `gh` | клонирование, ветки, коммиты, пуш, PR, просмотр проверок |
| `npm`, `npx`, `node` | установка зависимостей, сборка, тесты; сеть до реестра npm работает |
| Python 3 | скрипты, обработка изображений (`cutout-chromakey.py`) |
| Запуск серверов | `start_process`, порт доступен как live-preview |
| Установка браузера | `playwright-core` и `@sparticuz/chromium` ставятся через npm — но **запустить их нельзя** (см. ниже) |
| Сеть | только к разрешённым хостам: GitHub, npm, PyPI. Прочие домены недоступны |

## Нельзя или нельзя надёжно

| Ограничение | Что это значит на практике |
|---|---|
| **Браузер не запускается** | проверено: `chromium.launch()` выходит с кодом 127 — нет `libnspr4/libnss3/libnssutil3`; `apt-get` недоступен (не root, пустые списки), системного браузера и кэша Playwright нет. Пиксели снимаются в GitHub Actions, а не в песочнице |
| **Локальная ветка не переживает ход** | песочница пересоздаётся: незапушенное теряется. Коммит и пуш — в конце каждого шага, а не «потом» |
| **`node_modules` не сохраняется** | после пересоздания нужен `npm ci`; кэш зависимостей не переносится |
| **Файлы вне репозитория не сохраняются** | всё, что должно жить, живёт в git или во внешнем сервисе |
| **Нет доступа к чужим репозиториям на запись** | пуш только в свой репозиторий и свою ветку |
| **Секреты не передаются через чат** | токены и ключи — только в переменных окружения песочницы или в настройках ScriptCat |
| **Долгие процессы не гарантированы** | сервер может быть остановлен между ходами; состояние — в файлах, а не в памяти процесса |

## Правила, вытекающие из ограничений

1. **Push или потеря.** Работа без пуша живёт до конца хода. Это не совет, а
   свойство среды.
2. **Инструменты — в репозитории.** Если скрипт нужен в следующем ходе, он
   коммитится, а не лежит в `/tmp`.
3. **Проверка — командой, а не словами.** `npm test`, `npx tsc`, `node
   scripts/...` — то, что можно повторить. «Я посмотрел, красиво» не является
   результатом; результатом является отчёт скрипта или PNG из CI.
4. **Глаза — через CI.** Визуальная проверка делится на три слоя
   (`visual.md`): математика и структура — локально и в песочнице, пиксели —
   в `visual.yml`. Агент скачивает артефакт
   (`gh run download <run-id> -n visual-report -D out/visual`) и читает PNG как
   изображение. Утверждать «выглядит нормально», не открыв картинку, нельзя.
5. **Никаких секретов в коде и в промптах.** Ключ шлюза и токен Notion живут в
   ScriptCat, у агента их нет и быть не должно.

## Что делать, если чего-то не хватает

Не «обходить» ограничение, а зафиксировать его в отчёте одной строкой:
«требуется X, недоступно, потому что Y». Координатор решает, менять ли план.
Молчаливая подмена (например, «вместо браузера посмотрел в код и решил, что
работает») — худший вариант: она выглядит как успех.
