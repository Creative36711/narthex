# ТЗ Координатору: миссия NAR-4 «Второй рантайм — настоящий realtime»

Версия: **1.0** (2026-10-27). Предыдущая миссия NAR-3 закрыта с вердиктом
«принять»: фаза 2 закрыта, обе демо-кампании проходятся в браузере до финала
(Ash — 8 шагов, Adventure — 12 шагов, 0 pageerror).

**Это направление, а не инструкция.** Как именно — решают Координатор и
исполнители. Пробелы закрываются по лестнице [`freedom.md`](./freedom.md) §4.
Вопрос Мастеру — строка в базе «Вопросы» с вариантом по умолчанию, цикл не
встаёт.

## 0. Место в плане

Фаза **3 из десяти** ([`phases.md`](../phases.md)). Закрыты: фаза 0 (контракты),
фаза 1 (ядро), фаза 2 (шов «движок / пак»). Эта миссия открывает фазу 3 и
закрывает её — третьей миссии «на добивку» быть не должно: критерий
фиксируется до первой карточки и не ослабляется.

Смысл фазы: отделить **что происходит** от **когда считается**. Сейчас всё
считается по ходам: игрок сделал шаг — движок посчитал. Второй рантайм — это
непрерывное время, фиксированный шаг, ввод по нажатию. Ядро при этом не должно
знать, чей цикл крутится.

## 1. Оракул миссии (фиксируется до первой карточки)

Оракул — это **критерий**, а не имя скрипта. Критерий не меняется никем до
конца миссии; ослабить его можно только ADR `proposed` с ответом Мастера.

1. **Детерминизм внутри рантайма.** Один и тот же seed даёт один и тот же хэш
   состояния — на обоих эталонных проектах, на любом числе прогонов.
2. **Детерминизм между средами.** Один и тот же код симуляции даёт одинаковый
   результат в браузере и в `cf-play` (сравниваются хэши, а не «на глаз»).
3. **Нет ветвлений по рантайму.** `cf-play` проходит оба проекта одним путём
   кода: `if (это realtime)` в обвязке нет.
4. **Регрессия пошагового мира не сдвинулась.** Эталон `cf-play check` обоих
   паков фазы 2 — те же числа, что до миссии; браузерный экзамен `playthrough:exam`
   по-прежнему `check = 0`.
5. **Бюджет кадра** измерен и записан числом в отчёт (медиана и p95 на
   эталонном realtime-проекте, машина указана).
6. **Долг D-01 оплачен:** `npm run lint` — 0 ошибок.

Инструменты, которые обязаны быть зелёными (существующие команды плюс то, что
вводит карточка 4.1):

```bash
npx tsc -b
npm run check:contracts              # включает check:browser-gate
npm run check:brand
npm run check:version
npm run check:core-graph
npm run check:module-size
npm run smoke:core
npm run lint                         # D-01: 0 ошибок
npm run build
npm run playthrough:exam             # браузер: пошаговый мир не сломан
npm run check:mission                # переписан под NAR-4 (D-05): два рантайма
```

Скрипт детерминизма (`scripts/check-determinism.mts`, npm-алиас
`check:determinism`) создаётся карточкой 4.1 вместе с подкомандой `cf-play` для
обоих циклов. С момента приёмки 4.1 критерий из пунктов 1–2 заморожен: скрипт
менять можно, критерий — нет.

## 2. Что построить

### Карточка 4.1 — Интерфейс исполнителя и инструмент проверки

- Ввести интерфейс исполнителя: `step(dt)`, приём ввода, пауза,
  детерминизм по seed. Границы — [`platform.md`](../platform.md) и ADR 0002
  (два рантайма — два проекта, смешивать нельзя).
- Перевести `turn` на этот интерфейс **без изменения поведения**: эталон
  `cf-play check` обоих паков и `playthrough:exam` дают те же числа, что до
  карточки.
- `cf-play` получает прогон обоих циклов headless; `scripts/check-determinism.mts`
  делает двойной прогон и сравнивает хэши.
- **Acceptance:** `check:determinism` rc 0 на эталоне `turn`; числа эталона
  совпадают с базой миссии; критерий оракула записан в отчёте.

### Карточка 4.2 — Цикл `realtime`

- Фиксированный шаг симуляции, накопление времени, интерполяция отрисовки,
  бюджет кадра (без «прыжков» при просадке).
- Ввод по нажатию: клавиши и указатель, без реакции «на кадр» в логике.
- **Acceptance:** эталонный realtime-проект идёт 60 секунд игрового времени без
  пропусков шага; хэш состояния стабилен по seed; бюджет кадра записан числом.

### Карточка 4.3 — Эталонный realtime-проект

- Минимальный, но настоящий: движение, столкновение, простой триггер
  (например «вошёл в зону → открылась дверь»).
- Проект лежит в `public/` по правилам [`dev-campaigns.md`](./dev-campaigns.md),
  если он полигон, или в реестре витрины, если он играбельный. Решение —
  ADR, как в NAR-3.3.
- **Acceptance:** проект открывается в браузере, играется руками, доходит до
  триггера; `playthrough` (или его новый маршрут) проходит его в CI.

### Карточка 4.4 — Равенство сред

- Один и тот же seed → одинаковый хэш в браузере и в `cf-play`. Расхождение —
  дефект, а не «плавающая точка».
- Если расхождение неизбежно (порядок обхода, время, платформенная математика)
  — сначала ADR с объяснением и способом фиксации, потом код.
- **Acceptance:** отчёт с парами «seed → хэш браузер / хэш cf-play» на 5 seed'ах,
  0 расхождений.

### Карточка 4.5 — `check:mission` под NAR-4 (D-05)

- Единый экзамен миссии проверяет **оба** рантайма и обе среды.
- **Acceptance:** `npm run check:mission` rc 0; удалённых проверок 0; счётчики
  проверок в отчёте до и после.

### Карточка 4.6 — Гигиена: lint (D-01) и бюджет кадра в отчёте

- `npm run lint` → 0 ошибок (5 сейчас). Ни одно правило не отключается, ни один
  файл не исключается: правится код.
- В `_tools/reports/NAR-4.md` — числа: медиана и p95 кадра, машина, число
  прогнанных seed'ов.
- **Acceptance:** `npm run lint` rc 0; отчёт с числами и ссылками на PR.

## 3. Что запрещено

- Смешивать рантаймы в одном проекте (ADR 0002): один проект — один цикл.
- Сдавать «почти детерминировано»: плавающий хэш — красный результат, а не
  «особенность окружения».
- Маскировать недетерминизм округлением, сортировкой «на глаз» или повтором
  прогона «пока не совпадёт» — только ADR и явное правило.
- Ослаблять оракул, повышать пороги гейтов, удалять проверки ради зелени.
- Начинать фазу 4 до закрытия этой миссии.
- Писать «браузера в песочнице нет»: страж `check:browser-gate` краснеет.

## 4. Готово, когда

- Два эталонных проекта — по одному на рантайм — детерминированы по seed.
- Один и тот же код симуляции даёт одинаковый результат в браузере и в
  `cf-play`.
- `cf-play` проходит оба проекта без ветвлений «если это realtime».
- Бюджет кадра зафиксирован в отчёте числом.
- `npm run lint` — 0 ошибок (D-01), `check:mission` проверяет оба рантайма (D-05).
- В Notion: миссия NAR-4 «Завершена», вердикт с ссылками на PR и отчёт; в
  [`phases.md`](../phases.md) фаза 3 помечена закрытой с датой.
