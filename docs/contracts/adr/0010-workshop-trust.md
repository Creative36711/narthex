# ADR 0010. Мастерская: файлы у автора, доверие у платформы

Дата: 2026-10-23
Статус: принято

## Контекст

Платформа не хранит игры и ассеты: они могут весить гигабайты, а хостинг
превращает её в модератора чужого контента. При этом пользователю нужны
рейтинг, отзывы и число скачиваний. На платформе, где игры массово делает ИИ,
дефицит — не количество, а качество: голоса легко накрутить, проверку — нет.

## Решение

**Запись каталога — манифест, не архив.**

```json
{ "id": "…", "title": "…", "author": "…", "kind": "…",
  "manifest_url": "…", "manifest_sha256": "…", "size_estimate": 0,
  "license": "CC-BY-4.0", "check_report_sha256": "…" }
```

**Рейтинг — по проверяемости и завершённости:** `check = 0`, пройденная матрица
seed'ов, заявленный объём, реальная длина. Голоса — вторичны.

**Счётчики и отзывы — на сервере.** Это единственная серверная часть и
единственный случай, когда платформа что-то хранит; файлов и ассетов там нет.
Сервер обязан быть заменяемым (интерфейс `CatalogSource`).

**Доверие:** подпись манифеста, зеркала, «источник недоступен» как штатный
статус, бейдж «здесь кастомный код».

**Происхождение:** лицензия, отпечаток содержимого, детект производных
(«совпадает с X на 87 %»). Код локально закрыть нельзя, поэтому защищаем
авторство, а не секретность.

## Последствия

**Положительные.** Платформа остаётся дешёвой; каталог можно поднять без
хостинга; рейтинг отличает законченные проекты от пустых.

**Отрицательные.** Метрики приблизительны (скачивания считаются с клиента),
а мёртвые ссылки — штатная ситуация. Обе проблемы честно показываются
пользователю, а не скрываются.

## Что стало невозможным

- Хостить файлы игр и ассеты на платформе.
- Ранжировать только по голосам.
- Продавать игры внутри платформы без сервера (см. `vision.md` §8).
- Скрыть от игрока наличие кастомного кода.
