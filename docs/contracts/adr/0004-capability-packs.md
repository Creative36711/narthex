# ADR 0004. Пак как единица расширения

Дата: 2026-10-22
Статус: принято

## Контекст

Платформа должна расширяться направлениями, не превращаясь в один большой
движок с флагами. Флаги плохи тем, что каждый новый жанр добавляет `if` в
общий код, и через год невозможно сказать, что от чего зависит.

## Решение

Единица расширения — **пак**. Пак приносит направление целиком и обязан иметь
четыре части:

1. **Схема** (`provides.schema`) — типы данных пака.
2. **Панели** (`provides.panels`) — вкладки студии с указанием слота и условий
   показа по возможностям.
3. **Валидаторы** (`provides.validators`) — статические правила с уровнем
   `error`/`warn`; те же, что видит `check`.
4. **Пробы** (`provides.probes`) — динамические сценарии с бюджетом времени и
   списком проверяемых утверждений.

Нет хотя бы одной части — пак не принимается. Пак без проб нельзя проверить,
пак без валидаторов нельзя принять в ревью, пак без схемы нельзя сохранить.

Правила зависимостей:

- Пак знает ядро и не знает другие паки напрямую. Всё, что нужно, берётся
  через `requires.caps` — возможности, а не импорты.
- Циклические зависимости паков запрещены.
- Студия не знает конкретных паков: она читает их манифесты и регистрирует
  панели. Ни одного `if (pack === 'narrative')` в студии.

## Манифест

`pack.json`, схема `../pack.schema.json`. Обязательные поля: `id`, `title`,
`version`, `runtime`, `provides`, `saves`, `requires`.

`caps` в манифесте обязан совпадать с реестром один-к-одному: пак объявляет
ровно те возможности, которые записаны за ним в `caps.json`. Расхождение —
ошибка сборки, а не предупреждение.

## Гейты пака

| Гейт | Условие |
|---|---|
| G0. Реестр | возможности добавлены в `caps.json` со статусом `planned` |
| G1. Манифест | проходит схему и семантику `check:contracts` |
| G2. Схема | проект с этим паком открывается в студии и сохраняется без потерь |
| G3. Валидаторы | на эталонном проекте нет `error` |
| G4. Пробы | все пробы зелёные в бюджете времени |
| G5. Регрессия | фикстуры остальных паков не сломаны |
| G6. Статус | `experimental` → `stable` только после двух релизов без ломающих правок |

## Последствия

**Положительные.** Направление добавляется каталогом, а не правкой ядра.
Студия остаётся одной. Проверка едина: `check` знает про паки ровно столько,
сколько написано в их манифестах.

**Отрицательные.** Больше формальностей на старте: чтобы сделать маленькую
фичу, нужен манифест и проба. Ответ: это цена того, что через год в проекте
будет понятно, кто за что отвечает. Для одноразовых экспериментов есть
`experimental`-возможности, но не «пак без манифеста».

## Что стало невозможным

- Нельзя добавить поведение «просто в ядро»: если оно относится к
  направлению — это пак, если ко всем — это ADR и общий контракт.
- Нельзя выпустить пак без проб, даже срочно.
- Нельзя двум пакам писать в одно пространство сейвов (`saves.namespace`).
