# ADR 0005: Версионирование движка

**Статус:** принято
**Дата:** 2026-10-22
**Контекст:** ребрендинг `Chronicle Forge` → `Narthex`, версия `0.8.0` не
отражала состояние проекта, а вопрос «кто двигает номер» был открыт.

## Проблема

Номер версии жил в четырёх файлах (`package.json`, `package-lock.json`,
`src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`) и ещё в двух гайдах в виде
примеров. Обновляли его руками и по-разному. Следствия:

- ИИ-агенты копировали `"engine_version": "0.8.0"` из примеров гайда и
  объявляли `min_engine`, которого нет.
- Никто не знал, что означает `0.8.0`: 25 раундов фидбека, 48 смоуков и
  платформенные контракты умещались в одну цифру.
- `0.8.0 → 0.9.0` можно было сделать только «на память», без проверки, что
  все места согласованы.

## Решение

### 1. Версия — обещание совместимости, а не счётчик прогресса

Номер отвечает ровно на один вопрос: **можно ли старую кампанию открыть этим
движком без правок**. Прогресс по проекту отслеживается миссиями в Notion и
`CHANGELOG.md`, а не цифрой.

| Событие | Что делаем с номером |
| --- | --- |
| Новая механика, старые кампании работают как работали | minor |
| Ломающее изменение: формат пакета, контракт манифеста, поведение, на которое кампании рассчитывали | major (в 0.x — minor) |
| Только исправления | patch |

Пре-релизные суффиксы (`-rc.1`) не используем: сборки не публикуются в
магазины, а тег в git делает то же самое без неоднозначности.

### 2. Четыре номера — разные вещи, путать нельзя

Уже разделены в `src/shared/versions.ts`:

| Номер | Что означает | Кто меняет |
| --- | --- | --- |
| `PACKAGE_FORMAT` / `OLDEST_PACKAGE_FORMAT` | версия формата пакета кампании | человек, вместе с ADR 0003 |
| `ENGINE_VERSION` | версия движка = `package.json.version` | только `npm run version:bump` |
| `SAVE_VERSION` | версия формата сохранений | человек, при изменении сохранений |
| `version` кампании | версия самой кампании | автор кампании (ИИ-агент) |

`min_engine` в манифесте кампании — требование кампании к движку, а не версия
движка. Агент пишет там ту версию, чьи возможности реально использует.

### 3. Номер двигает человек на релизе, ИИ — только предлагает

ИИ-цикл **не** имеет права менять версию. Причина простая: bump — это
обещание совместимости, а его даёт тот, кто отвечает за выпуск. Если бы номер
двигался на каждом PR, он превратился бы в счётчик коммитов и перестал что-либо
означать; а `min_engine` у кампаний начал бы требовать несуществующих движков.

Разделение:

- **ИИ-агенты** в своих отчётах и PR пишут предложение: `version: minor` /
  `version: major` + одна строка обоснования (что ломается или что добавилось).
  Это часть шаблона PR.
- **Человек** (Master) на релизе запускает `npm run version:bump <level>` —
  один раз, механически, во всех файлах сразу.
- **Build/Release** (роль ИИ) проверяет `npm run check:version` и падает, если
  номера разошлись, но сам номер не выбирает.

### 4. Один источник, проверка в CI

- `package.json.version` — единственный ручной источник.
- `tauri.conf.json` больше не дублирует номер: `"version": "../package.json"`
  (Tauri 2 читает версию из файла).
- `Cargo.toml`, гайд и `CHANGELOG.md` правятся скриптом `scripts/version.mts`.
- `npm run check:version` — согласованность всех мест; входит в релизный
  чек-лист рядом с `check:brand` и `check:contracts`.

## Текущий номер: 0.9.0

Кандидаты были такие:

| Вариант | За | Против |
| --- | --- | --- |
| оставить `0.8.0` | ничего не ломается | врёт: с 0.8.0 сменились имя, идентификаторы, форматы; агенты копируют старый номер |
| `1.0.0` | заявка «мы готовы» | по обещанию пользователя 1.0 = движок для любых жанров (3D, RTS); реализован только narrative |
| `0.9.0` | minor в 0.x = допустимое ломающее изменение по semver; честно отражает «платформа заявлена, движок один» | — |

Принято `0.9.0`.

**Почему не 1.0.0.** Платформа объявляет пять направлений
(`narrative`, `state-ui`, `grid-strategy`, `endless-2d`, `spatial-3d`), но
реализовано одно. Поставить 1.0.0 сейчас — значит пообещать, что игру любого
жанра на этом движке сделать можно; её сделать нельзя. 1.0.0 — это версия, в
которой работают как минимум все пять направлений и есть настоящие игры,
сделанные на них людьми, а не только примеры.

## Последствия

- Ветка `0.x` остаётся: ломающие изменения допустимы в minor, но каждое
  фиксируется в `CHANGELOG.md` строкой «Совместимость».
- Ребрендинг в 0.9.0 сломал идентификаторы (ключи `localStorage`, расширения,
  `app.narthex.desktop`) без миграции — допустимо единственный раз, потому что
  установок и игроков нет. Следующее такое изменение потребует миграции.
- Первое переименование идентификаторов **после** 0.9.0 обязано получить
  код миграции, иначе это нарушение собственного обещания.
