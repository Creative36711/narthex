# ADR 0011. Кит — среда, а не книга

Дата: 2026-10-23
Статус: принято

## Контекст

Чемодан `__chronicle_ai__` задуман как документация для агента, но работает
как книга, которую надо постоянно переписывать. Сейчас в нём гайд на 268 КБ и
схема на 327 КБ — около 150 тысяч токенов. Агент не держит это в контексте,
читает наугад и угадывает; каждый релиз движка делает часть текста ложью, а
`smoke:guide` ловит только расхождения формулировок.

## Решение

Кит перестаёт быть источником правды и становится средой:

| Инструмент | Заменяет |
|---|---|
| `cf-play explain <код>` | раздел гайда «почему это ошибка» |
| `cf-play schema <тип>` | половину схемы: поля одного типа |
| `cf-play example <механика>` | пример из гайда, но исполняемый |
| `cf-play shoot` | «посмотри глазами»: детерминированные кадры сцены |
| `kit doctor` | «какая версия кита и совпадает ли она с движком» |

Правила:

1. Гайд ≤ 10 % исходного объёма и только «почему»; «какое поле» отвечает
   `schema`/`explain`.
2. Корпус `examples/<механика>/` гоняется в CI; пример без прогона не
   считается примером.
3. Ошибка без пути, минимального фикса и якоря — дефект валидатора.
4. Мажорное расхождение кита с движком — отказ работать, а не тихий неверный
   совет.
5. MCP-сервер — тонкая обёртка над тем же CLI, не второй продукт.

## Последствия

**Положительные.** Документация перестаёт отставать, потому что её основной
объём генерируется и проверяется. Агент получает ответ на вопрос, а не тысячу
страниц.

**Отрицательные.** Нужно поддерживать `explain`, `example` и `shoot` как код, а
не как текст. Это работа роли Tools, зато она измерима: `check` на эталоне.

## Что стало невозможным

- Считать гайд единственным источником правды.
- Выпустить кит без `KIT.json` и проверки версии.
- Добавить ошибку валидатора без объяснения и минимального фикса.
