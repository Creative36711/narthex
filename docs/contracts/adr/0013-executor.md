# ADR 0013. Исполнитель: один контракт на два цикла

Дата: 2026-10-27
Статус: принято

## Контекст

Сейчас цикла как отдельной сущности нет: `GameEngine` — это и состояние, и
правила, и цикл одновременно. Игрок нажал — движок посчитал. Второй рантайм
(ADR 0002) требует непрерывного времени: фиксированный шаг, накопление,
интерполяция. Соблазн — форкнуть движок и получить две несвязанные системы,
которые разойдутся через месяц.

Нужна граница, которую можно проверить: ядро не должно знать, чей цикл
крутится, а `cf-play` — ветвиться «если это realtime».

## Решение

**`Executor` — единственное, что ядро знает о цикле.**

```ts
step(dt, input) → { changed, clock }
pause() / resume()
setSeed(seed)
fingerprint()
```

Правила контракта:

1. **Время приходит шагом, в миллисекундах игрового времени.** Пошаговый цикл
   переводит мс в тики внутри себя; непрерывный — копит остаток и делает
   фиксированные шаги. Ядро не спрашивает, сколько сейчас времени у машины.
2. **Ввод — события, а не состояние клавиш.** `ExecutorInput` описывает
   нажатие с моментом внутри шага. Зажатая клавиша — это повторные события,
   которые создаёт цикл, а не поле «клавиша нажата».
3. **Пауза — часть контракта.** Пока `paused`, `step` не двигает состояние и
   возвращает `changed: false`. Это нужно и для меню, и для `cf-play`.
4. **Зерно — строка.** `setSeed` пересоздаёт ГПСЧ; после этого прогон
   воспроизводим. `GameState.seed` уже хранит зерно забега, второго поля нет.
5. **Отпечаток — число, а не «на глаз».** `fingerprint()` возвращает
   канонический отпечаток состояния (`src/core/fingerprint.ts`): ключи в
   порядке, нечисла помечены, 64-битный FNV-1a в hex. Сравнение сред — это
   сравнение строк.
6. **Ядро не импортирует реализации.** `executor.ts` не знает слов `turn` и
   `realtime`; реализации подключаются снаружи через `ExecutorFactory`.

## Последствия

**Положительные.** Второй цикл добавляется файлом, а не форком. `cf-play`
гоняет оба цикла одним кодом. Детерминизм проверяется сравнением отпечатков
(карточки 4.4 и 4.6), а не повторным проходом «пока не совпадёт».

**Отрицательные и как их держим.**

- Контракт шире, чем нужно сегодняшнему `turn`: `clock` и `dt` в мс пошаговому
  циклу не нужны. Ответ: цена — два поля, выгода — один код на два цикла;
  лишние члены контракта не обязаны использоваться.
- Отпечаток зависит от формы состояния. Ответ: форма состояния — часть сейва,
  её изменение и так требует миграции (`savemigrate.ts`).
- 64-битный хэш не криптографический. Ответ: он ловит расхождение кода, а не
  подделку; для подписи сейвов он не используется.

## Что стало невозможным

- Цикл, который сам решает, когда считать состояние, минуя `step`.
- Ветвление ядра по виду цикла (`if (realtime)`) — реализация подключается
  снаружи, а не распознаётся внутри.
- Изменение состояния из представления: у представления нет `step`.
- Сравнение сред «на глаз»: у состояния есть отпечаток, и расхождение — дефект.
- Два цикла в одном проекте (подтверждает ADR 0002): фабрика создаёт один.
