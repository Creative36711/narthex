# Формат проекта v2

Статус: **draft**. Предлагаемое правило заморозки описано в [ADR 0015](./adr/0015-format-freeze.md)
(сейчас `proposed`) и ещё не действует. `accepted` ставится только по карточке
NAR-5.10 после зелёного доказательства на третьем жанре: пак и игра-пример
должны пройти проверки. До принятия допускаются правки по ADR; после принятия
изменение смысла существующих полей требует миграции, а новые поля допускаются
только необязательными и аддитивными. Правки от 2026-10-23: режимы и версии возможностей, языки, код в
швах (ADR 0006, 0008, 0009). Все три — **необязательные поля**: проект без них
читается как раньше.

## 1. Зачем новый формат

Сегодня проект — это `campaign.json` с параметрами кампании и `manifest.json`
со списками файлов. Этого достаточно, пока движок один и направление одно. С
платформой нужно пять вещей, которых в текущем формате нет:

1. **Тип проекта** — от него зависит, какие панели студии открыть.
2. **Список возможностей** — что именно проект включает, а не «всё сразу».
3. **Режим каждой возможности** — работает система, работает код или
   выключено с сохранением данных.
4. **Языки проекта** — на чём написан исходник и какие переводы есть.
5. **Требования к движку** — с какой версией проект проверялся.

При этом ломать существующие пакеты нельзя: все внешние проекты и эталонный
полигон должны читаться без ручной правки.

## 2. Файл

Имя: `project.json` в корне проекта. Рядом — `manifest.json` со списком файлов.

```json
{
  "format": 2,
  "id": "river-of-ash",
  "title": "Река пепла",
  "kind": "narrative",
  "caps": ["narrative", "scenes", "dialogue", "map", "inventory", "combat"],
  "cap_options": {
    "combat": { "version": 1 }
  },
  "languages": ["ru", "en"],
  "default_language": "ru",
  "locales": "locales",
  "engine": { "min": "0.9.0", "tested": "0.9.3" },
  "entry": "world.json",
  "manifest": "manifest.json",
  "license": "CC-BY-4.0",
  "authors": [{ "name": "Мастер" }]
}
```

## 3. Поля

| Поле | Обяз. | Тип | Смысл и ограничения |
|---|---|---|---|
| `format` | да | `2` | версия формата; `1` — старый пакет без этого файла |
| `id` | да | slug | `^[a-z0-9][a-z0-9-]{1,63}$`; не меняется после публикации |
| `title` | нет | строка ≤120 | отображается в студии и мастерской |
| `kind` | да | enum | тип проекта, обязан быть в `caps.json` |
| `caps` | да | массив slug | включённые возможности, только `stable`/`experimental` |
| `cap_options` | нет | объект | режим и версия поведения по возможности; ключи обязаны входить в `caps` |
| `languages` | нет | массив тегов | языки проекта; `default_language` обязан входить в список |
| `default_language` | нет | тег | язык исходного текста и фолбэка |
| `locales` | нет | путь | каталог переводов, по умолчанию `locales` |
| `code` | нет | объект | точка входа кода и песочница; обязателен, если есть режим `code` |
| `engine.min` | да | semver | ниже — движок обязан отказаться с понятной ошибкой |
| `engine.tested` | нет | semver | версия, на которой проект реально прогонялся |
| `entry` | да | путь | файл состояния мира относительно корня |
| `manifest` | нет | путь | по умолчанию `manifest.json` |
| `license` | нет | SPDX или `custom:…` | нужна мастерской, не движку |
| `authors` | нет | массив `{name, url?}` | — |
| `homepage` | нет | строка | страница проекта у автора |
| `x-*` | нет | любой | расширения вендора; ядро их сохраняет и не толкует |

Схема: `project.schema.json`. Поля с `x-` — единственное место, где допустимы
незнакомые ключи: всё остальное, чего нет в таблице, считается опечаткой и
отклоняется.

## 4. Правила, которые не выражаются схемой

Их проверяет `npm run check:contracts`:

1. `kind` существует в реестре, и все его `requires` входят в `caps`.
2. Каждая возможность в `caps` существует и имеет статус `stable` или
   `experimental`.
3. Все возможности проекта принадлежат пакам одного рантайма. Смешение `turn`
   и `realtime` — ошибка, а не «гибрид».
4. `engine.tested` не ниже `engine.min`.
5. `default_language` входит в `languages` (если заданы оба).
6. Ключи `cap_options` входят в `caps`, режим — `core`/`code`/`off`,
   версия — целое ≥ 1.
7. Если хотя бы одна возможность в режиме `code`, объект `code` обязателен и
   содержит `entry`. Обратное не требуется: `code` без режима `code` допустим —
   это `view`-расширения.
8. Возможность, которую требует `kind`, нельзя перевести в `off`: проект
   потеряет собственный жанр.

## 5. Режимы и версии возможностей

`cap_options` отвечает на два вопроса: **как** работает возможность и **по
каким правилам**.

| Режим | Что работает | Формы в студии | Проверка |
|---|---|---|---|
| `core` (по умолчанию) | система ядра | есть | полная |
| `code` | код проекта в объявленном шве | скрыты, вместо них дерево и Monaco | `check` для `sim`, кадры для `view` |
| `off` | ничего; данные остаются | только чтение с предупреждением | данные валидируются, поведение — нет |

Правила:

- режим задаётся **по возможности**, а не на проект целиком: `combat` может
  быть `code`, `quests` — `off`, остальное — `core`;
- `off` не удаляет данные: выключить систему можно, не потеряв сцены и
  реплики; включить обратно — тоже;
- `version` — версия **поведения**, а не данных. Движок держит старую и новую
  реализацию параллельно на время депрекации (ADR 0009); по умолчанию —
  последняя стабильная;
- повышение `version` — осознанный шаг автора или миграция из студии, а не
  автоматическое «догони движок».

Швы объявляет пак в `provides.seams` (см. `pack.schema.json`). Проект не может
подключить код к шву, которого нет в манифесте пака.

## 6. Языки и локализация

- `default_language` — язык исходного текста. Если он не задан, проект
  считается одноязычным, и это допустимо.
- `languages` — какие переводы проект объявляет (не обязательно все готовы).
- `locales` — каталог; файл перевода называется `<language>.json`.

Формат файла перевода:

```json
{
  "schema": 1,
  "language": "de",
  "source_language": "ru",
  "strings": {
    "scene_outpost/npc_brann/greeting/2": "Der Weg ist frei."
  },
  "sources": {
    "scene_outpost/npc_brann/greeting/2": "9f2c1a7d"
  }
}
```

Правила:

1. Ключ строки — **стабильный ID по структуре**, а не текст и не хэш текста:
   `scene_outpost/npc_brann/greeting/2`. Иначе каждая правка реплики обнуляет
   перевод.
2. `sources[key]` — хэш исходной строки, по которой сделан перевод. Исходник
   изменился — перевод помечается устаревшим, но не удаляется.
3. У каждой строки есть источник, у каждого источника — строка.
4. Язык в файле совпадает с именем файла и входит в `languages`.
5. Инлайн-текст остаётся валидным: проект без `locales` ничего не переводит.

Перевод может быть машинным — это помечается бейджем в мастерской и не
считается вычитанным (ADR 0008).

## 7. Код в швах

```json
{
  "cap_options": { "combat": { "mode": "code", "version": 2 } },
  "code": { "entry": "code/combat.js", "sandbox": "worker" }
}
```

- `entry` — точка входа относительно корня проекта; один файл, дальше —
  обычные модули рядом.
- `sandbox` — пока единственное значение `worker`: отдельный воркер без DOM и
  сети, права выдаются явно (`render`, `audio`, `input`, `state`).
- Код не может менять форму сохранения без миграции, объявленной проектом.
- Проект с кодом помечается в мастерской бейджем; это не запрет, а честность.

## 8. Миграция с формата 1

Старый пакет — это `campaign.json` без `project.json`. Правила чтения:

| Что | Откуда берётся |
|---|---|
| `format` | `1` |
| `id` | `campaign.id` |
| `title` | `campaign.title` |
| `kind` | всегда `narrative` |
| `caps` | из `campaign.features`, где значение не `false`; плюс базовые `narrative`, `scenes`, `dialogue` |
| `cap_options` | все возможности в `core`, версия — текущая |
| `languages` | `[ru]`, если текст на русском; иначе не задаётся |
| `default_language` | не задаётся |
| `engine.min` | `campaign.min_engine`, если есть, иначе версия движка на момент чтения |
| `entry` | `world.json` |
| `manifest` | `manifest.json` |

Миграция **не перезаписывает файлы**. `campaign.json` остаётся, `project.json`
появляется при первом сохранении из студии. Так старый проект можно открыть,
не рискуя потерять данные, и откатиться к прежнему поведению.

Обратная совместимость действует бессрочно до отдельного ADR о прекращении
поддержки формата 1. Прекращение возможно только вместе с мигратором, а не
вместе с сообщением «ваш проект устарел».

## 9. Версионирование

- Правка, которая только добавляет необязательное поле, — минорная, версия
  формата не меняется.
- Правка, меняющая смысл существующего поля, — новый формат (3), старый
  читатель обязан отказаться, а не догадываться.
- Правка, которая делает проект несовместимым с движком, фиксируется в
  `engine.min`, а не в формате.
- Версия поведения возможности — это `cap_options[cap].version`, а не версия
  формата: правила могут меняться, не ломая форму.

## 10. Ошибки

Формулировки одинаковы в студии, в `check` и в плеере:

| Ситуация | Сообщение |
|---|---|
| `format` новее движка | «Проект собран для формата N; эта версия понимает до M» |
| `engine.min` выше движка | «Нужен движок X или новее, сейчас Y» |
| неизвестный `kind` | «Тип проекта `kind` не установлен: нужен пак `pack`» |
| неизвестная возможность | «Возможность `cap` не установлена» |
| смешение рантаймов | «Проект смешивает пошаговый и realtime-рантаймы» |
| язык по умолчанию вне списка | «Язык `de` не входит в список языков проекта» |
| настройка неизвестной возможности | «Настройка `cap` не относится ни к одной включённой возможности» |
| режим `code` без кода | «Возможность `cap` работает в режиме code, но `code.entry` не задан» |
| выключена обязательная возможность | «Возможность `cap` выключена, но тип `kind` её требует» |

Ни одна из этих ошибок не должна приводить к «пустому экрану»: проект
открывается только для чтения с объяснением, что нужно поставить.

## 11. Заморозка

Предложенное правило заморозки для `project.json` и `pack.json` описано в
[ADR 0015](./adr/0015-format-freeze.md); его текущий статус — `proposed`.
Пока ADR не принят, заморозка не действует. В этой карточке статус `accepted`
не устанавливается: его ставит только карточка NAR-5.10 после зелёного
доказательства на третьем жанре — пак и игра-пример должны пройти проверки.

После принятия ADR 0015 существующие поля сохраняют имена, структуру, типы,
обязательность, ограничения и смысл; новые поля могут добавляться только
необязательными и аддитивными, так чтобы старые валидные файлы оставались
валидными. Изменение смысла существующего поля требует явной миграции по
[ADR 0003](./adr/0003-project-format-v2.md), а не незаметного изменения v2.
Полная таблица замораживаемых и добавляемых полей находится в ADR 0015. Любое
будущее изменение схемы и проверки проходит обычный цикл изменения контракта;
этот предложенный ADR схемы и проверки не меняет.
