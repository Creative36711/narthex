# 7. Работа с ИИ-агентом: чемодан, промпты, петля правок

Мы принципиально не встраиваем собственный ИИ в Chronicle Forge: мастер
пользуется своим ИИ-сервисом (Claude, ChatGPT, любой другой чат с
поддержкой файлов). Зато всё для комфортного обмена заранее подготовлено —
эта глава про рабочий порядок.

## 7.1. Что такое «чемодан для ИИ-агента»

**Файл → Чемодан для ИИ-агента** — один клик скачивает архив с пятью
файлами:

- `campaign.json` — вся ваша кампания одним документом (монолит);
- `campaign-guide.md` — системный гайд по движку и формату (первым разделом в него уже встроены правила `НАЧНИ С ЭТОГО`, двухфазный протокол и формат обратной связи);
- `campaign.schema.json` — формальная схема полей той же версии движка;
- `design-template.md` — пустой бланк дизайн-документа кампании для Фазы 1;
- `НАЧНИ_С_ЭТОГО.txt` — сопроводительный текст: пошаговая инструкция и правила для тех, кто предпочитает вставлять первое сообщение вручную.

Поскольку полный текст инструкции встроен первым разделом в `campaign-guide.md` из единого источника, сценарий «загрузил файлы чемодана в чат → написал "сделай кампанию по брифу"» работает сразу, без ручной копипасты промпта. Поэтому в самом архиве достаточно отдать всё как есть: `НАЧНИ_С_ЭТОГО.txt` оставлен намеренно — это копия того же протокола из единого источника (`scripts/gen-schema.mts`), она ничего не стоит в поддержке и нужна тем, кто привык вставлять первое сообщение текстом. Сценарий «отдал агенту весь архив zip целиком» работает и без него, потому что инструкция уже внутри гайда.

## 7.2. Двухфазный протокол: сначала дизайн-документ, потом монолит

При создании новой кампании с нуля работа делится на две фазы (протокол зашит в начало гайда и бланк `design-template.md`):

- **Фаза 1 (Дизайн-документ человеческим языком):** прежде чем генерировать тысячестрочный JSON, агент составляет компактный план по шаблону `design-template.md`:
  - паспорт кампании (название, жанр, тон, объём) и устройство мира;
  - главы (напрямую ложатся в `meta.chapters`), список сцен с ролью каждой и таблицу НПС/пропов;
  - квесты, концовки, чек-лист задействованных механик из гайда и рамки баланса.
- **Фаза 2 (Монолит по утверждённому документу):** когда мастер отвечает «ок» (или вносит правки в план), агент собирает полный `campaign.json` строго по согласованному дизайн-документу, после чего включается обычная петля проверки.

| Задача | Как спросить ИИ | Что вернуть |
| --- | --- | --- |
| **Новая кампания с нуля** | «сделай кампанию по такому брифу» (Фаза 1 → «ок» → Фаза 2) | сначала дизайн-документ, затем монолит |
| **Исправить сцену/диалог** | передайте монолит + «поправь диалог кузнеца» | новый монолит или сам файл диалога |
| **Дописать контент** | «добавь новый квест на лечебную траву, вот бриф» | монолит с добавлением; проверка кампании покажет огрехи |
| **Проверить кампанию** | «найди швы по этой кампании» (монолит) | список предупреждений; латать удобнее в редакторе |
| **Миграция старого** | «переведи кампанию версии X на новый формат по гайду» | монолит в новом формате |

ИИ надёжнее всего в механической работе: типовые сцены, однотипные
существа, выверка форматов. Сюжетный замысел пусть остаётся у мастера.

## 7.3. Петля обратной связи

Рабочий цикл «попросил — получил — проверил — попросил поправить» — это норма:

1. ИИ даёт монолит → **Файл → Импорт из JSON** (текст или файл).
2. **Инструменты → Проверить кампанию** — короткий список замечаний или
   пусто.
3. Список замечаний копируется отсюда прямо агенту (кнопка «Скопировать отчёт для ИИ») —
   и следующий ответ агента их уже учтёт.

Такой «читающий цикл» в среднем даёт кампанию без единого замечания за
2–3 итерации.

## 7.4. Правила, которые соблюдает ИИ

В первый раздел `campaign-guide.md` и в `НАЧНИ_С_ЭТОГО.txt` входят строгие формулы-ограничения:

- формат только по гайду и схеме;
- id — латиницей, тексты — русские;
- не переименовывать и не переиспользовать id;
- ссылки — только на существующие id;
- не выдумывать новые поля и типы;
- в диалогах переход `stay` ставить только на вариантах ответа (`choices[].goto`), а не на узлах;
- говорящие объекты оформлять как стационарных `npc`, а осматриваемые пропы без реплик — как `item` в слотах сцены;
- использовать встроенные art-примитивы; ссылки на картинки — только если
  их добавит мастер.

## 7.5. Конвенция `cf-feedback`: заметки ИИ для разработчиков

Если во время сборки кампании агенту не хватило какого-то эффекта, условия или пояснения в гайде, он не выдумывает несуществующие поля, а в конце ответа оставляет блок `cf-feedback` с JSON-массивом заметок (с полями `id`, `kind`, `detail`, `workaround`, `severity`).

Мастер может по желанию открыть **Инструменты → Заметки ИИ для разработчиков**, вставить туда этот блок и нажать **«Открыть issue на GitHub»** — откроется предзаполненная страница создания задачи с аккуратной таблицей замечаний. Никакой фоновой телеметрии в редакторе нет: отправка полностью добровольна и происходит в один клик.

## 7.6. ИИ нужно НЕ знать

Движок сам делает за агента всю механику загрузки файлов, миграции формата
и проверки: ИИ должен лишь аккуратно вернуть обновлённый монолит.
Согласовывать версии с ИИ не нужно: мигратор кампании справляется сам.
