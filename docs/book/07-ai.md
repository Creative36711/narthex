# 7. Работа с ИИ-агентом: чемодан, промпты, петля правок

Мы принципиально не встраиваем собственный ИИ в Chronicle Forge: мастер
пользуется своим ИИ-сервисом (Claude, ChatGPT, любой другой чат с
поддержкой файлов). Зато всё для комфортного обмена заранее подготовлено —
эта глава про рабочий порядок.

## 7.1. Что такое «чемодан для ИИ-агента»

**Файл → Чемодан для ИИ-агента** — один клик скачивает архив ровно из
четырёх файлов:

- `campaign.json` — вся ваша кампания одним документом (монолит);
- `campaign-guide.md` — системный гайд по движку и формату; читает ИИ как
  спецификацию, и начинается он с двух разделов:
  - §0 — пошаговая инструкция и правила, которые ИИ обязан соблюдать;
  - §0б — бланк гейм-дизайнерского документа (тот же текст, что
    `design-template.md`);
- `campaign.schema.json` — формальная схема полей той же версии движка;
- `design-template.md` — бланк гейм-дизайнерского документа отдельным
  файлом, чтобы удобнее было читать.

Дальше — **одно действие: перетащите архив в чат целиком**. Распаковывать и
выбирать файлы руками не нужно — инструкция для агента лежит первым
разделом гайда внутри архива. Если ваш чат не принимает архивы, в окне
после скачивания есть кнопка «Скопировать инструкцию для ИИ»: вставьте её
текст первым сообщением, а следом отправьте файлы из архива.

Когда агент закончит, он вернёт вам `campaign.json` — импортируйте его
через **Файл → Импорт из JSON**, и кампания готова к проверке и плейтесту.

## 7.2. Дизайн-документ: сначала замысел, потом код

Основной режим работы — через **гейм-дизайнерский документ кампании**.
Агент ведёт его сам (поле `design_doc` в `campaign.json`): пишет замысел
человеческим языком — паспорт, завязку, главы, сцены, персонажей, квесты,
рамки баланса и журнал решений — и обновляет документ на каждой итерации.

Мастер читает документ в разделе **«Проект → Дизайн-документ»**: копирует
 себе, правит руками, отвечает «ок» или «поправь вот это». Только после
«ок» агент наполняет кампанию по документу. Порядок итерации такой:

1. агент обновил документ → мастер прочитал и сказал «ок» или прислал правку;
2. агент привёл кампанию в соответствие с документом;
3. «Инструменты → Проверить кампанию» → отчёт агенту → следующая итерация
   снова начинается с документа.

Пустой документ — брак итерации; проверка кампании предупредит, если
документ вообще не описывает ваши сцены.

## 7.3. Рабочие режимы

| Задача | Как спросить ИИ | Что вернуть |
| --- | --- | --- |
| **Исправить сцену/диалог** | передайте монолит + «поправь диалог кузнеца» | новый монолит или сам файл диалога |
| **Дописать контент** | «добавь новый квест на лечебную траву, вот бриф» | монолит с добавлением; проверка кампании покажет огрехи |
| **Проверить кампанию** | «найди швы по этой кампании» (монолит) | список предупреждений; латать удобнее в редакторе |
| **Новая кампания с нуля** | «сделай кампанию по такому брифу» | сначала дизайн-документ на «ок», потом монолит |
| **Миграция старого** | «переведи кампанию версии X на новый формат по гайду» | монолит в новом формате |

ИИ надёжнее всего в механической работе: типовые сцены, однотипные
существа, выверка форматов. Сюжетный замысел пусть остаётся у мастера —
через дизайн-документ вы держите его под контролем.

## 7.4. Петля обратной связи

Рабочий цикл «попросил — получил — проверил — попросил поправить» — это норма:

0. Дизайн-документ обновлён → **«Проект → Дизайн-документ»** → «ок» или
   правка (этот шаг есть у новой кампании и у каждой существующей).
1. ИИ даёт монолит → **Файл → Импорт из JSON** (текст или файл).
2. **Инструменты → Проверить кампанию** — короткий список замечаний или
   пусто.
3. Список замечаний копируется отсюда прямо агенту (кнопка «Скопировать отчёт для ИИ») —
   и следующий ответ агента их уже учтёт.

Такой «читающий цикл» в среднем даёт кампанию без единого замечания за
2–3 итерации.

## 7.5. Правила, которые должен соблюдать ИИ

Инструкция для агента — **§0 гайда, первого раздела `campaign-guide.md`
внутри чемодана**: скиньте архив целиком, и агент прочитает её сам. Отдельного
файла с инструкцией нет; для чатов без архивов её можно вставить текстом —
кнопка «Скопировать инструкцию для ИИ» в окне после скачивания. В инструкции
формулы-ограничения:

- сначала дизайн-документ на «ок» мастера, потом кампания; на каждой
  итерации документ обновляется раньше кода;
- формат только по гайду и схеме;
- id — латиницей, тексты — русские;
- не переименовывать и не переиспользовать id;
- ссылки — только на существующие id;
- не выдумывать новые поля и типы;
- использовать встроенные art-примитивы; ссылки на картинки — только если
  их добавит мастер.

## 7.6. ИИ нужно НЕ знать

Движок сам делает за агента всю механику загрузки файлов, миграции формата
и проверки: ИИ должен лишь аккуратно вернуть обновлённый монолит.
Согласовывать версии с ИИ не нужно: мигратор кампании справляется сам.
