# 6. Технические вопросы: файлы, экспорт, проверка кампании, версии

Глава про «инструментарий»: где лежит кампания, в каких видах её можно
передать и проверить, что случится с сохранениями игроков при новой версии.

## 6.1. Где лежит кампания и что внутри

Ваша кампания — папка файлов. Вам точно нужно это знать, когда делается
бэкап/дележка работы, или когда вы просите ИИ «поправить один файл».

Состав папки кампании:

- `campaign.json` — все настройки кампании (реестры, правила бросков,
  тема, появления, механика).
- `world.json` — география: регионы, локации, карта.
- `manifest.json` — список всех «модулей» (сцены, существа, правила,
  арены и т. д.).
- `scenes/`, `entities/`, `rules/`, `quests/`, `arenas/`, `cutscenes/`,
  `codex/`, `recipes/`, `rules/encounters.json` — сам контент;
- `dialogues/*.ink` — источники диалогов;
- `assets/` — файлы изображений, звука и пр.

Файлы предназначены для правки из редактора. Вручную их можно
изучать и бэкапить, но перемещать/переименовывать не стоит — пути
жёстко закреплены в манифесте.

## 6.2. Экспорт и импорт — все виды обмена

Встаёт свет в верхнем меню **Файл**:

| Действие | Формат | Для чего |
| --- | --- | --- |
| Экспорт `.chronicle` | zip-пакет со всеми файлами (включая файлы `assets/`) | автономная передача целиком (друзьям, на свой другой компьютер, публикация) |
| Экспорт JSON | один большой **монолитный JSON** всей кампании | удобно «загрузить ИИ чтоб поправил», сравнить две версии, сложить в git внешнего хранилища |
| Чемодан для ИИ-агента | zip: монолит + гайд формата + схема + инструкция для чата | обмен с внешним ИИ (глава [«Работа с ИИ»](07-ai.md)) |
| Импорт `.chronicle` | восстановление из zip-пакета | принять кампанию от знакомого |
| Импорт из JSON | текст или файл монолита | вернуть правки от ИИ, из чата, из бэкапа |

**Галочка экспорта .chronicle** «вшить внешние ссылки» забирает картинки
и звуки с внешних URL прямо в пакет — офлайн-безбажная кампания.

## 6.3. Проверка кампании

**Инструменты → Проверить кампанию**:

- все ссылки между объектами кампании валидны (сцены смотрят на существующие
  локации, предметы — на изображения, диалоги — на NPC);
- синхронность реестров (валюты корректно ссылаются на монеты, id
  не повторяются);
- полностью заполненные обязательные поля формата.

Отчёт можно скопировать в чат ИИ-агенту (см. главу «Работа с ИИ») — он
«починит» файлы кампании сам.

## 6.4. Плейтест и отладка

Кнопка **Плейтест** запускает забег поверх редактора текущим состоянием
документа:

- изменений в файлах, кандидатов на сохранение — не нужно;
- сейва плейтеста не появляется, он изолирован от «взрослого» сейва;
- панель отладки позволяет быстро прыгать по сценам, менять флаги,
  добавлять предметы, настраивать настройки времени.

## 6.5. Совместимость версий и сохранения игроков

Каждая кампания имеет **версию** (счётчик мастера). Сохранения игрока
привязаны к паре «кампания — версия»:

- при совпадении версии файла кампании и версии сейва — чтение прямое;
- при расхождении — движок запускает миграцию старого сейва на новую
  версию кампании (запишет, что именно поменял, и сделает бэкап у игрока);
- если кампания слишком новая — старую кампанию предложат скачать.

Обновление версии поля «Версия» — каждый существующий выпуск. Журнал
изменений держите в той же вкладке — поможет и игрокам, и вам самим.

Замена id (переименование) остаётся под запретом до конца времени: «устаревший»
объект удалите и создайте новый под другим id — миграция тогда ничего не
рискует развернуть первому забегу.

## 6.6. Резервные копии

Повторяем: так как кампания — папка файлов, резервное копирование — это
просто скопирование папки (или экспорт `.chronicle`). Бэкапы старых сейвов
игрока движок создаёт автоматически на устройстве игрока при миграции.
