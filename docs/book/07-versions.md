# 7. Версии кампании и сохранения игроков

Кампания живёт долго: вы правите сюжет, добавляете локации, балансируете бой.
Игроки в это время носят в сохранениях своих героев. Глава объясняет, как
публиковать обновления так, чтобы чужие забеги не пропадали.

## Три номера, которые вы видите

| Поле | Что значит | Кто заполняет |
| --- | --- | --- |
| **Версия кампании** | Номер выпуска вашей кампании (`1.4.2`) | вы (редактор предлагает) |
| **Мин. движок** | Самая старая версия Chronicle Forge, на которой кампания работает правильно | вы, обычно оставляете предложенную |
| **Сохранения поддерживаются с версии** | Граница, до которой сохранения ещё открываются | редактор при публикации |

Версия движка и формат пакета — не ваши поля: их задаёт Chronicle Forge, они
подставляются сами.

Раздел: **«Кампания» → вкладка «Версии»**.

## Публикация обновления

1. Откройте «Кампания → Версии» и нажмите **«Проверить совместимость и
   опубликовать версию»**.
2. Редактор сравнит пакет с предыдущей публикацией и покажет отчёт: что
   добавлено, что изменено, что удалено, и какие из изменений ломают
   сохранения.
3. Подтвердите номер версии (предложенный можно поправить) и напишите «что
   изменилось» — этот текст увидит игрок.
4. Редактор запишет `compat.json` и обновит `campaign.json`. Сохраните
   кампанию и экспортируйте `.chronicle` как обычно.

### Что считается ломающим изменением

| Изменение | Последствие для сохранений |
| --- | --- |
| Новое название, описание, картинка, музыка | никаких |
| Новый персонаж, предмет, локация, навык, статус | никаких |
| Правка баланса: урон, убывание потребности, цены, бюджеты создания героя | никаких (движок предупредит игрока) |
| Удалён персонаж, предмет, локация, сцена, стадия квеста, потребность, навык, правило | **ломают**: сохранения до новой версии не откроются |

Игрок всё равно не теряет забег молча: движок чинит сохранение и показывает
список («Из инвентаря убрано: «Ржавый ключ» — этих предметов больше нет в
кампании»). Но если удалено что-то важное для сюжета, правильнее поднять
границу сохранений и дать игрокам доиграть на прежней версии.

## Почему нельзя переименовывать id

Id объекта — это адрес: на него ссылаются сцены, правила, диалоги, квесты и
сохранения игроков. Переименование равносильно удалению старого объекта и
созданию нового, поэтому редактор его не выполняет: в «Расширенном JSON»
правка `id` отклоняется с объяснением.

Нужно «переименовать» — создайте новый объект, перенесите содержимое, удалите
старый. Это честное ломающее изменение: контракт покажет его игроку.

## Что видит игрок

- **Обновился движок** — сохранение переносится автоматически; если что-то
  поменялось в формате, игрок увидит отчёт перед продолжением забега.
- **Обновилась кампания, сохранение подходит** — кнопка «Продолжить» на месте,
  при необходимости показывается список почищенного.
- **Сохранение слишком старое** — игрок видит причину и кнопки «Начать новый
  забег» / «Сохранить файл сейва». **Сохранение при этом не удаляется**: оно
  откроется, если вернуться к прежней версии кампании.

## Хорошие привычки автора

1. Публикуйте обновления через вкладку «Версии», а не правкой номера вручную.
2. Не занижайте и не завышайте границу сохранений «на всякий случай» — и то, и
   другое стоит игрокам забегов.
3. Пишите в «что изменилось» то, что заметит игрок: «добавлен перевал и три
   встречи», а не «рефакторинг правил».
4. Крупные правки сначала проверьте в консоли:
   `npx tsx scripts/compat-report.mts <старая-версия> <новая-версия>`.
5. Не переиспользуйте id удалённых объектов — ни в этой версии, ни в
   следующих.
