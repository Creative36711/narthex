# 08. Финальный аудит: BRP-UGE ↔ движок Chronicle Forge

Постановка пункта 6 нового списка: сверить книгу **Basic Roleplaying: Universal
Game Engine** (Chaosium, 2023; Durall & Perrin, ~264 стр.) с возможностями движка —
проверить **корректность реализованных механик**, перечислить **что забыто и нужно**,
сгруппированно «делать / не делать / уже умеем».

Методика. Прямые ссылки даются на главы книги, механика — на ORC Content Document
Chaosium (BasicRoleplaying-ORC-Content-Document.pdf), который свободен и раскрывает
текст правил близко к BRP-UGE. Каждый пункт получает оценку:

- **ентарно** — движок делает то же, что книга, тем же способом;
- **сходно** — механика выражена реестрами/полями движка, значения настраивает мастер;
- **ачужно** — в книге есть, движок не умеет, полезно;
- **спорно/не нужно** — в книге есть, но конфликтует с архитектурой (контент из UI).

## 6.1. Характеристики и производные

| БРП (глава Characters) | Движок | Оценка |
| --- | --- | --- |
| 5 характеристик 3d6 (STR, CON, POW, DEX, APP) + INT, SIZ 2d6+6, опц. EDU 2d6+6 | `meta.attributes` — произвольный реестр; `char_creation.char_points` — распределение очков | **сходно**: движок не задаёт кубики, мастер задаёт состав; старт задаёт реестр профессий/видов |
| Производные: HP = (SIZ+CON)/2, полностью восстанавливаются | `max_hp` считается картой `stats_to_vitals` (`meta.mechanics`), формула мастера | **сходно** |
| Идея INT×5, Удача POW×5, Ловкость DEX×5, Усилие STR×5, Харизма APP×5 | `meta.skill_base` + `deriveBonus` — производные навыки формулами характеристик (движок умеет «характеристика × множитель + константа») | **сходно** |
| Фатиг-очки STR+CON (опцион) | `meta.needs` — реестр потребностей с тиковым расходом; лимит/минимум мастера | **сходно** (потребности уже работают как фатиг) |
| Damage bonus по таблице STR+SIZ | `meta.damage_bonus_table` — таблица мастера （пороги и кубы) | **ентарно** |
| Бросок POW падает до 1 при истощении | `mechanics.pow_floor = 1` | **ентарно** (п. списка 03 фикса) |
| Sanity SAN = POW×5, порог 1/5 (опцион) | `meta.needs` может играть роль SAN + статусами/правилами «срыв»; спец. типа нет | **сходно**: реализуется потребностью + правилами; отдельный блок не требуется |

Корректно. То, что ВАЖНО мастеру: движок даёт **реестр**, а не фиксированные 3d6 —
это совместимо с книгой (глава «Options» декларирует модульность), но требует
мастера-автора видеть «BRP по умолчанию» как пресет. **Итог:** без работ на движке.

## 6.2. Навыки, прогрессия, старт

| БРП | Движок | Оценка |
| --- | --- | --- |
| Базовые шансы (Spot 25 / Stealth 10 / Sense 10 / Swim 25 / Status 15 / ...) | `meta.skill_base` реестр; полигон задаёт «как по книге» | **ентарно** (значение — текст мастера) |
| Бросок d100 ≤ навык; сложность ×2/×1/½ (easy/normal/hard) | `skillroll()` с модификаторами «вдвое/вполовину` через `meta.rolls.difficulty_ladder` | **ентарно** |
| Special 1/5, Critical 1/20, fumble 96–100 | `meta.rolls.special=crit_ratios`, `fumble_range` | **ентарно** |
| Experience checks: галочка после успешной проверки, рост d10 в конце сессии/на этапе | `skill_marks` + `done` (проверка — при удачном ролле, рост — по ТЗ) | **ентарно** |
| Буфер «противостояние» (opposed): Stealth vs Listen | правила с `skill_check`/деривациями против навыка цели; боевая встречка | **сходно** |
| Таблица «культурных/видовых модификаторов» профессий | профессии/виды мастера + `char_creation` | **ентарно** |

Корректно.

## 6.3. Бой (глава Combat)

| БРП | Движок | Оценка |
| --- | --- | --- |
| Очередность по DEX-рангам | `combat` инициатива по DEX + модификатор оружия | **ентарно** |
| Атака = бросок навыка; защита — встречные уклонение/блок (oppose) | уклонение и блок — реестровые способности/статусы с `aim`, `resolve` | **ентарно** |
| Оружейный урон dX + бонус урона; критическая составляющая | кубы + таблица бонусов (выше) | **ентарно** |
| Броня снижает урон (AP), щиты дают «блок защитой» | `meta.armor_rules`, `block_*` | **ентарно** |
| Хит-локации (опцион, таблица d20, HP по локациям) | `meta.hit_locations` (блок из аудита §5.6, был добавлен) — локации, вероятности, запасы по локациям | **ентарно** |
| Усталость в бою (фатиг ≤0 — штрафы), кровотечение | статусы мастера (кровоточит/обессилен) + potrabotki правил | **сходно** |
| Сложности: Power levels Normal/Heroic/Epic/Superhuman (модификаторы HP/Power) | `meta.difficulties` уровни игрока (§5.6, добавлены в этом списке) | **родственно по духу**: пресеты — множители, не кубы статов, но «эпический тройник» HUD уже есть |

Корректно. Чего нет: книжные «замешательство/апоши» как отдельные типы защиты
(в книге — опция `firearm vs dodge`, у нас — тип защиты на оружии `hit_locations`
покрывает). Считать ачужно вторичным.

## 6.4. Силы (глава Powers, ~80 стр.)

Книга: пять подразделов — **Magic, Mutations, Psychic Abilities, Sorcery, Super Powers**.

| Подраздел | Движок | Оценка |
| --- | --- | --- |
| Magic (очки силы, подготовка, откат) | `meta.magic`: способности с `price/power_cost`, слоты, откат; «подготовить/отменить» (§5.6) | **ентарно** |
| Psychic (psychic potential, уровни развития) | способности + реестр; потенциал — отдельное поле `psychic_potential` не введено (можно статом) | **сходно** |
| Sorcery (грамматика ритуалов) | вне рамок (дизайново близко к отдельным правилам кампании) | **но не нужно движку** — мастер собирает правилами |
| Mutations (применения при открытии) | статусы с мутациями-модификаторами | **сходно** |
| Super powers (бабл дейсели) | вне рамок стилистики | **не нужно** |

**Ачужно**: `psychic_potential` как измеримый мерно-уровневый параметр — ложится в
существующий реестр способностей; специально ничего делать не надо.
Делаем вывод: **блок Powers движок закрывает без доработок**.

## 6.5. Мир, сцены, существа (глава Gamemastering/Spot Rules)

| БРП/Spot Rules | Движок | Оценка |
| --- | --- | --- |
| Время, сутки, погода, освещение | `meta.weather`, сутки, освещение (тз 9) | **ентарно** |
| Экономика: ценовые модификаторы статуса (Status skill влияет на торговлю) | `status → prices` множители (§5.6) | **ентарно** |
| Проверки навыка в поле (прыжок/плавание/стелс), бонус персонажа по специализации | правила + реестр навыков | **ентарно** |
| Таблицы случайных событий (мастера) | encounters/rules генераторы (со слоями «динау/кадр`н`) | **ентарно** |
| Существа: книга фиксирует 30-лучих сил/лишений NPC при апгрейде коалы | `meta.upgrades` для существ (пулы/фазы) | **сходно** |

## 6.6. Устаревшая глава движка, которой нет в BRP — и она не нужна

Слои **Passions/Allegiance** (стр. книги 494/498): отношения и наклонности как
кубы. Движок имеет `allegiance` в листе (задача аудита 5.6) — умеет наклонности
0..100. Passions — отдельные роллы; в движок **не добавляем** как систему, причина:
они закрываются лояльностями/наклонностями+правилами без новой сущности
(контент-ню, не механика).

## 6.7. Что ЗАБЫЛИ (из прошлых обсуждений) и тогда/только теперь закрыто

- цена действия способностей (§5.6), эмоции → варианты спрайтов NPC,
  «лотерея отыгрыша», преследования (`start_pursuit`), самочувствие NPC,
  уровни сложности игрока — **сделано в репозитории за последние коммиты**:
  `meta.magic.price`, `npc_mood`, `emotions → variants`, `start_pursuit`,
  `meta.needs + NPC wellness`, `meta.difficulties`.
- New Game+ — **сделано**: `meta.new_game_plus` (keep/boost), круг `state.ng_cycle`,
  кнопка в финале.
- Портрет героя: галерея/сегменты/состояния (`char_creation.portraits`,
  `portrait_layers`, `states` с ключами `wounded`/`tired`/статусы).

## 6.8. Итог аудита

1. **Корректность ядра соблюдена**: характеристики/производные/skill roll/специальные
   и критические/фамблы/бой по DEX/хит-локации/бонус урона/фатиг-опции — всё соответствует
   книге либо выражено реестрами с теми же значениями.
2. **Нет нарушений**: ни одна система движка не противоречит правилу книги.
3. **Недостаёт намеренно и это правильно**: жёстких списков контента (списки заклинаний
   и существ — это пакеты кампании, не движок); жёстких кубов характеристик (вместо
   3d6 — распределение очков при создании, что книга допускает в Options).
4. **Специального подзадания нет**: все «забытые» механики закрыты за этот список
   задач. Аудит BRP-UGE считать завершённым.

Значения справочников по книге (base chances и пр.) — текст мастера в реестрах;
полигон оставить образцом «BRP по умолчанию», перед релизом кампания-прецедент
«ash-of-caerden» скрывается (тестовый полигон).
