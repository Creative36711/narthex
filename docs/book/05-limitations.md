# 5. Чего в движке пока нет

Аудит механик. Источники: код движка (`src/core/`, `src/shared/types.ts`,
`src/shared/compat.ts`) и книга **Basic Roleplaying: Universal Game Engine**
(Chaosium, ORC) — сверены главы 1–11.

Правило простое: **помеченное «нет» не обещайте игрокам как встроенную
механику.** Обход, собранный из сцен, правил и эффектов, — авторское решение
мастера, а не подсистема движка: опишите его игрокам до начала забега и
держите условия в самой кампании.

Статусы в таблицах:

| Статус | Значение |
| --- | --- |
| **нет** | подсистемы не существует, собрать «руками» можно только имитацию |
| **частично** | есть деталь механизма, но не вся механика |
| **обход** | встроенного нет, но имитация получается убедительной |
| **есть** | реализовано, ищите в справочнике механик (глава 4) |

## 5.2 Генерация характеристик кубиками

**Статус: внедрено.** Мастер может включить на экране создания героя базовый
метод BRP — броски вместо покупки за бюджет. Конфиг целиком мастерский:

| Поле | Смысл | Умолчание |
| --- | --- | --- |
| `char_creation.roll.notation` | формула по умолчанию | `3d6` |
| `char_creation.roll.per_stat` | переопределение на характеристику: `{"INT": "2d6+6", "SIZ": "2d6+6"}` | нет |
| `char_creation.roll.arrays` | сколько наборов бросить сразу, игрок берёт один | 1 |
| `char_creation.roll.rerolls` | перебросы отдельных характеристик (по одной) | 0 |
| `char_creation.roll.redistribute` | очков докрутки сверх выброшенного набора (BRP — до 3) | 0 |

Детали реализации:

- брошенные значения прижимаются к рамкам `stat_limits` мастера;
- в режиме кубиков бюджет `total_points` больше не валидируется, а
  распределение характеристик у происхождений (`profession.stats`)
  игнорируется — бонусы навыков и снаряжение происхождений работают;
- бросок делается на экране (не привязан к seed забега), производные HP/MP
  пересчитываются при применении выбора;
- выбор из нескольких наборов (`arrays`) — практика «брось три — возьми
  один»: снимает главный минус кубиков, долгие перебросы «на удачу».

Без блока `roll` всё остаётся по-прежнему: происхождения распределяют очки,
игрок докручивает бюджет вручную.

Пока этого нет, обход: несколько происхождений с заранее разными наборами
характеристик («Крепыш», «Проворный», «Везунчик»…) — игрок выбирает один из
готовых. Работает сегодня, без кода.

## 5.3 Чего нет: сверка с BRP по главам

### Глава 2. Персонажи

| Механика | Статус | Примечание |
| --- | --- | --- |
| Броски характеристик | **есть** | `char_creation.roll`, см. 5.2 |
| Уровень силы кампании (Обычный / Героический / Эпический / Сверхчеловеческий) | нет | задаётся руками через `stat_limits` и `skill_cap` |
| Перераспределение очков между характеристиками | нет | только ручная докрутка бюджета |
| Культурные и видовые модификаторы | **есть (мастером)** | отдельной сущности «вид» нет — модификаторы закладываются при создании героя: `char_creation.roll.per_stat` (формулы по характеристикам, культура/вид меняет базу), лимиты `stat_limits`; уровень мощи `meta.power_level` (normal/heroic/epic/superhuman) метит кампанию и доступен условием `power_level_ge` |
| Возраст, происхождение-биография, имя | частично | имя — если `choose_name`; биография — текстом в описании кампании |
| Уровень достатка и богатство | **есть, опция** | `meta.wealth_levels` — шкала от низшей к высшей ступени; сдвиг эффектом `change_wealth`, условие `wealth_ge`; деньги как предметы-валюта (`meta.currencies`) — рядом, уровень достатка абстрагирует имущество/положение |
| Нечеловеческие персонажи | частично | характеристики НПС любые, но форма героя одна и та же |

### Глава 3. Навыки

| Механика | Статус | Примечание |
| --- | --- | --- |
| Базовый шанс навыка от характеристик (Скрытность = Ловкость ×2 и т. п.) | нет | навык — просто число из реестра кампании |
| Категории навыков | **есть, опция** | `meta.skill_categories` + `skills[].category`; лист персонажа группирует навыки по категориям |
| Проверки характеристик (Сила ×5, Телосложение ×5, Удача = Мощь ×5, Идея = Интеллект ×5) | **есть** | эффект `stat_check` (stat, multiplier ум. 5, modifier) с ветками успеха/провала; новые условия правил `stat_ge`, `hp_ge/hp_le`, `luck_ge`; ink-экстернал `stat_roll(stat, mult)` |
| Противоборство и таблица сопротивления | **есть** | в бою — сравнение рангов атаки и защиты; вне боя — эффект `opposed_check` (двойной бросок, ранги, tie за игроком/соперником) и ink-экстернал `opposed_roll(skill, entity)`; таблица сопротивления не нужна — роли уже по d100 |
| Уровни сложности (½, ¼, невозможно) | нет | сложность — число-порог, модификатор к цели можно добавить везде руками; названных уровней нет |
| Аугменты (страсть усиливает бросок) | **есть** | `augment_passion` у `stat_check`/`opposed_check`; порог и бонус — `meta.augments` (умолчание 50 и +20, книжно). Страсти — опциональная система `meta.passions_list`, эффекты `change_passion`, условие `passion_ge` |
| Групповые и вспомогательные проверки (подмога) | **есть (подмога)** | `assist_entity`/`assist_skill` у `stat_check` — союзник с навыком ≥ порога аугмента даёт +20; полноценных сцепленных групповых бросков нет |

### Глава 4. Силы

| Механика | Статус | Примечание |
| --- | --- | --- |
| Магия, мутации, психика, колдовство, суперсилы | нет | есть MP (POW) и реестр способностей с кулдаунами, но это боевые приёмы, а не школы сил с изучением, стоимостью и списком заклинаний |

Обход для магии: способности + статусы + кодекс + флаги «изучено». Работает
для 3–10 заклинаний; для полноценной школы магии не хватит ни интерфейса, ни
экономики MP.

### Глава 5. Система

| Механика | Статус | Примечание |
| --- | --- | --- |
| Отметка опыта и рост навыка на отдыхе | **есть** | отметка при успехе, бросок `1d100 > навык` → `+1d6` |
| Рост характеристик (тренировка, прирост POW) | **есть** | эффект `train_stat` (мир/события/правила): ±к характеристике с клампом по `stat_limits`, пересчёт HP/MP/усталости/рассудка; из ink — `train_stat("POW", 1)` |
| Очки удачи (Удача = Мощь ×5) | нет | — |
| Очки усталости (Сила + Телосложение) | **есть, опция** | `meta.vitals.fatigue` (max = (STR+CON)×множитель): чип в HUD, эффект `change_fatigue`, условия `fatigue_ge`/`fatigue_le`; отдых восстанавливает (`rest_restore` ≠ false). Мастер сам решает, что тратит (бег, труд) и что происходит на нуле — правилами |
| Естественное заживление | **есть** | сон (`sleep(t)`) лечит HP костями из `meta.rest.hp` (умолчание `1d3`) и полностью восстанавливает MP (`rest.mp_full`, умолчание да); мастер настраивает или отключает |
| Тяжёлые раны, потеря сознания, состояние при 0 HP | **есть, опция** | `meta.combat.death.mode='brp'`: удар ≥ ½ max HP — спасбросок CON, провал — нокаут до конца боя; при 0 HP — спасбросок CON, успех — выживание без сознания (1 HP), проигрыш разрешают эффекты `on_defeat` у `start_combat` (нет — смерть). Умолчание — мгновенная смерть как прежде |

### Глава 6. Бой

| Механика | Статус | Примечание |
| --- | --- | --- |
| Хит-локации | нет | броня общая, урон общий |
| Несколько атак за раунд | **есть** | `WeaponData.attacks_per_round` работает: атак в ходу столько, сколько указано; повторные атаки идут со штрафом `meta.combat.multi_attack_penalty` (умолчание −20 за каждую следующую, разделение навыка по духу BRP; мастер может поставить 0) |
| Отступление и бегство игрока | **есть** | кнопка «Бежать из боя»: враги в досягаемости бьют вслед, затем проверка навыка отступления (умолчание `dodge`, иначе DEX×5); успех — бой окончен, эффекты `on_fled`, враги живыми остаются на арене. | Укрытия | нет | есть только препятствия (`blocked_hexes`) и сложная местность (×2 к стоимости) |

| Импал, сбивание, разоружение, захват, толчок | **есть** | `WeaponData.traits`: `impale`, `knockback`, `disarm`, `grapple`, `push_harmless` — срабатывают с уверенного успеха и критического |

| Таблицы критических попаданий и провалов | частично | крит фиксирован (максимальный урон, броня не спасает); провалы — таблица мастера `meta.combat.fumble_table` (рождение оружия, застревание, саморазне, потеря хода) |
| Фланкирование и удар в спину | нет | разворот фигурки — косметика, на логику боя не влияет (удар из скрытности покрывает сценарий засады) |
| Зоны контроля и атаки возможности | **есть** | `meta.combat.opportunity_attacks` (умолчание вкл.): уход из угрожаемого гекса — бесплатный удар вслед, обе стороны |

| Конный, воздушный, подводный бой; транспорт | нет | — |
| Внезапная смерть при 0 HP | **есть (умолчание)** | режим `death.mode='instant'`; мастер может включить BRP-режим с потерей сознания и спасбросками (см. главу 5) |

## 5.4 Механики, которых нет в BRP, но которые напрашиваются

То, чего просит сам жанр текстового рогалика, а не книга.

**Комфорт игрока**

| Механика | Статус | Примечание |
| --- | --- | --- |
| Несколько слотов сохранения | **есть** | автосейв + ручные слоты игрока, `meta.save_slots` (умолчание 3, 0 — только авто); пермадет стирает автосейв, ручные снимки переживают забег, см. [главу 7](07-versions.md) |
| Откат хода / отмена действия в бою | нет | есть автосохранение, отмены хода нет (undo — только в редакторе) |
| Уровень сложности как настройка игрока | обход | отдельные кампании или `dice_rules`, но это выбор мастера, а не игрока |
| Доступность (размер шрифта, режим для дальтоников, экранный диктор) | частично | есть темы полотна редактора и настройки звука; системных настроек доступности нет |
