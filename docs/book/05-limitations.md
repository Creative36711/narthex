# 5. Чего в движке пока нет

Аудит механик. Источники: код движка (`src/core/`, `src/shared/types.ts`,
`src/shared/compat.ts`) и книга **Basic Roleplaying: Universal Game Engine**
(Chaosium, ORC) — сверены главы 1–11.

Правило простое: **помеченное «нет» не обещайте игрокам как встроенную
механику.** Обход, собранный из сцен, правил и эффектов, — авторское решение
мастера, а не подсистема движка: опишите его игрокам до начала забега и
держите условия в самой кампании.

Статусы в таблицах:

| Статус | Значение |
| --- | --- |
| **нет** | подсистемы не существует, собрать «руками» можно только имитацию |
| **частично** | есть деталь механизма, но не вся механика |
| **обход** | встроенного нет, но имитация получается убедительной |
| **есть** | реализовано, ищите в справочнике механик (глава 4) |

## 5.2 Генерация характеристик кубиками

**Статус: внедрено.** Мастер может включить на экране создания героя базовый
метод BRP — броски вместо покупки за бюджет. Конфиг целиком мастерский:

| Поле | Смысл | Умолчание |
| --- | --- | --- |
| `char_creation.roll.notation` | формула по умолчанию | `3d6` |
| `char_creation.roll.per_stat` | переопределение на характеристику: `{"INT": "2d6+6", "SIZ": "2d6+6"}` | нет |
| `char_creation.roll.arrays` | сколько наборов бросить сразу, игрок берёт один | 1 |
| `char_creation.roll.rerolls` | перебросы отдельных характеристик (по одной) | 0 |
| `char_creation.roll.redistribute` | очков докрутки сверх выброшенного набора (BRP — до 3) | 0 |

Детали реализации:

- брошенные значения прижимаются к рамкам `stat_limits` мастера;
- в режиме кубиков бюджет `total_points` больше не валидируется, а
  распределение характеристик у происхождений (`profession.stats`)
  игнорируется — бонусы навыков и снаряжение происхождений работают;
- бросок делается на экране (не привязан к seed забега), производные HP/MP
  пересчитываются при применении выбора;
- выбор из нескольких наборов (`arrays`) — практика «брось три — возьми
  один»: снимает главный минус кубиков, долгие перебросы «на удачу».

Без блока `roll` всё остаётся по-прежнему: происхождения распределяют очки,
игрок докручивает бюджет вручную.

Пока этого нет, обход: несколько происхождений с заранее разными наборами
характеристик («Крепыш», «Проворный», «Везунчик»…) — игрок выбирает один из
готовых. Работает сегодня, без кода.

## 5.3 Чего нет: сверка с BRP по главам

### Глава 2. Персонажи

| Механика | Статус | Примечание |
| --- | --- | --- |
| Броски характеристик | **есть** | `char_creation.roll`, см. 5.2 |
| Уровень силы кампании (Обычный / Героический / Эпический / Сверхчеловеческий) | нет | задаётся руками через `stat_limits` и `skill_cap` |
| Перераспределение очков между характеристиками | нет | только ручная докрутка бюджета |
| Культурные и видовые модификаторы | нет | нет самого понятия «вид» |
| Возраст, происхождение-биография, имя | частично | имя — если `choose_name`; биография — текстом в описании кампании |
| Уровень достатка и богатство | обход | богатство = предметы-валюта (`meta.currencies`); уровня достатка нет |
| Нечеловеческие персонажи | частично | характеристики НПС любые, но форма героя одна и та же |

### Глава 3. Навыки

| Механика | Статус | Примечание |
| --- | --- | --- |
| Базовый шанс навыка от характеристик (Скрытность = Ловкость ×2 и т. п.) | нет | навык — просто число из реестра кампании |
| Категории навыков (Восприятие, Общение, Физические…) | нет | `SkillDef` — только `id` и `label` |
| Проверки характеристик (Сила ×5, Телосложение ×5, Удача = Мощь ×5, Идея = Интеллект ×5) | **есть** | эффект `stat_check` (stat, multiplier ум. 5, modifier) с ветками успеха/провала; новые условия правил `stat_ge`, `hp_ge/hp_le`, `luck_ge`; ink-экстернал `stat_roll(stat, mult)` |
| Противоборство и таблица сопротивления | **есть** | в бою — сравнение рангов атаки и защиты; вне боя — эффект `opposed_check` (двойной бросок, ранги, tie за игроком/соперником) и ink-экстернал `opposed_roll(skill, entity)`; таблица сопротивления не нужна — роли уже по d100 |
| Уровни сложности (½, ¼, невозможно) | нет | сложность — число-порог, модификатор к цели можно добавить везде руками; названных уровней нет |
| Аугменты (один навык или страсть усиливает другой) | нет | модификаторы только от статусов (`skill_mods`) |
| Групповые и вспомогательные проверки | нет | — |

### Глава 4. Силы

| Механика | Статус | Примечание |
| --- | --- | --- |
| Магия, мутации, психика, колдовство, суперсилы | нет | есть MP (POW) и реестр способностей с кулдаунами, но это боевые приёмы, а не школы сил с изучением, стоимостью и списком заклинаний |

Обход для магии: способности + статусы + кодекс + флаги «изучено». Работает
для 3–10 заклинаний; для полноценной школы магии не хватит ни интерфейса, ни
экономики MP.

### Глава 5. Система

| Механика | Статус | Примечание |
| --- | --- | --- |
| Отметка опыта и рост навыка на отдыхе | **есть** | отметка при успехе, бросок `1d100 > навык` → `+1d6` |
| Рост характеристик (тренировка, прирост Мощи) | нет | характеристики фиксированы на весь забег |
| Очки удачи (Удача = Мощь ×5) | нет | — |
| Очки усталости (Сила + Телосложение) | нет | усталость делают потребностью |
| Естественное заживление | **есть** | сон (`sleep(t)`) лечит HP костями из `meta.rest.hp` (умолчание `1d3`) и полностью восстанавливает MP (`rest.mp_full`, умолчание да); мастер настраивает или отключает |
| Тяжёлые раны, потеря сознания, состояние при 0 HP | **есть, опция** | `meta.combat.death.mode='brp'`: удар ≥ ½ max HP — спасбросок CON, провал — нокаут до конца боя; при 0 HP — спасбросок CON, успех — выживание без сознания (1 HP), проигрыш разрешают эффекты `on_defeat` у `start_combat` (нет — смерть). ## 5.5 Обходные пути: рецепты

| Хочется | Как собрать сейчас |
| --- | --- |
| Рассудок | потребность + `change_need` из правил на пугающих событиях; последствия — правила на порогах |
| Усталость | потребность с `decay_when` (ночь, бой) и восстановлением при отдыхе |
| Удачу | переменная + заранее описанные правила траты; игрок должен знать правила до забега |
| Хит-локации | статусы («ранена рука», «травма головы») с `skill_mods`; урон при этом общий |
| Тяжёлые раны | только вручную: в диалоге условие «здоровье ниже» (или `get_hp()` в ink) → эффект `apply_status` со `skill_mods` и `mov_mod`. Автоматически правило на HP не сработает: в реестре условий здоровья нет. 0 HP — смерть |
| Лечение со временем | отдельная кампанийная механика на предметах и сценах; регенерации за сон нет, а правило с `tick_elapsed` сработает один раз (`fired_rules`) |
| Магию | способности + MP + кулдауны + статусы; изучение — флагами и записями кодекса |
| Репутацию | отношения к фракциям (в том числе скрытым) + правила на порогах `disposition_ge` |
| Страсти и верность | переменные + правила, влияющие на проверки и диалоги; вручную |
| Уровень сложности | отдельная кампания или правка `dice_rules` |
| Несколько атак за раунд | **обхода нет** — только код |
| Бегство из боя | **обхода нет** — только код |
