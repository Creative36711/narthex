# 2. Редактор: обзор каждой вкладки и рабочие приёмы

Эта глава закрывает «работу с визуальным редактором». Она читается не «от
начала до конца», а по потребности: открыл раздел → нашёл в этой главе
соответствующий блок → читал, пока не понял вопрос.

## 2.1. Общая логика

- **Левая навигация** группирует содержимое кампании. Большинство разделов
  — «список + карточка выбранного объекта».
- **Любое изменение ждёт кнопки «Сохранить»**. Автосохранения нет — это
  сознательное правило: вы сами решаете, когда «сделать снимок» кампании.
  Учтите это, если привыкли к авто-сейвам.
- **Ctrl+Z / кнопка «Отменить»** откатывает последние изменения (ограничение:
  только действия, сделанные в текущей сессии редактора).
- **Поля со ссылками** обычно имеют выпадающий список — редактор сам собрал
  его из содержимого кампании. Id вбиваете только когда знаете зачем.
- **Маленькая иконка «?»-подсказки** есть у большинства полей — она
  поясняет, от чего это меняет в игре.

## 2.2. Шапка и меню «Файл»

**Файл**: новая кампания, удаление кампании, экспорт (`.chronicle`-пакет,
JSON-монолит, *Чемодан для ИИ-агента*, zip), импорт пакета, импорт из JSON.
Подробно о форматах — в главе [«Технические вопросы»](06-technical.md).

**Инструменты**: «Проверить кампанию» (свод отчёта возникающих ссылок и
пустых полей), «Кампания с ИИ» (мастер ИИ-настройки проекта), «Книга мастера» —
эта книга, из самого приложения.

Шапка справа: «Плейтест», «Выйти», индикатор сохранённости.

## 2.3. Раздел «Проект»

| Вкладка | Что тут живёт | Когда трогать |
| --- | --- | --- |
| Основное | название, стартовая сцена, шаблон героя, версия | всегда в начале и перед релизом кампании |
| Создание героя | какие вопросы игрок пройдёт на старте: имя, роль, класс, распределение характеристик, портрет (галерея/сегменты), уровень сложности | когда герой хоть как-то настраивается игроком |
| Версии | история версий кампании и дневник изменений, заметки о совместимости сохранений | при каждом значимом выпуске (сохранения игроков завязаны на версии) |
| Механики | правила бросков, слоты магии, потребности, время, валюта, уровни сложности | один раз в начале, дотонение — по необходимости |
| Оформление | цветовой профиль, токены, рамка-«кадр», шрифты, фоны, полный CSS | ближе к релизу; мнение мастера о «визуальной идентичности» |
| Статусы и способности | реестр статусов (буфы/дебафы), способности боевые и магические | когда герой или существо получат активные умения и изменения состояния |
| Персонажи (реестр) | НПС, существа, параметры, состояния порта и эмоции | наполнение мира |
| Предметы и слоты | инвентарь, экипировка, карман/места, категории ценностей | когда игрок носить с собой лут и использовать его |
| Флаги | переключатели мач в истории | сложные квестовые развилки |
| Звук и музыка | реестр звуков и треков, синтезаторное покрытие | атмосферный слой |
| События и генераторы | таблицы событий, периодические генераторы, мета-хроника, доска заданий, магазин обмена валюты | «живой мир» |
| Хроника | мета-прогресс игрока между забегами, достижения, магазин постоянного усиления, New Game+ | постоянная (над-забеговая) прокачка игрока |
| JSON | прямая правка монолитного представления кампании (№, не для слабых сердец!) | только если знаете, что делаете |

Совет: работа мастера — **не трогать вкладку «JSON»**, а пользоваться
конструкторами. Подробности про поля вкладки JSON — в технической главе:
она нужна для ремонта, а не для ежедневной работы.

## 2.4. Раздел «Мир»

**Локации и регионы** держат географию. **Сцены** — комнаты и виды:

- фон (картинка или анимация; о погодных слоях и «кадрах» камеры — глава
  [«Визуальная часть»](04-visual.md));
- **слои состояний сцены** — day/night-состояния по ходу забега (например,
  «утро», «весна», «после пожара»); переключаются правилами и условиями;
- **слоты** — места обитателей; **зоны навигации** — куда из сцены можно
  пройти/уехать; **зоны события** — триггеры «когда герой подошёл».

Рисовать зоны прямо по картинке удобно: откройте сцену, разверните «Фон» и
включите режим **«Разметка»** — мастерская инструмент поставит прямоугольники
мышкой. Поставленная зона получает метку «слот/выход» — и игрок сразу
на неё кликает.

**Арены** (тактические карты боёв) — отдельная страница в Мир: собрать
карту полей, препятствия, точки появления. И **катсцены** — слайдовые
истории с музыкой.

## 2.5. Раздел «Персонажи»

Карточка существа сводится в одном окне: характеристики, навыки, способности,
экипировка, портрет и состояния-облики (об этом — [визуальная глава](04-visual.md)),
**эмоции как варианты портрета**, стартовые правила поведения.

Важно: существо, которого мастер хочет «сказать в диалоге», должно иметь
`dialogue` — ссылка появляется сама, если открыть редактор диалогов рядом с ним.

## 2.6. Раздел «История»

- **Диалоги** — визуальный конструктор: узлы, реплики и ответы собираются
  формами без кода; вставки стандартных значений (имя героя, число монет)
  делаются кнопками токенов. Диалог, написанный вручную на языке Ink,
  открывается как код — но кнопка **«Открыть в конструкторе»** рядом с
  подсказкой переводит его в визуальную модель: смысл, ответы и проверки
  навыков сохраняются (если конвертер встретил что-то рукотворные и
  непонятное, он заранее перечислит эти строки и попросит подтверждение).
- **Правила мира** — главный двигатель событий: «когда (условения) →
  (эффекты)». С помощью правил ставятся флаги, отменяются переходы, начинаются
  бой, преследование, катсцена, «баннер» и «открытка» поверх мира.
- **Квесты** — журнал со стадиями и наградами; переключение уровней сложности игрока живёт в
  «Проект → Механики» и «Проект → Создание героя».
- **Кодекс** — расширяемый энциклопедический блок для игрока.

## 2.7. Рабочие приёмы (что я советую выполнять на автомате)

1. **Сохраняйтесь после каждого действия, а не «на всякий случай раз в час».**
   Максимальный урон от восклицания «как всё сломал после обеда» — кнопка
   «Отменить» не поможет после перезапуска редактора.
2. **Проверяйте кампанию после изменений связей** (удалили персонажа,
   переименовали сцену — движок покажет висючие ссылки до игроков).
3. **Несите исходники изображений вместе с кампанией** через кнопку
   загрузки в редакторе, не вручную по файловой системе: иначе легко
   пропустить файлы при экспорте.
4. Не называйте состояния сцен, предметы и события одинаково — проверка
   кампании выясняет правильную отсылку только замешанность.
5. Журналируйте изменения во вкладке **«Версии»** — спасает при возврате
   к кампании через три месяца ночи: вы не вспомните «зачем этот флаг».
