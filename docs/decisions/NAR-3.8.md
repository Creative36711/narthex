# D-076 · Намеренно отсутствующие изображения: объявляет кампания, а не тест

Статус: accepted
Дата: 2026-10-26
Дата решения: 2026-10-26
Решил: Мастер (ответ на открытый вопрос Координатора)

## Неясно

ТЗ NAR-3 противоречит само себе:

- §4 «Готово, когда» требует `playthrough` с **0 экранов ошибки** и без
  «Фон сцены не загрузился», без битых `<img>`;
- §3.3/§3.4 объявляют 27 отсутствующих изображений `ash-of-caerden` и
  `ash-of-caerden-adventure` **намеренной фикстурой**.

NAR-3.7 закрыл фазу 2 с `check = 0`, но опирался на три вещи, которые
оракулом не являются:

1. жёсткий список исключений **внутри** harness (`KNOWN_ABSENT_IMAGES`);
2. `MutationObserver` в `src/player/GameView.tsx`, который скрывает любую
   техническую плашку уже после её появления в DOM;
3. разметка плашки «Фон сцены не загрузился» остаётся в `SceneScreen.tsx` —
   то есть игрок её не видит только потому, что её прячут извне.

Такой механизм не масштабируется: список знает ровно те шесть путей, которые
проходит маршрут, хотя реально отсутствуют 27 ссылок в каждом из двух
полигонов (проверено: 27 несуществующих файлов из 27 ссылок `assets/...`).
Новый случай отсутствия попадёт в красный, а старый — никогда не покраснеет,
даже если файл появится.

## Факты, на которых основано решение

- Игроку полигоны не показываются: их нет в `public/campaigns/index.json`
  (D-073, D-075). Значит «что видит игрок» на них проверить нельзя — можно
  проверить только «что видит агент на скриншоте».
- 27 файлов `ash-of-caerden` существуют в истории git (`a3bea9a`, родитель
  `60a2da5`). Восстановление возможно и не требует генерации (D-075).
- `smoke:no-campaign` — действующий оракул — утверждает, что у полигона нет
  `assets/img` и нет файлов больше 200 КБ. Восстановление картинок без ADR его
  ломает.
- `campaign:release` уже отказывается выпускать проект с отсутствующими
  `assets/...`, поэтому у проекта витрины объявленных отсутствий быть не может.

## Решил

**Принят вариант A по существу, механизм заменён.** Пустой список исключений
должен получаться сам, а не поддерживаться в тесте.

1. **Объявляет кампания.** В `dev-fixture.json` появляется поле
   `known_absent_images` — массив путей `assets/...`, отсутствие которых
   намеренно. Это данные фикстуры, а не код проверки.
2. **Harness не знает путей.** `scripts/visual/playthrough.mjs` читает список
   из маркера кампании. У проекта витрины маркера нет → список пуст → любое
   отсутствующее изображение красное. У `fmv-crossing` список остаётся пустым
   навсегда, пока он витринный.
3. **Страж фикстуры.** `check:dev-campaigns` требует:
   - каждый объявленный путь относителен, начинается с `assets/` и **не
     существует** на диске (иначе декларация устарела);
   - каждый объявленный путь действительно упомянут в JSON кампании (иначе
     запись мёртвая);
   - **любая** отсутствующая ссылка `assets/...` в каталоге вне реестра
     объявлена. Необъявленное отсутствие — красный гейт, а не «и так сойдёт».
4. **Игрок не видит техническую плашку.** Её разметка удаляется из
   `SceneScreen.tsx`; при ошибке фона рисуется существующий нейтральный
   `scene-bg-fallback`, причина остаётся в `console.error`. `MutationObserver`
   в `GameView.tsx` удаляется: скрывать то, чего нет, больше не нужно.
   Игрок никогда не видит путь к файлу; разработчик видит всё в консоли, в
   `audit:campaign` и в отчёте экзамена.
5. **§4 читается как «0 находок при объявленных отсутствиях».** Экзамен
   печатает каждое объявленное отсутствие с `path`, `status` и `content-type`
   и не считает его находкой. Всё остальное — по-прежнему находка: битый
   `<img>`, пустой `src`, `pageerror`, экран ошибки, сырой NPC id, а также
   объявленный путь, который внезапно начал отдаваться как `image/*`.
6. **27 файлов не восстанавливаются** (D-075). Если `ash-of-caerden` пойдёт в
   витрину — это отдельная карточка: восстановить из `a3bea9a`, снять маркер,
   очистить `known_absent_images`, пересмотреть `smoke:no-campaign` через ADR.

## Отклонённые альтернативы

- **B — восстановить 6 отсутствующих изображений и снять фикстуру.**
  Покрывает 6 путей из 27 (остальные 21 остаются битыми при любом другом
  маршруте), ломает оракул `smoke:no-campaign` и даёт игроку ноль: полигон не
  показывается. Восстанавливать имеет смысл все 27 и только вместе с выпуском
  в витрину.
- **C — исключить ash-полигоны из §4 и закрыть фазу по adventure + fmv.**
  Это не решение конфликта, а его отмена: фаза 2 лишится единственной
  браузерной регрессии narrative- и adventure-маршрутов, ровно той, ради
  которой принимали D-072.
- **Оставить как есть** (вариант по умолчанию): жёсткий список из шести путей
  в тесте плюс скрытие плашки в рантайме. Отклонено: список неполон и
  поддерживается вручную, а скрытие ошибки в `GameView` действует и на
  витринный проект — то есть маскирует настоящую поломку у игрока.

## Проверка

- `npm run check:dev-campaigns` — декларации полны, устаревших и мёртвых
  записей нет, необъявленных отсутствий нет.
- `npm run smoke:absence-policy` — политика на временных каталогах: маркер
  объявляет → отсутствие не находка; маркера нет → находка; объявленный путь,
  который отдаётся изображением → находка.
- `npm run playthrough:exam` — 0 находок, каждое объявление напечатано
  `path/status/content-type`, `pageerror = 0`, битых и пустых `<img>` нет.
- Мутационная проба: лишний отсутствующий `assets/...` в dev-полигоне, которого
  нет в декларации, делает экзамен красным (проверяется `--fixture-root`).
- `npm run check:contracts`, `npx tsc -b` — зелёные.
- `npm run check:mission` — 11 шагов зелёные, включая `smoke:mission` (55
  скриптов) и `cf-play check` на обоих полигонах.
- `check:module-size`: правка `SceneScreen.tsx` упёрлась в лимит 450 строк
  (632), поэтому экран разложен на слои — `SceneForeground` (спрайты и точки
  «использовать предмет»), `SceneNavigation`, `SceneIntroOverlay`,
  `ItemInteractDialog`; поведение не менялось, `playthrough` и строгий экзамен
  после разбиения зелёные.

## NAR-3.8 follow-up — smoke selectors after D-076 (2026-10-27)

- **неясно** — D-076 уже находился в базовой ветке, но несколько старых smoke assertions продолжали искать извлечённую логику в прежних файлах или по прежним исходным строкам, а package.json не объявлял отдельные npm-команды для этих смоуков.
- **решение** — скорректировать только пути и селекторы к фактическим владельцам кода, сохранить все 15/31/63/45 проверок без изменения runtime-поведения, добавить четыре npm aliases; `SceneScreen.tsx` уже содержит 414 строк при лимите 450, поэтому повторное разбиение не требуется и Phase 3 остаётся закрытой.
- **откат** — откатить только NAR-3.8 smoke path/selector changes и четыре aliases; не откатывать D-076, policy-модуль, объявления кампаний, порог размера или закрытие Phase 3.
