# STAB-1.8 — Studio: восстановление связи `src/editor` ↔ паки

Статус: accepted
Дата: 2026-10-30
Дата решения: 2026-10-30
Решил: Studio (исполнитель карточки STAB-1.8)
Миссия: STAB-1 · Восстановление проверяемой базы Narthex
Базовая точка: `origin/main` `6a98572cdb31d08fadd5d764e26a0a6a2c43bc98`

## Контекст

`2344bcf` (GOLD-1) вернул в `src/editor/` более старую ревизию: из
`src/editor/store.ts` и `src/editor/EditorApp.tsx` исчезла вся обвязка проекта и
паков (`project`, `packResolution`, `capabilityModes`, `setCapabilityMode`,
`project.json`), а `src/core/dialogue.ts` переехал в `packs/narrative/dialogue.ts`.
Панели паков и потребители диалогов остались новыми, поэтому `npx tsc -b` падал
с 12 диагностиками. Последнее совместно рабочее состояние — `c501d32` (NAR-2.8).

Ремонт: API `EditorStore` восстановлен из `c501d32` (типы и импорты — на
существующие модули `src/core/pack/*` и `packs/narrative/*`), `EditorApp`
подключён заново, два неверных импорта диалогов переведены на реальный модуль.
Поведение не перепроектировалось: восстановлены те же ветки, что были до GOLD-1.

## Решения по неоднозначностям

### 1. `check:audit-bundle` против запрета пересобирать `public/ai/*`

- **Неясно:** карточка требует `npm run check:audit-bundle` rc 0 и одновременно
  запрещает пересборку `public/ai/*`. `scripts/campaign-audit.mts:353` делает
  `await import('../src/editor/store')`, поэтому `store.ts` входит в бандл, и
  любой честный ремонт стора делает опубликованный артефакт устаревшим.
- **Решил:** артефакт не трогать (явный запрет сильнее), rc 1 задокументировать с
  точными числами и передать пересборку владельцу `public/ai/**` — карточке
  Tools «Согласованность сборки и проверок». Доказательство причины: при
  откате одного `src/editor/store.ts` проверка снова rc 0, а дельта
  сгенерированного бандла (16 участков, 134 строки) состоит только из
  восстановленного кода `project`/`capabilityModes`/`packResolution`.
- **Откат:** `npm run build:ai-bundle` (артефакт не изменён, откатывать нечего).

### 2. Секция `panels` и автовыбор документа

- **Неясно:** в `c501d32` из автовыбора исключены `packs`, но не `panels`, хотя
  список файлов исключал обе секции.
- **Решил:** исключить обе — секция, чья главная панель показывает верстак, не
  должна молча менять выбранный документ.
- **Откат:** убрать `'panels'` из массива в `EditorApp.tsx` (один токен).

### 3. Запись `project.json` внутри `setCapabilityMode`

- **Неясно:** `c501d32` писал манифест приватными присваиваниями плюс
  `this.touch('project.json')`, а `scripts/view-write-smoke.mts` отклоняет любой
  новый вызов `.touch(` вне своего белого списка (файл смоука вне зоны карточки).
- **Решил:** писать через существующий внутренний `setJson('project.json', …)`:
  он выполняет ту же последовательность (`project`/`projectFileExists`/
  `capabilityModes`, затем `touch`), поэтому инвариант «просмотр ≠ запись»
  остаётся зелёным без правки смоука и без ослабления проверки.
- **Откат:** заменить вызов на три присваивания и `touch` и в том же изменении
  добавить строку в белый список смоука.

### 4. Тексты бренда в `EditorApp.tsx`

- **Неясно:** та же ревизия GOLD-1 оставила в `EditorApp.tsx` `Chronicle Forge` и
  `.chronicle`, которые `scripts/brand-guard.mts` теперь считает старым брендом.
- **Решил:** не переименовывать продуктовые строки в карточке ремонта `tsc`;
  `npm run check:brand` красный на `main` с 298 попаданиями до и после патча, а
  список файлов бренда принадлежит карточке «Согласованность сборки и проверок».
- **Откат:** сверить список попаданий `npm run check:brand` и передать его
  карточке бренда.

## Границы

Изменены только `src/editor/**`, `_tools/reports/STAB-1.8.md` и этот файл.
`tsconfig*`, `package.json`, `src/core/**`, `src/shared/**`, `packs/**`,
`public/**`, `.golden/**`, `docs/contracts/**`, `.github/**` не изменялись.
Панели `PackCatalogPanel.tsx` и `PackPanelWorkbench.tsx` остались байт-в-байт
равны baseline-хешам `check-module-size`: чинился связываемый API, а не пробы.
