# NAR-3.7 — намеренно отсутствующие изображения в строгом браузерном экзамене

- **неясно** — в двух внутренних Ash-полигонах есть по 27 намеренно отсутствующих изображений, но строгий браузерный экзамен должен оставаться красным для любого отсутствия, не объявленного самой кампанией, и для любой устаревшей декларации.
- **решение** — после D-076 каждую фикстуру кампании объявляет поле `known_absent_images` (27 + 27 путей). `scripts/visual/absence-policy.mjs` — единый источник политики для экзамена, `check:dev-campaigns` и `smoke:absence-policy`. Экзамен записывает наблюдаемые отказы с `path`, `status` и `content-type`; объявленные отсутствия не являются находками, но отсутствие без объявления и путь из объявления, который начал отдаваться как `image/*`, остаются находками. У витринной кампании без внутреннего маркера любое отсутствие остаётся ошибкой.
- **откат** — менять D-076 и все потребители политики согласованно; не возвращать локальные для маршрута исключения, не менять данные кампаний и не восстанавливать изображения только ради зелёного экзамена.

- **неясно** — штатная засада Ash может перевести маршрут в бой и тем самым запросить дополнительные изображения, хотя браузерная проверка должна достичь существующего `ending_ashes` и учитывать любой неожиданный image request как находку.
- **решение** — только браузерный harness использует фиксированный обычный seed и штатные controls создания героя с допустимыми минимальными характеристиками; кампания, боевая логика и обработка ресурсов не меняются.
- **откат** — убрать seed и выбор характеристик только из маршрута экзамена; сохранить маршрутную проверку, политику `known_absent_images` и все правила классификации ресурсов.
