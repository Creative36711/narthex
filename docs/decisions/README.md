# Журнал решений и статусы ADR

В этом каталоге хранятся ADR и журналы решений. Для новых ADR указывай поле
`Статус`. Старые журналы без этого поля остаются валидными: обратная
совместимость сохраняется, в том числе для 19 существующих журналов, в которых
нет `Статус`; отсутствие поля не означает никакой конкретный статус.

## Статусы и метаданные

Если поле `Статус` есть, его значение — ровно одно из четырёх:

- `proposed` — предложение ожидает ответа;
- `accepted` — предложение принято;
- `rejected` — предложение отклонено;
- `superseded` — решение заменено более новым ADR; укажи ссылку на заменивший ADR.

Для `accepted` и `rejected` обязательны `Дата решения: YYYY-MM-DD` и непустое
поле `Решил`. Для остальных статусов эти два поля не обязательны. Дату создания
предложения при наличии записывай отдельно в поле `Дата`.

`npm run check:decisions` проверяет допустимость указанного статуса и обязательные
метаданные для `accepted`/`rejected`. Журналы без `Статус` остаются допустимыми.
`proposed` выводится в информационном списке и сам по себе не проваливает проверку
или сборку.

## Жизненный цикл предложения

`proposed` — временное состояние до ответа, а не завершённое решение. Для ADR,
созданного со статусом `proposed`, карточка, породившая его, обязана выполнить
второй шаг: создать строку в базе «Вопросы» со ссылкой на ADR, тремя вариантами
и вариантом по умолчанию `оставить как есть`. Этот вариант означает сохранить
действующий контракт и не принимать предложенное изменение; если его выбрали
явным ответом, ADR получает статус `rejected`.

Значение по умолчанию — подсказка, а не ответ: оно не меняет статус автоматически.
До фактического ответа ADR остаётся `proposed`; после ответа статус меняется на
результат решения. Если ответ просит заменить предложение другим ADR, `proposed`
сохраняется до появления решения-замены. Только после фактического ответа,
который выбирает замену, и создания нового ADR прежнее решение получает
`superseded` со ссылкой на него. Предложение, которое никто не решил, — дефект
процесса, а не допустимое постоянное состояние. Строка в «Вопросах» должна
оставаться видимой, пока ответ не записан.

## Нейтральность оракула

Проверка может требовать, чтобы ADR существовал и чтобы его статус — если поле
есть — входил в список выше. Она не должна требовать конкретного значения
статуса. Тест, который требует `proposed`, защищает нерешённость от ответа и
является дефектом теста, а не правилом ADR.
