# NAR-4 · Пошаговый Executor поверх GameEngine

Статус: accepted
Дата: 2026-10-27
Дата решения: 2026-10-27
Решил: Turn Runtime в рамках NAR-4.2, без изменения замороженного ADR 0013

## Контекст

ADR 0013 уже фиксирует `Executor`, `ExecutorFactory`, миллисекунды шага,
события ввода, паузу, строковый seed и канонический fingerprint. До NAR-4.2 в
репозитории был только контракт `src/core/executor.ts`; реализации не было.

Дополнительное ограничение даёт существующий `check:core-graph`: ни один модуль
core не может импортировать `src/core/engine.ts`. Поэтому прямой import
`GameEngine` из `src/core/turn` сделал бы обязательный гейт красным. Менять гейт
или ослаблять его нельзя.

## Решение

Реализация находится в `src/core/turn/index.ts` (229 строк при лимите 450):

- `TurnExecutor implements Executor<GameState>` делегирует время и действия
  существующему движку, не копируя игровые правила;
- `createTurnExecutorFactory(campaign, GameEngine)` возвращает замороженный
  `ExecutorFactory<GameState>`;
- конструктор движка передаётся вторым аргументом из внешнего composition root.
  Структурный `TurnEngine` описывает только нужные существующие методы, поэтому
  `turn` не импортирует `engine.ts`, а `engine.ts` не импортирует реализацию;
- `src/core/executor.ts`, тела методов `GameEngine`, browser и cf-play не
  изменяются. Дополнительный адаптер в `engine.ts` не понадобился.

### Время, пауза и ввод

Один тик равен `86_400_000 / campaign.meta.ticks_per_day` миллисекунд. Дробный
остаток сохраняется между вызовами; в `GameEngine.advanceTicks` уходят только
целые тики. `clock` — текущий `state.tick`, переведённый обратно в мс.

События стабильно сортируются по `at` (по умолчанию 0). Перед событием
продвигается только время до его момента, после последнего — остаток шага.
Обычный пошаговый ввод с `at: 0` поэтому выполняется до пачки тиков, как и
прежний прямой вызов действия с последующим `advanceTicks`.

`pause()` сохраняет остаток, но отбрасывает dt и ввод приостановленного шага;
результат — `changed: false` с тем же `clock` и fingerprint. `resume()` не
двигает время само. Некорректные dt, `at` и неизвестные действия — нарушения
контракта вызывающего, а не игровые отказы, поэтому обозначаются явной ошибкой.

Базовые события `move`, `travel`, `interact`, `use`, `choose` и `wait`
делегируются существующей навигации, слотам и действиям движка. Остальные
строки действий проходят через generic pack operation port, если операция
зарегистрирована; ветвления по pack id нет.

### Seed, состояние и начало забега

`setSeed` повторяет существующий cf-play порядок: создаёт новый `PRNG` и
записывает его seed в `GameState.seed`. Второго seed-поля нет.

Для нового забега фабрика применяет seed до старта, использует существующий
`newCharChoice` при наличии `char_creation`, затем вызывает `engine.start()` —
тот же порядок, что у cf-play. Для продолжения `options.state` важнее
`options.seed`: сохранённые RNG/состояние не пересоздаются по постороннему
зерну и повторного выбора персонажа нет. Сам save format не участвует и не
меняется.

`changed` вычисляется сравнением канонического fingerprint до/после шага;
`fingerprint()` использует `fingerprintOf` из замороженного контракта.

## Неясно / решил / откат

### 1. Как использовать GameEngine без запрещённого core→engine import

- **Неясно:** фабрика должна создавать настоящий движок, но `turn → engine`
  запрещён существующим core graph, а обратный import реализации нарушил бы
  границу ADR 0013.
- **Решил:** передать `GameEngine` как конструктор из внешнего composition
  root; внутри `turn` оставить только структурный тип. `engine.ts` не менять.
- **Откат:** удалить `src/core/turn/index.ts`; существующие файлы и потребители
  уже не зависят от новой реализации, дополнительный revert не нужен.

### 2. Как перевести миллисекунды в тики без нового поля кампании

- **Неясно:** контракт задаёт мс, а campaign schema — только `ticks_per_day`;
  добавлять поле длительности тика нельзя без отдельного согласования.
- **Решил:** считать игровые сутки 24 часами и использовать
  `86_400_000 / ticks_per_day`; неполный тик хранить только в памяти Executor.
- **Откат:** удалить адаптер; остаток не входит в `GameState`, поэтому saves и
  миграции не затрагиваются даже при удалении решения.

### 3. Как инициализировать новый и сохранённый забег без второго API

- **Неясно:** замороженные `ExecutorOptions` содержат только seed/state, а
  cf-play перед стартом ещё применяет стандартный выбор персонажа.
- **Решил:** для нового state повторить существующий порядок cf-play, для
  переданного state ничего не пересоздавать и игнорировать отдельный seed.
- **Откат:** удалить фабричную композицию вместе с новым файлом; прежние
  browser/cf-play entrypoints и так не были переподключены.

## Доказательство неизменного поведения

На реальной кампании Ash прямой `GameEngine` и `TurnExecutor` с одинаковым seed
дали одинаковые fingerprint на старте, после целого тика, после двух половин
тика и после события `wait` в середине шага. Отдельные прогоны `use`, `move`,
`interact` и `startQuest` также совпали по fingerprint с прямыми вызовами.
Пауза сохранила fingerprint и clock. Эталонные cf-play без переподключения на
новый цикл остались численно неизменными (10/8/6/21, 0 ошибок, 8 предупреждений
для обеих кампаний); browser exam завершился 8 + 12 шагами с ожидаемыми
финалами и 0 findings.
