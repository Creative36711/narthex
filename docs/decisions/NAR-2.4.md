# NAR-2.4 — проект без установленного пака

неясно — где показывать отказ и как читать старые проекты, если `project.json` ещё отсутствует.
решил — проверять пак один раз при открытии в `EditorStore`; формат 1 трактовать как `kind: narrative` по `format-v2.md` §8. Использовать общий data-driven resolver в `src/core/pack/registry.ts`: таблица `kind → pack` и названия берутся из контракта, установленный набор — из manifest registry. Missing возвращать результатом `PACK_MISSING`, тем же текстом для Studio и `cf-play check`; отказная Studio-страница не загружает документы и не предлагает редактирование/сохранение.
откат — удалить `resolveProjectPack` и preflight checks, убрать проверку из `EditorStore`/`cf-play`, экран отказа, fixture, smoke, регистрацию smoke-команды и эту запись; формат проекта и игровые сейвы не мигрируются.

Сообщение содержит имя пака и обратимую инструкцию установки: добавить каталог с `pack.json` под `packs/<id>/`, зарегистрировать ID в `packs/registry.json`, перезапустить Studio. Существующий `src/core/engine.ts` не менялся (599 строк).
