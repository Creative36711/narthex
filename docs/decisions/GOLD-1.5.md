неясно: в pinned `dialogues/*.dlg.json` варианты не содержат собственного стабильного `id`, а runtime-индексы существуют только среди вариантов текущего диалога и могут меняться при фильтрации условий.
решил: соблюдать требование live runtime choice index: перед каждым выбором runner читает текущий список доступных кнопок, однозначно сопоставляет нужный вариант с индексом в этом live-списке, проверяет текст и нажимает кнопку по индексу; ID записывается как `runtime:<npc>#<node>[<0-based-live-index>]`. Source-ordinal применяется только как обратимая ссылка для нахождения целевого варианта в импортированных данных, но не как ID выбора.
откат: если кампания получит нативные стабильные ID выборов, использовать их и убрать временный runtime-index convention.
