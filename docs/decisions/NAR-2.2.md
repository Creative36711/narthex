# NAR-2.2 — generic pack host seam

## Решение

Добавлен отдельный `PackHost` в `src/core/pack/host.ts`: он получает manifests снаружи и регистрирует переданные `sim`/`view` функции только для объявленных manifest seams. Хуки получают узкие data-context типы; ссылки на engine/API engine в контракте отсутствуют. Исполнение идёт в порядке manifests, симуляция — синхронно с переданным seed, а view получает readonly-снимки состояния и кадра и только draw-порт.

Каждый снимок клонируется; view-снимки дополнительно обёрнуты рекурсивным runtime Proxy, запрещающим запись, удаление и изменение свойств. В headless-режиме и при `enabled: false` view hook не запускается. Ошибка хука, попытка записи, async-хук или нарушение контракта устанавливает первое постоянное состояние pause с pack ID, именем hook и причиной; исключение не покидает host в игровой цикл.

Для sim действует readonly-контракт входов, запрет async/generator функций и source guard на распространённые источники недетерминизма и I/O (`Date.now`, `Math.random`, ambient APIs, таймеры). Это проверка известных запрещённых примитивов, а не формальное доказательство чистоты произвольного JavaScript/замыканий; для более сильной изоляции понадобится отдельная sandbox-миссия.

Добавлен fixture hook module в `packs/fixtures/full/hooks.ts` и запускаемый вручную probe `npm run probe:pack-host`. Probe покрывает регистрацию из manifest, отсутствие engine в sim-контексте, headless suppression, неизменность state hash при включённом/выключенном view, runtime write rejection, pause при ошибках и 20/20 одинаковых seed прогонов.

## Неясно / решил / откат

- **Неясно:** где подключать универсальный hook host к игровому engine, если NAR-2.2 одновременно запрещает менять остальные файлы `src/core` и не задаёт интеграционный API.
- **Решил:** оставить seam самостоятельным модулем в `src/core/pack/**`; не протаскивать engine или менять gameplay/kernel. Контракт намеренно требует, чтобы вызывающая сторона передала manifests, seed, события и draw-порт.
- **Откат:** удалить новый host, fixture hooks, probe, его package script и этот decision record; никаких миграций или изменений существующих campaign/core runtime данных нет.

## Границы

Изменения ограничены NAR-2.2 Scope. Не менялись существующие core-модули за пределами `src/core/pack/**`; существующие проверки и oracles не ослаблялись. Новый probe не имеет префикса `smoke:`, чтобы не менять число зарегистрированных smoke-проверок.
