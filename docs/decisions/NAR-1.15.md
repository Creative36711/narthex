# NAR-1.15 — пересборка `public/ai/cf-play.mjs` после 1.11/1.12

**Что сделано.** Закоммиченный бандл оракула пересобран из текущего `src` на `main`
(`34432a9`, после NAR-1.12) штатной командой репозитория:

```
npm run build:playkit-bundle
# esbuild scripts/playkit/cli.mts --bundle --platform=node --format=esm --target=node20 \
#   --legal-comments=none --define:__CF_ENGINE_VERSION__='"0.9.0"' --outfile=public/ai/cf-play.mjs
```

`package.json` не менялся: команда `build:playkit-bundle` уже была (её и вызывал
`npm run build`), дублировать её не понадобилось. `src/`, `scripts/`, кампания и
эталон §2 не тронуты — пересборка правки исходников не потребовала.

**Воспроизводимость.** Две сборки подряд дали побайтно один файл:

```
sha256(public/ai/cf-play.mjs) = 355803824407dd78ecd64e5cc215350467aba2ce1dee0de17679e894f8d44b98
```

Хэш src-набора, из которого собран бандл (34 файла `scripts/playkit/**` +
`src/core/**`, сортировка по пути, в хеш идут путь, `\0`, содержимое, `\0`):

```
sha256:5afd7a04cdf4e138f041f862ca69e0edc3aefa12b615b0d34552b27f99dbc7e7
```

Проверка команды, которой считается этот хэш, — в ответе карточки;
`__CF_ENGINE_VERSION__` подставлен из версии пакета: в бандле маркера не осталось
(`grep -c __CF_ENGINE_VERSION__` → `0`), строка `0.9.0` присутствует.

**Что изменилось в поведении.** В бандле появился порядок правил из манифеста
(`grep -c ruleOrder` → `4`, было `0`). На новом файле 20 прогонов
(`run --seed 7 --script route.json --debug`) дают по одному sha256 на каждый из
трёх файлов; на сохранённой копии старого файла те же 20 прогонов дают два
разных `state.final.json` (18× `3ea10dea…390e`, 2× `82d76c1a…ce11`) с разменом
`rule_gates_greeting` ↔ `rule_intro_cutscene` в `fired_rules` и `log` — то есть
старый бандл краснеет ровно там, где красноречил «Итог», новый зеленеет.

неясно: пересобирать существующим скриптом `npm run build:playkit-bundle` или звать esbuild напрямую с флагами из ответа 1.14 — и надо ли регистрировать новую команду в `package.json`.
решил: существующим скриптом, `package.json` не менять: команда уже есть, её флаги совпадают с той сборкой, которой доказывали детерминизм в 1.13/1.14 (`--target=node20 --legal-comments=none --define:__CF_ENGINE_VERSION__='"0.9.0"'`), а вторая регистрация создала бы два источника правды о том, как собирается один файл.
откат: удалить новую команду из `package.json` (если бы она появилась) и собирать esbuild-строкой выше — результат тот же, `sha256` бандла воспроизводится.

неясно: ставить ли в CI проверку «бандл не отстал от src» — именно её отсутствие и породило эту карточку (файл не пересобирался с #20).
решил: в этой карточке не ставить: проверка требует скрипта, а `scripts/**` вне Scope; вариант «одна строка в `package.json` с esbuild в `/tmp` и `cmp`» зависит от платформы (Windows) и дублирует флаги сборки. Записал как следующий шаг для Координатора: карточка Tools «`check:playkit-bundle` — сборка в temp и побайтное сравнение», плюс `npm run build` уже пересобирает бандл, так что регресс возможен только при ручной правке `src` без сборки.
откат: добавить `check:playkit-bundle` в `package.json` и повесить на `ci`, когда появится скрипт в зоне Tools; бандл при этом не меняется.

неясно: не пора ли вообще убрать бандл из репозитория (собирать при установке) — карточка просит в таком случае ADR proposed и паузу.
решил: оставить в репозитории. Оракул Мастера запускается штатной командой `node public/ai/cf-play.mjs …` на чистом клоне, без сборки и без node_modules; удаление файла сломало бы эту команду, то есть сменило бы контракт. Основания для ADR нет — дефект был в устаревании артефакта, а не в его месте.
откат: вернуть файл из `34432a9` (`git checkout 34432a9 -- public/ai/cf-play.mjs`); исходники и гейты не затрагивались.

неясно: `transcript.md` в прогоне зависит от отпечатка логики кампании, а `logicDigest()` (`scripts/playkit/cli.mts:121–133`) хеширует весь каталог, включая артефакты `.cf-play`, — на рабочем дереве после `check` его sha256 не равен прогону на чистом клоне.
решил: не чинить здесь (`scripts/**` вне Scope) и не прятать: в отчёте карточки приведены sha256 на закоммиченном бандле при текущем состоянии каталога и отдельно проверка на чистом клоне; ограничение зафиксировано ещё в §15.3 отчёта NAR-1.14 и вынесено в список правок Координатору. Для оракула детерминизма это неважно: 20 из 20 совпадают внутри одного набора прогонов.
откат: пересчитать `transcript.md` на чистом клоне (команда в ответе) — числа §12 и §15.3 не меняются.

**Допущение:** версия бандла берётся из `package.json` (`0.9.0`), поэтому `ENGINE_VERSION` в артефакте и версия пакета остаются согласованными без отдельной правки — это и проверяет `check:version`.
