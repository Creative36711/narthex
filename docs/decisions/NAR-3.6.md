# D-075 · Кампании: dev по умолчанию, витрина по решению, квота на медиа

Статус: accepted
Дата: 2026-10-26
Дата решения: 2026-10-26
Решил: Мастер

## Неясно

26.10 Мастер поставил три вопроса и одно ограничение среды:

1. **Картинки.** Кто возвращает 27 изображений `ash-of-caerden` и надо ли их
   генерировать?
2. **Dev и реальные проекты.** Делить их или это лишний шаг? Как скрыть
   кампанию в движке и как потом легко вернуть её в dev?
3. **`ash-of-caerden`.** Оставить полигоном или вернуть как реальный проект и
   дорабатывать?
4. **Квота Arena.** На генерацию изображений и озвучки — по 10 штук на каждый
   вид за один ход. Это нужно зафиксировать, чтобы исполнители не удивлялись.

Общая рамка Мастера: кампании, созданные агентами, для него сейчас всё равно
тестовые; вкладываться в визуал, квесты и историю не нужно. После создания и
тестов кампанию должно быть можно скрыть, а позже — легко перевести в dev.

## Проверенные факты

- Игрок видит **только** записи `public/campaigns/index.json`:
  `fetchCampaignIndex()` → `hydrateCampaignIndex()` отбрасывает запись, если
  каталога или `campaign.json` с тем же `id` нет. Каталог вне реестра не
  показывается ни в меню игрока, ни в списке редактора. Отдельный флаг
  «скрыть» не нужен: скрытие уже реализовано отсутствием записи в реестре.
- `scripts/visual/playthrough.mjs` подменяет ответ реестра списком каталогов —
  это тестовый маршрут, а не то, что видит игрок. Прогон намеренно видит
  больше поставки.
- 27 изображений `ash-of-caerden` **не потеряны**. Они лежат в истории git в
  коммите `a3bea9a` (родитель `60a2da5`), в
  `public/campaigns/ash-of-caerden/assets/img/{scenes,npc,arenas,maps}`,
  суммарно ≈4,4 МБ. Восстановление — `git checkout` из истории, а не
  генерация.
- `smoke:no-campaign` — оракул — утверждает, что поставка начинается с пустого
  реестра, `ash-of-caerden` игроку недоступна, в полигоне нет `assets/img` и
  файлов больше 200 КБ. Возврат `ash-of-caerden` в витрину без правки этого
  смоука невозможен, а правка оракула — только через ADR.
- `pack:ai-kit` кладёт `public/campaigns/ash-of-caerden` в кит как
  `examples/narrative`. Возврат картинок увеличит кит на те же ≈4,4 МБ.
- `packs/publications.json` описывает три публикации: `narrative/ash-of-caerden`,
  `narrative/fmv-crossing`, `adventure/ash-of-caerden-adventure`.
  `check:campaigns` сверяет источник пака и публичную копию; `project.json` не
  копируется.
- `dev-fixture.json` уже несёт `visibility`, `reason`, `used_by`, `created_by`,
  `remove_rule`; `check:dev-campaigns` требует `[DEV]` в заголовке и маркер для
  каждого каталога вне реестра.

## Решил

### Витрина и dev

1. **Витрина — это реестр.** Никаких новых полей в `campaign.json` и никакого
   переключателя в движке: dev-кампания — каталог вне `index.json` с префиксом
   `[DEV]` и маркером `dev-fixture.json`. Это уже работает; усложнять нечего.
2. **Новая кампания агента по умолчанию dev.** В реестр она попадает только по
   отдельной карточке или ADR, после полного набора медиа.
3. **Условия перевода в витрину:** `npm run audit:campaign` даёт 0 ошибок
   (включая 0 отсутствующих изображений), `cf-play check` даёт 0,
   `npm run playthrough` проходит, `smoke:campaign-start` зелёный, строка в
   `docs/agents/dev-campaigns.md` перенесена в раздел витрины.
4. **Один выключатель:** `npm run campaign:dev -- <id>` и
   `npm run campaign:release -- <id> --title "<название>"`. Инструмент правит
   источник пака, маркер и реестр, затем публикует копию. Руками
   `public/campaigns/**` не правится: это артефакт пака.
5. **`ash-of-caerden` остаётся dev в NAR-3.** Причины: она — оракул
   (фикстура отсутствующих ассетов), пример в ките и лёгкий каталог. Если
   Мастер захочет её в витрине, это отдельная карточка: восстановить 27
   картинок из `a3bea9a` (не генерировать), завести маленькую отдельную
   фикстуру для проверки отсутствующих ассетов, изменить `smoke:no-campaign`
   отдельным ADR. `ash-of-caerden-adventure` остаётся dev без изменений.
6. **`fmv-crossing` — штатный проект поставки** по D-074. Его перевод в витрину
   делает карточка NAR-3.5, а не этот ADR.

### Медиа и квота

7. **Квота Arena:** не более **10 изображений** и не более **10 аудиоклипов
   (озвучки) за один ход**. Считать консервативно: вызов, вернувший несколько
   вариантов, — это несколько изображений. Это лимит среды, а не дефект
   инструмента; обходить его другими инструментами или повторными сессиями
   нельзя.
8. **Dev-полигоны не генерируют медиа вообще.** Допустимы плейсхолдеры, текст,
   CSS и честная плашка «демо без графики». Генерация начинается только после
   решения выпустить проект.
9. **Сначала восстановление, потом генерация.** Готовый ассет из истории git,
   с Диска или из соседнего проекта дешевле и консистентнее нового.
10. **Планирование партиями.** Список ассетов и промптов составляется до первой
    генерации; одна партия — не больше 10 изображений и 10 клипов. 27 картинок —
    минимум три хода. Если в ход не влезает, работа делится на ходы, а не
    сокращается молча.
11. **Журнал генерации:** `packs/<pack>/data/<campaign>/.generation-plan.md`
    (скрытый файл, в публичную копию не попадает). В нём — что сгенерировано,
    каким промптом и что осталось, чтобы следующий ход продолжал, а не начинал
    заново.

### Документы

12. `docs/agents/generation-quotas.md` — квота и правила; ссылки из
    `docs/agents/README.md`, `sandbox.md`, `dev-campaigns.md`, `tz-nar-3.md`.
13. `docs/agents/dev-campaigns.md` — раздел «dev ↔ витрина» с командами,
    критериями и судьбой `ash-of-caerden`.

## Отклонённые альтернативы

- **Поле `dev: true` в `campaign.json` и переключатель в движке.** Второй
  источник истины, который дублирует реестр и требует правок UI. Реестр уже
  отвечает на вопрос «видит ли игрок».
- **Сгенерировать 27 картинок заново.** Дороже, дольше и хуже по стилю, чем
  восстановить готовые из истории git.
- **Вернуть `ash-of-caerden` в витрину сейчас.** Ломает оракул пустого реестра,
  раздувает кит и не даёт NAR-3 ничего: стартовый проект уже выбран D-074.
- **Отдельная папка `dev-campaigns/` вне `public/`.** Ломает 129 ссылок,
  `packs/publications.json`, оракул `cf-play check` и playkit `example`.

## Проверка

- `npm run check:dev-campaigns` — маркеры, `[DEV]`, чистота реестра.
- `npm run check:campaigns` — источник пака и публичная копия совпадают.
- `npm run smoke:campaign-visibility` — `dev` → `release` → `dev` на временном
  каталоге; отказ при отсутствующих ассетах; сохранение исходного названия.
- `npm run audit:campaign -- <папка>` — 0 ошибок у проекта витрины.
