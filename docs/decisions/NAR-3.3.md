# NAR-3.3 — стартовый проект в поставке

## Решение Мастера (26.10)

**Принято по существу, изменено по механизму.**

Принято: в поставке обязан быть играбельный проект, доступный игроку из
обычного меню, а пустой реестр проверяется отдельной изолированной фикстурой.
Источник данных — `fmv-crossing`: на текущем дереве это единственный проект с
полным набором медиа (0 отсутствующих изображений), тогда как у
`ash-of-caerden` и `ash-of-caerden-adventure` 27 картинок удалены намеренно в
`60a2da5`, и игрок видит на них красную плашку «Фон сцены не загрузился».

Отклонено: держать `fmv-crossing` одновременно `[DEV]`-полигоном и записью в
реестре игрока, с захардкоженным исключением для одного ID в
`check:dev-campaigns`. Это противоречит D-073, который ввёл `[DEV]` именно как
признак «игроку не показывать», и ослабляет страж, поставленный два часа
раньше. Игрок увидел бы в меню «[DEV] Перекрёсток огней — проект FMV (полигон
смоуков)».

Вместо этого **`fmv-crossing` повышается до штатного проекта поставки**:

- `title` в `campaign.json` (и в источнике пака, и в публичной копии) —
  `Перекрёсток огней`, без префикса `[DEV]` и без слов «полигон смоуков»;
- `dev-fixture.json` удаляется из обеих копий: проект больше не полигон;
- в `public/campaigns/index.json` появляется единственная запись `fmv-crossing`;
- `check:dev-campaigns` **не получает никаких исключений**: в реестре — без
  `[DEV]` и без маркера, вне реестра — с маркером и с `[DEV]`, как и было;
- `id` остаётся `fmv-crossing`: каталог не переименовывается, потому что на
  него ссылаются `packs/publications.json`, `check:campaigns`, playthrough
  (регрессия D-072) и оракул `cf-play check`.

Смысл поправки: страж должен оставаться стражем, а не списком известных
исключений. Если `[DEV]`-проект нужен игроку, то он и не `[DEV]`.

Остальное из предложения Architect принимается без изменений:
`smoke:no-campaign` проверяет изолированный ответ/фикстуру `[]` и
восстанавливает реестр, добавляется `smoke:campaign-start` на путь игрока из
реального `index.json`.

## Контекст

`public/campaigns/index.json` пуст. Коммит `60a2da5` и `npm run smoke:no-campaign`
намеренно удерживали пустой реестр как самостоятельный сценарий: приложение
показывает «Кампаний пока нет». После NAR-3.1 и NAR-3.2 проекты уже проходят
игровой маршрут в браузере, но стартовая поставка по-прежнему не предлагает
играбельный проект. Пустой сценарий нужен смоуку, но не должен быть
единственным содержимым поставки.

Причина прежнего расхождения: реестр оставили пустым намеренно ради
`smoke:no-campaign`, когда играбельные примеры были только полигонами. Теперь
пустой случай тестируется отдельно, а реестр поставки представляет путь игрока.

## Что решено (в редакции Мастера)

- Игрок открывает приложение и видит в меню «Перекрёсток огней» — штатную
  запись реестра, без консоли, query-параметров и ручной подкладки файлов.
- Проект остаётся тем же проектом FMV; его данные, сцены и медиа не меняются.
- `npm run smoke:no-campaign` больше не требует пустоты поставочного
  `index.json`: он проверяет изолированный ответ/фикстуру `[]`, подтверждает
  экран пустого реестра и **восстанавливает** исходный реестр после прогона.
  Он не имеет права очищать запись стартового проекта.
- Добавляется `npm run smoke:campaign-start`: проверяет, что `fmv-crossing`
  берётся именно из реального `index.json`, виден в меню и открывается до
  играбельной сцены.
- `docs/agents/dev-campaigns.md`: `fmv-crossing` переезжает из таблицы
  полигонов в раздел «штатный проект поставки»; маркер и `[DEV]` у него больше
  не требуются. Правила для остальных каталогов не меняются.
- `ash-of-caerden` и `ash-of-caerden-adventure` остаются `[DEV]`-полигонами;
  27 отсутствующих изображений — намеренная фикстура, их не чинить, не
  подменять и не копировать в стартовый проект.

## Отклонённые альтернативы

- **Оставить как есть** (вариант по умолчанию в вопросе). Отклонён: в поставке
  по-прежнему нет играбельного проекта, намерение карточки не выполнено,
  игрок видит «Кампаний пока нет».
- **`fmv-crossing` в реестре, но с `[DEV]` и маркером, плюс узкое исключение в
  `check:dev-campaigns`** — исходное предложение Architect. Отклонено по
  причине из §«Решение Мастера»: противоречит D-073, ослабляет страж и
  показывает игроку служебный префикс.
- **Явный экран выбора проекта при запуске.** Отклонён: новое состояние и
  переход, дублирование уже имеющегося выбора из реестра, и отдельный тест
  пустого каталога всё равно нужен.

## Автоматическая проверка

- **Штатный старт:** `npm run smoke:campaign-start` — `fmv-crossing` из
  реального `index.json` виден в меню и открывается до играбельной сцены.
- **Пустой реестр:** `npm run smoke:no-campaign` — изолированная фикстура `[]`,
  экран пустого реестра, восстановление реестра.
- **Стражи:** `npm run check:contracts` продолжает вызывать
  `check:dev-campaigns` и `check:campaign-formats`; новый стартовый смоук
  добавляется рядом с существующими, а не вместо них. Оракул миссии
  (`npm run check:mission`) не меняется.

Места вызова в CI (после NAR-3.0 шаг «Экзамен миссии до сборки» уже
существует):

1. «Пустой реестр» — `check:mission` → `smoke:mission` → `smoke:no-campaign`.
2. «Штатный старт» — `.github/workflows/visual.yml`, шаг «Снять экраны и
   проверить утверждения», после готовности preview:
   `npm run smoke:campaign-start -- http://127.0.0.1:4173`.
