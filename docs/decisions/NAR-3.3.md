# NAR-3.3 — стартовый проект в поставке

## Контекст

`public/campaigns/index.json` пуст. Коммит `60a2da5` и `npm run smoke:no-campaign`
намеренно удерживали пустой реестр как самостоятельный сценарий: приложение
показывает «Кампаний пока нет». После NAR-3.1 и NAR-3.2 проекты уже проходят
игровой маршрут в браузере, но стартовая поставка по-прежнему не предлагает
играбельный проект. Пустой сценарий нужен смоуку, но не должен быть единственным
содержимым поставки.

## Что решено

**Предлагается штатный стартовый проект в реестре игрока:** добавить в
`public/campaigns/index.json` единственную запись `fmv-crossing` — «Перекрёсток
огней». Игрок находит проект в обычном меню приложения и запускает его штатной
кнопкой; консоль, query-параметры и ручная подкладка файлов не нужны. Не
изменять содержимое `public/campaigns/fmv-crossing` или его фикстуры.

Проект и его `dev-fixture.json` остаются помеченными `[DEV]`. Этот ADR явно
предлагает разрешение **только для ID `fmv-crossing`** как стартового проекта.
После принятия ADR следующая карточка может внести это узкое исключение в
`check:dev-campaigns`; все остальные `[DEV]`-кампании в реестре и все
незарегистрированные каталоги без маркера по-прежнему должны проваливать гейт.
Статус `proposed` сам по себе не разрешает менять реестр или гейт: реализация
3.4 начинается после ответа на этот ADR и смены его статуса.

`npm run smoke:no-campaign` сохраняется как проверка пустого реестра, но должна
проверять изолированный ответ/фикстуру `[]`, а не требовать пустоты поставочного
`index.json`. Тест обязан восстанавливать исходный реестр после прогона; он не
должен очищать запись стартового проекта.

Причина прежнего расхождения — реестр оставили пустым намеренно ради
`smoke:no-campaign`, когда играбельные примеры ещё были только полигонами. Теперь
пустой случай тестируется отдельно, а реестр поставки представляет путь игрока.

## Варианты и цена

| Вариант | Что получает игрок | Что ломается / риск | Цена |
|---|---|---|---|
| **Оставить как есть** (default) | Пустой список и экран «Кампаний пока нет» | В поставке всё ещё нет играбельного проекта; намерение карточки не выполнено | Никаких изменений, но задача про стартовый проект остаётся нерешённой |
| **`fmv-crossing` в реестре** (предлагаемый) | «Перекрёсток огней» доступен из обычного меню | Текущий `smoke:no-campaign` требует пустой поставочный индекс; guard считает ID `[DEV]` недопустимым без ADR | Узкое исключение для одного ID, изолированная empty-index фикстура и один стартовый смоук |
| **Явный выбор при запуске** | Отдельный экран выбора проекта | Новое состояние/переход; пустой каталог всё равно нужно проверять независимо | Новый UI-путь и дополнительные смоуки запуска/выбора |

## Отклонённая альтернатива

Явный экран выбора проекта при первом запуске отклоняется в этом предложении.
Он добавляет отдельное состояние запуска и ещё один экран/переход, дублирует
уже имеющийся выбор из реестра и не убирает необходимость отдельного теста
пустого каталога. Один явно разрешённый стартовый ID использует существующий
путь интерфейса и проще проверяется. Оставить реестр пустым — вариант по
умолчанию вопроса Мастеру, но он не удовлетворяет намерению карточки.

## Автоматическая проверка

Имена и сценарии следующей карточки:

- **Штатный старт:** новый npm-скрипт `npm run smoke:campaign-start`. Он
  проверяет, что `fmv-crossing` берётся именно из реального `index.json`, виден
  в меню и открывается до играбельной сцены без консоли и query-параметров.
- **Пустой реестр:** существующий `npm run smoke:no-campaign`. Он запускается
  против изолированной фикстуры/ответа `[]`, подтверждает экран пустого реестра
  и не меняет поставочный `index.json`.
- `npm run check:contracts` и основной оракул `npm run check:mission` остаются
  без замены. `check:contracts` продолжает вызывать `check:dev-campaigns` и
  проверку форматов; новый стартовый смоук добавляется рядом с существующими,
  не вместо них.

Места вызова в CI:

1. «Пустой реестр»: `.github/workflows/visual.yml`, job `screenshots`, шаг
   «Экзамен миссии до сборки» запускает `npm run check:mission`; тот запускает
   `npm run smoke:mission`, в список которого уже входит
   `npm run smoke:no-campaign`.
2. «Штатный старт»: тот же workflow и job, шаг «Снять экраны и проверить
   утверждения», после готовности production preview на `127.0.0.1:4173` и
   установки Chromium запускает `npm run smoke:campaign-start --
   http://127.0.0.1:4173`. Этот дополнительный сценарий не заменяет
   `npm run check:mission`.

Проверенные факты на текущем дереве:

- `node public/ai/cf-play.mjs check public/campaigns/fmv-crossing` — rc=0,
  0 ошибок и 0 предупреждений.
- `npm run audit:campaign -- public/campaigns/fmv-crossing` находит 0 ошибок
  отсутствующих изображений: все 1 локальная ссылка на медиа найдена. Общий
  отчёт сейчас всё же rc=1 из-за двух отдельных ошибок схемы FMV-расширений
  (`manifest.json` и `scene_fmv_crossing.json`); это не ошибки изображений и
  этим ADR не замалчиваются.
- `npm run audit:campaign -- public/campaigns/ash-of-caerden` и запуск на
  `ash-of-caerden-adventure` каждый показывают ровно 27 отсутствующих
  изображений. Это намеренные `[DEV]`-фикстуры; их не чинить, не подменять и не
  копировать в стартовый проект.
- Текущая проверка браузером NAR-3.2 уже прошла для `fmv-crossing`; в частности,
  экран проекта, видео, выбор ветки и финал пройдены без находок.

Код, `package.json`, реестр, гейты и данные этим ADR не меняются. После ответа
статус должен стать `accepted` или `rejected` с датой решения; оставлять
`proposed` после ответа нельзя.
