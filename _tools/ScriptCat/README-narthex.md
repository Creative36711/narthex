# Narthex: передача хода между агентами

Скрипт для ScriptCat, который превращает страницы Arena в конвейер:
Координатор выдаёт задачу → исполнитель работает и открывает PR → PR
сливается автоматически → ход возвращается Координатору. Цикл идёт, пока
Координатор не скажет «готово».

Файл: `narthex.user.js`. Старый `dispatch.user.js` (кампании) остаётся как
есть и с новым скриптом не связан.

## Что нужно до установки

| Компонент | Зачем | Где взять |
|---|---|---|
| Notion-токен | читать и писать карточки | внутренний токен рабочего пространства; хранится только в ScriptCat |
| Шлюз Drive | тексты заданий и логи | `drive-gateway.gs`, развернуть как веб-приложение от своего имени |
| Ключ шлюза | подпись запросов | Script Properties → `CF_GATEWAY_KEY` |
| URL шлюза | адрес `/exec` | после развёртывания |

Скрипт обращается ровно к трём адресам: `api.notion.com`,
`script.google.com`, `script.googleusercontent.com`. Ничего другого в
разрешениях нет.

## Установка

1. Развернуть `drive-gateway.gs` (Развёртывание → Новое развёртывание → Веб-
   приложение → «от моего имени», доступ «всем»). Скопировать URL `/exec`.
2. В Script Properties задать `CF_GATEWAY_KEY` — любую длинную строку.
   Папку логов шлюз создаст сам («Narthex — логи») при первом `ping`.
3. Установить `narthex.user.js` в ScriptCat.
4. Открыть `https://arena.ai/?cf-auth-setup=1` и нажать **⚙** в панели.
   Параметр из адреса убирается сам — второй раз окно не появится.
5. Заполнить: Notion-токен, URL шлюза, ключ. Нажать «Проверить».
   Успех — строка «Настройка сохранена: <имя>, шлюз pong».

## Как это работает

```
[Координатор] --CF_COORDINATOR_RESULT next=<роль>--> [исполнитель]
      ^                                                   |
      |                                    работа, коммит, пуш, PR
      |                                                   |
      +-------- Submitted <-- авто-мерж PR <--------------+
```

* **Тик** — раз в 15 секунд, но только на странице агента, чей id есть в
  таблице «Роли». Ничего не делает, пока не включён тумблер.
* **Тумблер** — «Автоцикл». Выключенный тумблер = скрипт только показывает
  состояние. Включённый = работает бесконечно.
* **Пауза** — любая ошибка (нет карточки, PR не слился, Notion отказал)
  останавливает цикл и пишет причину в панель. Это защита от тихого
  проскальзывания, а не сбой.

### Маркеры

Исполнитель заканчивает ответ строкой:

```
CF_AGENT_RESULT {"dispatch_id":"…","run_id":"…","status":"submitted","check":0,"report":"…"}
```

`check: 0` → поле `Check = pass`, иначе `fail`. `report` попадает в `Report SHA`
(обрезка 200 знаков).

Координатор заканчивает ответ строкой:

```
CF_COORDINATOR_RESULT {"mission_id":"…","turn_id":"…","status":"completed","next":"Kernel"}
```

`next` — имя роли или `done`. `done` переводит миссию в «Завершена» и
выключает автоцикл: это единственный способ остановить бесконечность.

### PR

Порядок кнопок: `Create pull request` → `Merge pull request` →
`Pull request merged` → `Continue`.

* Нажатие **Create PR** — запасной путь: если агент не запушил, кнопка
  активна, и скрипт нажимает её сам.
* После `Continue` рабочая ветка меняется; скрипт читает её из шапки и пишет в
  карточку (`Branch`).
* Пока PR не слит, задача **не** переходит в `Submitted`. Если мерж не
  удался за 4 минуты — пауза, задача остаётся `Running`, после снятия паузы
  шаг повторяется (лог дописывается идемпотентно по маркеру).

### Зависшие задачи

Задача в `Running` дольше 45 минут возвращается в `Ready` — иначе один
незагрузившийся агент останавливает всю миссию.

## Панель

| Элемент | Действие |
|---|---|
| тумблер | включить/выключить автоцикл |
| «Шаг» | один тик вручную, даже если автоцикл выключен |
| «Журнал» | последние 80 строк |
| ⚙ | настройка заново |
| «Стоп» | снять паузу и выключить автоцикл |

## Ограничения

* Скрипт **не решает**, что делать: очередь, приёмка и завершение — в Notion.
  Он только исполняет решение Координатора.
* Один Координатор на миссию. Два — гонка за одну карточку.
* Скрипт не работает в фоне: вкладка должна быть открыта на странице агента.
* Селекторы кнопок привязаны к разметке Arena; при её изменении нужен
  ремонт в одном месте — `prButton()`, `continueButton()`, `branchName()`.

## Проверка перед запуском

```bash
node --check narthex.user.js          # синтаксис
grep -n 'C.notionV\|C.roles\|C.requests\|C.missions' narthex.user.js
```

Второй командой убедитесь, что id источников данных совпадают с рабочим
пространством: они записаны в `C` и при пересоздании баз меняются.
