# NAR-5.3 — state-ui: блокер регистрации пака

**Итог этой попытки:** пак и npm-проба не создавались, чтобы не нарушать точный Scope. Для нового `packs/state-ui/pack.json` обязательна запись в `packs/registry.json`, но этот файл в Scope не перечислен. Без неё `check:packs` гарантированно отклонит новый каталог.

## Находка фазы

- Разрешённая область включает `packs/state-ui/**`, `package.json` (только `probe:state-ui`) и этот отчёт.
- `packs/registry.json:3–7` перечисляет только `narrative`, `grid-strategy`, `adventure`.
- `scripts/check-packs.mts:230–235` проверяет двустороннее соответствие: каждый каталог пака должен быть в `packs/registry.json`, и каждый зарегистрированный пак должен иметь каталог. Следовательно, создание нового пака строго в разрешённой области оставило бы проверку красной; исправление требует изменить `packs/registry.json`, не включённый в Scope.

**Допущение:** соблюдать перечисленные пути буквально и не добавлять незарегистрированный пак. Обратимый следующий шаг — явно включить `packs/registry.json` в Scope либо вынести регистрацию в отдельную карточку; после этого создать пак и его пробу. Статусы возможностей оставлены `planned`, `probe: null`; `docs/contracts/**`, `src/core/**`, narrative и adventure не менялись.

3. `npm run check:contracts` — **rc=0** на текущем main; статусы возможностей не менялись. В составе команды также прошли проверки паков и границы.
