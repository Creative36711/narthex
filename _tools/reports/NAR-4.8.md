## Причина и исправление

До изменения `npm run lint` возвращал **rc=1: 1507 warnings, 3 errors**.
Все три ошибки — `rules-of-hooks`: эффект клавиатуры, состояние таймера и
эффект таймера вызывались после `if (!d) return null`. В этом же компоненте
были два предупреждения `exhaustive-deps`: отсутствовали обработчики клавиш
в зависимостях и заново создавался объект таймера. Остановка Audio/TTS и
переключение ducking дополнительно выполнялись прямо в рендере при смене диалога.

Исправлены причины, а не правила:

- Все хуки вызываются до условного возврата. При отсутствии диалога эффект
  клавиатуры не устанавливает обработчик, таймер и озвучка не запускаются.
- `skipOrAdvance` / `skipAllLines` стабилизированы `useCallback`, эффект
  клавиатуры перечисляет их и все остальные используемые реактивные значения.
- Прогресс по-прежнему сбрасывается синхронной корректировкой **состояния**
  при смене объекта диалога: ответ начинается с первой фразы. В рендере нет
  остановки аудио, изменения ref или музыкального ducking.
- Владение Audio/TTS и страховочным таймером вынесено в соседний
  `src/player/useDialogueAudio.ts`. Запуск — в эффекте, остановка — в его
  cleanup либо обработчике жеста игрока. Cleanup делает старые callbacks
  неактуальными и сохраняет StrictMode setup → cleanup → setup.
- `useEffectEvent` читает актуальные настройки **при старте очередной реплики**;
  изменение громкости/настроек само по себе не проигрывает текущую фразу и SFX
  заново. Реактивные причины запуска — диалог, индекс и текущая реплика —
  явно перечислены в зависимостях эффекта.
- Объект таймера мемоизирован. Начальное значение нового отсчёта выводится из
  его конфигурации, а состояние обновляется только тиками интервала: нет
  синхронного `setState` в эффекте и сброса отсчёта на каждом его рендере.

JSX, порядок/тексты реплик и кнопок, DOM-узлы и обработчики выбора не заменены;
keyed-remount для сброса состояния не используется. Печать 24 мс/символ,
пауза 750 мс, интервал отсчёта 120 мс и аудио-watchdog сохранены.

Допущение: настройки озвучки применяются на старте следующей реплики, как в
исходном компоненте; уже звучащая реплика не перезапускается. Контракт не меняется,
ADR не требуется. Извлечение аудио необходимо также для неизменённого гейта
размера: исходный `DialogueOverlay.tsx` имел 497 строк, изменённый модуль обязан
укладываться в 450; результат — **387/450**, аудиохук — **128/450**.

## Клавиши, фокус и жизненный цикл

Отдельная проба реальной Ash-кампании проверила Enter (ровно одна следующая
реплика), Space (допечатать текущую), Escape (весь монолог до выбора;
повторный Escape не закрывает выбор), игнорирование всех этих клавиш в
`input` и `textarea`, первую фразу после выбора ответа, открытие/закрытие
истории, закрытие самого диалога. Фокус сохраняется на «Далее» при перелистывании
и допечатывании; при удалении кнопок возвращается на body точно как до правки.
`keys-before/result.json` и `keys-after/result.json` в `out/nar-4.8/`
совпали полностью, включая фокус, тексты реплик и варианты.

Дополнительный изолированный браузерный стенд использует настоящий компонент
в React StrictMode, управляемые часы и замену только браузерного Audio:
проверяет отмену первого StrictMode setup, одну активную озвучку, отсутствие
перезапуска при печати/смене настроек, новые настройки для новой фразы,
игнорирование позднего завершения старого аудио, штатную паузу 750 мс,
`active → null → active` без нарушения порядка хуков, снятие/возврат
перехвата клавиатуры, остановку звука по пропуску и размонтированию.
Также проверены полный стартовый отсчёт, его ход через рендер истории,
однократный timeout выбора и завершение монолога по таймеру строки.

## Scope, D-01 и PR

В PR включаются только `src/player/DialogueOverlay.tsx`, новый
`src/player/useDialogueAudio.ts`, строка D-01 в `docs/debts.md` и этот отчёт.
`src/core/**`, `scripts/**`, `public/ai/**`, линт-конфигурация, D-02/D-03/D-04
и фаза 4 не изменены. Часть D-01 по аудитору уже оплачена
[PR #93](https://github.com/Creative36711/narthex/pull/93); эта миссия завершает
часть Player UI, после чего весь D-01 имеет 0 ошибок.

PR этой миссии и ссылка на независимый CI будут привязаны после создания PR.

Особенность среды: стартовая ветка была shallow-снимком; до правок при чистом
worktree выполнены fetch и reset на свежий `origin/main`. Имя ветки оставлено
закреплённым за сессией — `arena/1dabaa22-narthex`. У рабочих коммитов есть
общая история с `main`; удалений чужих файлов в PR нет.
